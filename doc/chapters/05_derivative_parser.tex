\chapter{Derivative-Based Parser}
\label{sec:derivative-parser}

Chapter~\ref{sec:derivatives} introduced \texttt{match\_deriv},
a matcher that uses Brzozowski derivatives to decide $w \in L(r)$. 
Chapter~\ref{sec:matching-vs-parsing} showed 
that a word may admit multiple valid parse trees for the same expression
and that a parser must select one according to a \emph{disambiguation policy}.
This Chapter shows how a parse tree can be recovered from the final derivative.

Following \citep{sulzmannlu2014}, 
this chapter presents two derivative-based methods 
for constructing POSIX parse trees. 
The direct method performs a forward derivative pass 
followed by a backward pass for tree reconstruction. 
The bit-coded method records 
parse-tree information during the forward pass, 
avoiding a separate backward pass.

\section{The Standard Derivative-Based Parser}
\label{sec:core-algorithm}
Consider again $r = (a+ab)(b+\varepsilon)$ with input $w = \mathtt{ab}$.
The derivation was already computed in Section~\ref{sec:deriv-worked-example}, 
shown here unsimplified:
\begin{equation}\label{eq:deriv-std-example}
r
  \xrightarrow{\ a\ } (\varepsilon + \varepsilon b)(b + \varepsilon)
  \xrightarrow{\ b\ } (\emptyset + (\emptyset b + \varepsilon))(b + \varepsilon) + (\varepsilon + \emptyset)
\end{equation}

The final derivative is nullable, 
so \(w \in L(r)\) and both disjuncts accept the empty word. 
Its first disjunct, \((\emptyset+(\emptyset b+\varepsilon))(b+\varepsilon)\), 
reflects \(ab\cdot\varepsilon\), and its second,
\((\varepsilon+\emptyset)\), reflects \(a\cdot b\).

A derivative step records only the remaining input language, 
not how the characters were matched, 
so the final derivative does not show which decomposition was selected. 
The derivation sequence itself does, 
because each step consumed one character and is invertible.
So reversing the steps recovers the tree (Figure~\ref{fig:two-pass}).

\subsection{Building the Empty-Word Tree}
\label{sec:mkeps-theory}

The backward pass starts with $\mathit{mkEps}$ ~\citep[Fig.~3]{sulzmannlu2014}, 
which recursively constructs an empty-word parse tree 
from the final nullable expression:
\begin{equation}\label{eq:mkeps}
\begin{aligned}
\mathit{mkEps}_{\varepsilon} &= () &&(\mathsf{E}_{\varepsilon}) \\
\mathit{mkEps}_{r^{*}} &= [\,] &&(\mathsf{E}_{*}) \\
\mathit{mkEps}_{r_1 r_2} &= (\mathit{mkEps}_{r_1}, \mathit{mkEps}_{r_2})
  &&(\mathsf{E}_{\mathrm{seq}}) \\
\mathit{mkEps}_{r_1+r_2} &=
  \begin{cases}
    \mathit{Left}\ \mathit{mkEps}_{r_1} & \text{if } n(r_1) \\
    \mathit{Right}\ \mathit{mkEps}_{r_2} & \text{otherwise}
  \end{cases}
  &&\begin{array}{l}(\mathsf{E}_{+}^{L}) \\ (\mathsf{E}_{+}^{R})\end{array}
\end{aligned}
\end{equation}

The first three rules follow from the structure of the expression:
$(\mathsf{E}_{*})$ treats a star matching the empty word as zero iterations, 
and $(\mathsf{E}_{\mathrm{seq}})$ matches a concatenation against $\varepsilon$ 
only when both factors do. 
No rules are needed for $\emptyset$ or literals, 
since neither can match the empty word. 
The alternation rule is where disambiguation occurs. 
If exactly one of $r_1$ and $r_2$ is nullable, 
that branch is the only possible witness. 
If both are, $(\mathsf{E}_{+}^{L})$ breaks the tie by preferring the left one,
after POSIX's leftmost-longest policy~\citep{sulzmannlu2014}.

For the example, the final expression is
$(\emptyset + (\emptyset b + \varepsilon))(b + \varepsilon) + (\varepsilon + \emptyset)$.
At the top-level $+$ both summands are nullable, 
so $(\mathsf{E}_{+}^{L})$ picks the left one. 
Within that summand's first factor $\emptyset + (\emptyset b + \varepsilon)$, 
only the right alternative is nullable, 
so $(\mathsf{E}_{+}^{R})$ applies, 
and within it only the right sub-alternative $\varepsilon$ is nullable, 
so $(\mathsf{E}_{+}^{R})$ applies again, contributing $\mathit{RightRight}()$. 
The second factor $b + \varepsilon$ contributes $\mathit{Right}()$ 
via $(\mathsf{E}_{+}^{R})$,
giving $\mathit{Left}(\mathit{RightRight}(),\mathit{Right}())$.

Since $\mathit{mkEps}$ handles disambiguation, 
the forward pass must preserve the branch that consumed $a$.
Otherwise, injection cannot reconstruct $\mathit{Right}(a,b)$. 
Simplifying would give:
\begin{equation}\label{eq:mkeps-simp}
\begin{aligned}
r
  &\xrightarrow{\ a\ } & (\varepsilon + \varepsilon b)(b + \varepsilon)
  &\xrightarrow{\ \mathrm{simp}\ } & (\varepsilon + b)(b + \varepsilon) \\
  &\xrightarrow{\ b\ } & (\emptyset + \varepsilon)(b+\varepsilon) + (\varepsilon + \emptyset)
  &\xrightarrow{\ \mathrm{simp}\ } & (b + \varepsilon) + \varepsilon,
\end{aligned}
\end{equation}
This still witnesses $w \in L(r)$, 
but $(\emptyset + \varepsilon) \to \varepsilon$ 
and $(\varepsilon + \emptyset) \to \varepsilon$ 
erase the pair structure holding both characters. 
$\mathit{mkEps}$ on $(b+\varepsilon)+\varepsilon$ 
gives $\mathit{Left}(\mathit{Right}(()))$,
and injecting $b$ fills that one empty leaf, 
leaving none for $a$, so $\mathit{Right}(a,b)$ is unrecoverable.

%

\paragraph{In Rust.}
\label{sec:mk-eps-impl}

Equation~\eqref{eq:mkeps} is implemented directly in Rust, 
as shown in Figure~\ref{fig:mkeps-rust}:
\begin{figure}[H]
\small
\begin{verbatim}
pub fn mk_eps(r: &Regex) -> ParseTree {
    match r {
        Regex::Eps         => ParseTree::Empty,
        Regex::Star(_)     => ParseTree::Star(Vec::new()),
        Regex::Seq(r1, r2) => ParseTree::Pair(
                              Box::new(mk_eps(r1)), Box::new(mk_eps(r2))),
        Regex::Alt(r1, r2) => 
            if nullable(r1)   {ParseTree::Left(Box::new(mk_eps(r1)))} 
            else              {ParseTree::Right(Box::new(mk_eps(r2)))},
        Regex::Lit(c)      => panic!("mk_eps called on Lit('{}')", c),
        Regex::Phi         => panic!("mk_eps called on Phi"),
    }
}
\end{verbatim}
\caption{\texttt{mk\_eps}: construct a parse tree for the empty word.}
\label{fig:mkeps-rust}
\end{figure}

The expression $r$ is borrowed rather than consumed 
because the backward pass needs it again during injection. 
The alternation arm encodes disambiguation as a conditional,
examining \texttt{r2} only when \texttt{nullable(r1)} is false. 
The panic arms enforce the precondition that $\mathit{mkEps}$ 
applies only to nullable expressions, 
rejecting the non-nullable $\emptyset$ and literals.

\subsection{Reinserting Characters via Injection}
\label{sec:inj-theory}

After $\mathit{mkEps}$ constructs the parse tree $v$ for the empty word, 
reconstruction starts from this tree 
and proceeds backwards through the derivation sequence. 
Each application of $\mathit{inj}$ takes the current tree, 
the corresponding derivative step, and its consumed character, 
and returns a tree for the preceding expression.
$\mathit{inj}$ follows the structure of the residual 
until it reaches the literal that consumed the character, 
reinserts the character there, and then unwinds to rebuild the surrounding tree. 
After all characters have been reinserted, 
the parse tree for the original expression and input is recovered. 
The rules are those of \citep[Fig.~3]{sulzmannlu2014}:
\begin{equation}\label{eq:inj}
\begin{aligned}
\mathit{inj}_{x \backslash x}() &= x
  &&(\mathsf{I}_{\mathrm{lit}}) \\
\mathit{inj}_{(r_1+r_2) \backslash x}(\mathit{Left}\ v_1)
  &= \mathit{Left}\ (\mathit{inj}_{r_1 \backslash x}\ v_1)
  &&(\mathsf{I}_{+}^{L}) \\
\mathit{inj}_{(r_1+r_2) \backslash x}(\mathit{Right}\ v_2)
  &= \mathit{Right}\ (\mathit{inj}_{r_2 \backslash x}\ v_2)
  &&(\mathsf{I}_{+}^{R}) \\
\mathit{inj}_{r^{*} \backslash x}(v, vs)
  &= (\mathit{inj}_{r \backslash x}\ v) : vs
  &&(\mathsf{I}_{*}) \\
\mathit{inj}_{(r_1 r_2) \backslash x}(v_1, v_2)
  &= (\mathit{inj}_{r_1 \backslash x}\ v_1,\ v_2)
  &&(\mathsf{I}_{\mathrm{seq}}),\ n(r_1) = \mathrm{false} \\
\mathit{inj}_{(r_1 r_2) \backslash x}(\mathit{Left}(v_1, v_2))
  &= (\mathit{inj}_{r_1 \backslash x}\ v_1,\ v_2)
  &&(\mathsf{I}_{\mathrm{seq}}^{L}),\ n(r_1) = \mathrm{true} \\
\mathit{inj}_{(r_1 r_2) \backslash x}(\mathit{Right}\ v_2)
  &= (\mathit{mkEps}_{r_1},\ \mathit{inj}_{r_2 \backslash x}\ v_2)
  &&(\mathsf{I}_{\mathrm{seq}}^{R}),\ n(r_1) = \mathrm{true}
\end{aligned}
\end{equation}

Rules $(\mathsf{I}_{\mathrm{lit}})$ and $(\mathsf{I}_{*})$ 
invert their derivative rules directly, 
reconstructing the consumed character and the current iteration, 
the latter prepended to the remaining ones.
The alternation rules recurse into the branch named by the incoming tag, 
which is either $\mathit{Left}\ v_1$ or $\mathit{Right}\ v_2$ 
because the consumed character lies in exactly one branch.
The concatenation rules cover the three cases of the sequence derivative. 
If $n(r_1) = \mathrm{false}$, $r_1$ must consume $x$, 
so $(\mathsf{I}_{\mathrm{seq}})$ recurses into $v_1$ $(\mathsf{I}_{+}^{L})$.
If $n(r_1) = \mathrm{true}$, 
the derivative tags which component consumed $x$: 
$(\mathsf{I}_{\mathrm{seq}}^{L})$ recurses into $v_1$, while
$(\mathsf{I}_{\mathrm{seq}}^{R})$ reconstructs $r_1$'s empty match 
with $\mathit{mkEps}_{r_1}$ and recurses into $v_2$ $(\mathsf{I}_{+}^{R})$.

%

\paragraph{In Rust.}
\label{sec:inject-impl}

\texttt{inject(r, l, v)} takes three arguments because $\mathit{inj}$ is
indexed by both an expression and a character.
It matches first on \texttt{r} and on \texttt{v} second, 
following the order in which \eqref{eq:inj} indexes its rules. 
This order matters because a tree tag is interpreted relative 
to the expression that produced it. 
Under an alternation, \texttt{Left} selects the left disjunct, 
while under a nullable concatenation it indicates 
that the derivative continued inside the left operand. 
The \texttt{Lit} arm reconstructs a leaf after asserting 
that the consumed character matches,
and the \texttt{Star} arm inverts $(\mathsf{I}_{*})$ 
by reinserting the character into the current iteration 
and appending it to the tail built so far.

The expression \texttt{r} is borrowed, 
while the tree \texttt{v} is consumed and decomposed. 
The expression is only read and is needed again 
at every level of the recursion, 
since each arm recurses on a subexpression \texttt{r1} or \texttt{r2}. 
The tree, by contrast, is taken apart once, 
and the parts that are not recursed into, 
such as \texttt{v2} in the concatenation arms, 
move directly into the rebuilt tree rather than being copied.

In the concatenation arms where the right operand was not derived,
\texttt{v2} moves directly into the new pair, 
since Equation~\eqref{eq:inj} leaves it unchanged. 
The \texttt{Right} arm of concatenation is the only case that synthesizes content, 
calling \texttt{mk\_eps(r1)} because the derivative skipped \texttt{r1} 
and the forward pass produced no tree for that half of the pair. 
Calling \texttt{nullable(r1)} in the \texttt{Seq} arm recomputes a decision 
the forward pass already made, 
when it chose between $\mathsf{D}_{\mathrm{seq}}$ and $\mathsf{D}_{\mathrm{seq}}^{\,n}$.
But carrying it as a flag would require additional storage, 
and \texttt{nullable} is cheap to evaluate on demand.

Appending rather than prepending makes each injection step $O(1)$, 
but leaves a \texttt{Star}'s iterations in reverse chronological order.
\texttt{reverse\_stars} reverses each \texttt{Star}'s items exactly once
after the backward walk, and both entry points apply it before returning,
so the pass remains $O(n)$. 
Prepending at every step, as Equation~\eqref{eq:inj} suggests literally, 
would instead copy the already-built tail on each call, raising the cost to $O(n^2)$.

\begin{figure}[H]
\small
\begin{verbatim}
pub fn inject(r: &Regex, l: char, v: ParseTree) -> ParseTree {
    match r {
        Regex::Lit(c) => { assert!(*c == l); ParseTree::Char(l) }
        Regex::Alt(r1, r2) => match v {
            ParseTree::Left(v1) =>
                ParseTree::Left(Box::new(inject(r1, l, *v1))),
            ParseTree::Right(v2) =>
                ParseTree::Right(Box::new(inject(r2, l, *v2))),
            _ => panic!("inject/Alt: want Left|Right"),
        },
        Regex::Star(r1) => match v {
            ParseTree::Pair(v1, vs) => match *vs {
                ParseTree::Star(mut rest) => {
                    rest.push(inject(r1, l, *v1));
                    ParseTree::Star(rest)
                }
                _ => panic!("inject/Star: want Star tail"),
            },
            _ => panic!("inject/Star: want Pair"),
        },
        Regex::Seq(r1, r2) => match (nullable(r1), v) {
            (false, ParseTree::Pair(v1, v2)) =>
                ParseTree::Pair(Box::new(inject(r1, l, *v1)), v2),
            (true, ParseTree::Left(vp)) => match *vp {
                ParseTree::Pair(v1, v2) =>
                    ParseTree::Pair(Box::new(inject(r1, l, *v1)), v2),
                _ => panic!("inject/SeqL: want Pair"),
            },
            (true, ParseTree::Right(v2)) =>
                ParseTree::Pair(Box::new(mk_eps(r1)),
                                Box::new(inject(r2, l, *v2))),
            _ => panic!("inject/Seq: bad tag"),
        },
        Regex::Eps | Regex::Phi => panic!("inject called on Eps/Phi"),
    }
}
\end{verbatim}

Reinserts a character into a parse tree.}

\end{figure}

\subsection{Parser}
\label{sec:deriv-std-parser}

The parser makes two passes: 
The forward pass stores all residuals $r_0,\ldots,r_n$, 
and the backward pass applies $\mathit{mkEps}$ to the final residual, 
then reconstructs the parse tree $v$ using $\mathit{inj}$. 
All residuals must be kept because each injection step 
requires the residual immediately before the corresponding character.
The residuals are computed left to right, $r_0$ to $r_n$, 
and the trees right to left, $v_n$ to $v_0$. 
The residual $r_n$ is nullable exactly when $w \in L(r)$, 
and the tree $v_0$ is the parse tree the parser returns.
\begin{equation}\label{eq:std-driver}
\begin{aligned}
r_0 &= r, & r_i &= r_{i-1} \backslash x_i
  &&(1 \leq i \leq n), \\
v_n &= \mathit{mkEps}(r_n), & v_i
  &= \mathit{inj}_{r_{i-1} \backslash x_i}(x_i,\ v_{i+1})
  &&(0 \leq i < n), \\
& & v_0 &= \mathit{inj}_{r_0 \backslash x_1}(x_1,\ v_1).
\end{aligned}
\end{equation}

%

\paragraph{In Rust.}
Figure~\ref{fig:deriv-std-drivers-rust} implements Equation~\eqref{eq:std-driver}.
The forward loop fills the \texttt{expressions} vector with $r_0, \ldots, r_n$, 
the nullability check returns early if $r_n$ is not nullable, 
and the backward loop walks the vector in reverse, 
applying \texttt{inject} to each residual and its character, 
before \texttt{reverse\_stars} restores left-to-right order once.
\begin{figure}[H]
\small
\begin{verbatim}
pub fn parse_deriv_std_loop(input: &str, r: &Regex) -> Option<ParseTree>{
    let chars: Vec<char> = input.chars().collect();
    let mut expressions = Vec::with_capacity(chars.len() + 1);
    expressions.push(r.clone());
    for &c in &chars {
        expressions.push(deriv(expressions.last().unwrap(), c));
    }
    if !nullable(expressions.last().unwrap()) { return None; }
    let mut tree = mk_eps(expressions.last().unwrap());
    for i in (0..chars.len()).rev() {
        tree = inject(&expressions[i], chars[i], tree);
    }
    Some(reverse_stars(tree))
}
\end{verbatim}

\end{figure}

\subsection{Worked Example: Standard Derivative Parser}
\label{sec:worked-example}
Apply the standard parser to the ambiguous example
$r_0=(a + ab)(b + \varepsilon)$ on input $\texttt{ab}$.

\paragraph{Forward pass.}
There are two derivative steps, one per input symbol. 
After deriving \texttt{a}, the left factor $\varepsilon+\varepsilon b$ is nullable, 
so the second derivation on \texttt{b} uses $\mathsf{D}_{\mathrm{seq}}^{\,n}$ 
rather than $\mathsf{D}_{\mathrm{seq}}$:
\[
\begin{aligned}
r_0 = (a+ab)(b+\varepsilon)
  &\xrightarrow[\mathsf{D}_{\mathrm{seq}}]{a}
    r_1 = (\varepsilon+\varepsilon b)(b+\varepsilon) \\
  &\xrightarrow[\mathsf{D}_{\mathrm{seq}}^{\,n}]{b}
    r_2 = \underbrace{(\emptyset+(\emptyset b+\varepsilon))(b+\varepsilon)}_{X}
       + \underbrace{(\varepsilon+\emptyset)}_{Y}.
\end{aligned}
\]
The final expression $r_2 = X + Y$ is nullable, 
and both disjuncts accept the empty word. 
$X$ records $ab \cdot \varepsilon$ (the first factor matched $ab$, 
the second $\varepsilon$).
$Y$ records $a \cdot b$ (the first matched $a$, the second $b$).

%

\paragraph{Backward pass: mkEps.}
The backward pass starts with $\mathit{mkEps}(r_2)$, 
the parse tree for the empty word. 
Both disjuncts of $X + Y$ are nullable, so $\mathsf{E}_{+}^{L}$ applies, giving:
\[
\mathit{mkEps}(r_2)
  = \mathit{Left}\bigl(\mathit{mkEps}(X)\bigr)
  \qquad (\mathsf{E}_{+}^{L}).
\]
Since $X$ is a concatenation,
$\mathsf{E}_{\mathrm{seq}}$ combines the trees for its two factors:
\[
\mathit{mkEps}(X)
  = \bigl(\mathit{mkEps}(\emptyset+(\emptyset b+\varepsilon)),\;
           \mathit{mkEps}(b+\varepsilon)\bigr)
  \qquad (\mathsf{E}_{\mathrm{seq}}).
\]
The first factor selects $\varepsilon$ by applying $\mathsf{E}_{+}^{R}$ twice, 
since $\emptyset$ and $\emptyset b$ are not nullable.
The second factor selects $\varepsilon$ by $\mathsf{E}_{+}^{R}$, 
since $b$ is not nullable. This gives:
\[
\begin{array}{@{}c@{\hspace{1em}}c@{}}
\begin{aligned}
\mathit{mkEps}(\emptyset+(\emptyset b+\varepsilon))
  &\xrightarrow{\ \mathsf{E}_{+}^{R}\ }
    \mathit{Right}\,\mathit{mkEps}(\emptyset b+\varepsilon)\\
  &\xrightarrow{\ \mathsf{E}_{+}^{R}\ }
    \mathit{Right}\,\mathit{Right}\,\mathit{mkEps}(\varepsilon)\\
  &\xrightarrow{\ \mathsf{E}_{\varepsilon}\ }
    \mathit{Right}\,\mathit{Right}\,()
\end{aligned}
&
\begin{aligned}
\mathit{mkEps}(b+\varepsilon)
  &\xrightarrow{\ \mathsf{E}_{+}^{R}\ }
    \mathit{Right}\,\mathit{mkEps}(\varepsilon)\\
  &\xrightarrow{\ \mathsf{E}_{\varepsilon}\ }
    \mathit{Right}\,()
\end{aligned}
\end{array}
\]
Hence the parse tree for the empty word is:
\[
v_2 = \mathit{mkEps}(r_2)
    = \mathit{Left}\bigl(
        \mathit{Right}\,\mathit{Right}\,(),
        \mathit{Right}\,()
      \bigr).
\]

%

\paragraph{Backward pass: Inj.}
Reinserting $\mathtt{b}$ transforms $v_2$ into a parse tree for
$r_1=(\varepsilon+\varepsilon b)(b+\varepsilon)$.
The $\mathit{Left}$ tag directs $\mathsf{I}_{\mathrm{seq}}^{L}$ 
into the first factor, leaving $\mathit{Right}\,()$ unchanged.
There, $\mathsf{I}_{+}^{R}$ selects the $\varepsilon b$ branch.
As $\varepsilon$ is nullable, $\mathsf{I}_{\mathrm{seq}}^{R}$
supplies its empty tree before $\mathsf{I}_{\mathrm{lit}}$ reinserts $\mathtt{b}$:
\[
\begin{aligned}
\mathit{inj}_{r_1 \backslash \mathtt{b}}(v_2)
  &= \mathit{inj}_{r_1 \backslash \mathtt{b}}\Bigl(
       \underbrace{\mathit{Left}(\mathit{Right}\,\mathit{Right}\,(),\;
                    \mathit{Right}\,())}_{v_2}\Bigr)\\
  &\xrightarrow{\ \mathsf{I}_{\mathrm{seq}}^{L}\ }
    \bigl(\mathit{inj}_{(\varepsilon+\varepsilon b)
          \backslash \mathtt{b}}(\mathit{Right}\,\mathit{Right}\,()),\;
          \mathit{Right}\,()\bigr)\\
  &\xrightarrow{\ \mathsf{I}_{+}^{R}\ }
    \bigl(\mathit{Right}\,
          \mathit{inj}_{\varepsilon b \backslash \mathtt{b}}
          (\mathit{Right}\,()),\;
          \mathit{Right}\,()\bigr)\\
  &\xrightarrow{\ \mathsf{I}_{\mathrm{seq}}^{R}\ }
    \bigl(\mathit{Right}\,
          (\mathit{mkEps}(\varepsilon),\;
           \mathit{inj}_{b \backslash \mathtt{b}}()),\;
          \mathit{Right}\,()\bigr)\\
  &\xrightarrow{\ \mathsf{E}_{\varepsilon},\ \mathsf{I}_{\mathrm{lit}}\ }
    \underbrace{\bigl(\mathit{Right}((), b),\;
          \mathit{Right}\,()\bigr)}_{v_1}.
\end{aligned}
\]

Reinserting $\mathtt{a}$ maps $v_1$ to a tree for $r_0=(a+ab)(b+\varepsilon)$. 
The first factor $a+ab$ of the outer sequence is not nullable, 
so $\mathsf{I}_{\mathrm{seq}}$ fires on $v_1$'s first component, 
leaving the second $\mathit{Right}\,()$ untouched. 
That component, $\mathit{Right}((),b)$, carries a $\mathit{Right}$ tag, 
so $\mathsf{I}_{+}^{R}$ selects $ab$, 
whose own first factor $a$ is not nullable, 
so $\mathsf{I}_{\mathrm{seq}}$ fires again and recurses into $a$, 
where $\mathsf{I}_{\mathrm{lit}}$ reinserts $\mathtt{a}$:
\[
\begin{aligned}
\mathit{inj}_{r_0 \backslash \mathtt{a}}(v_1)
  &= \mathit{inj}_{r_0 \backslash \mathtt{a}}\Bigl(
       \underbrace{(\mathit{Right}((), b),\;
                    \mathit{Right}\,())}_{v_1}
     \Bigr)\\
  &\xrightarrow{\ \mathsf{I}_{\mathrm{seq}}\ }
    \bigl(\mathit{inj}_{(a+ab) \backslash \mathtt{a}}
          (\mathit{Right}((), b)),\;
          \mathit{Right}\,()\bigr)\\
  &\xrightarrow{\ \mathsf{I}_{+}^{R}\ }
    \bigl(\mathit{Right}\,
          \mathit{inj}_{ab \backslash \mathtt{a}}
          (((), b)),\;
          \mathit{Right}\,()\bigr)\\
  &\xrightarrow{\ \mathsf{I}_{\mathrm{seq}}\ }
    \bigl(\mathit{Right}\,
          (\mathit{inj}_{a \backslash \mathtt{a}}(()),\;
           b),\;
          \mathit{Right}\,()\bigr)\\
  &\xrightarrow{\ \mathsf{I}_{\mathrm{lit}}\ }
    \underbrace{\bigl(\mathit{Right}(a, b),\;
          \mathit{Right}\,()\bigr)}_{v_0}.
\end{aligned}
\]

The implementation stores $r_0$, $r_1$, and $r_2$ in its vector. 
One entry per character, plus the initial expression, 
kept for the backward pass to reconstruct from. 
The tree it returns is $(\mathit{Right}(a,b), \mathit{Right}())$, 
which flattens to $\mathtt{ab}$ and matches the input.

\section{The Bit-Coded Derivative-Based Parser}
\label{sec:bitcoded-construction-formal}

The direct construction of \citep{sulzmannlu2014} reconstructs the tree
only once the entire input has been consumed,
since each injection step needs the preceding expression. 
Their bit-coded optimization records 
the reconstruction choices during a single pass instead.
Their idea is, that each subexpression carries 
the bit-sequence it has committed to so far, written $bs@r$. 
For $r_0=(a+ab)(b+\varepsilon)$, write $P$ and $Q$ 
for its two annotated factors. 
Deriving $w = \mathtt{ab}$ gives:
\begin{equation}\label{eq:bitcoded-overview-example}
\begin{aligned}
\mathit{ri}_0 &= [\,]@\Big(\underbrace{[0]@a \oplus [1]@(a\,b)}_{P}
                 \,\cdot\, \underbrace{[0]@b \oplus [1]@\varepsilon}_{Q}\Big) \\[2pt]
  &\xrightarrow{\ a\ }
    \mathit{ri}_1 = [\,]@\big(\underbrace{[0]@\varepsilon \oplus [1]@b}_{P'} \cdot\, Q\big) \\[2pt]
  &\xrightarrow{\ b\ }
    \mathit{ri}_2 = [\,]@\big([1]@Q \,\oplus\, [0,0]@\varepsilon\big).
\end{aligned}
\end{equation}

extraction step it feeds into:

\paragraph{The bit-coded pipeline.}
$\mathit{internalize}$ tags each alternation branch 
with a bit that records its preference, 
producing $\mathit{ri}_0=[\,]@(P\cdot Q)$ with $P=[0]@a\oplus[1]@(a\,b)$ 
and $Q=[0]@b\oplus[1]@\varepsilon$, 
where $0$ selects the left branch and $1$ the right.

Deriving by $\mathtt{a}$ extracts $P$'s leading $a$, 
producing $P'$ while leaving $Q$ unchanged. 
Since $P'$'s $\varepsilon$ branch is nullable, 
both decompositions survive in $\mathit{ri}_2$.
One completes inside $P'$ and folds its completion bit $1$ onto $Q$.
The other matches $\mathtt{b}$ in $Q$ 
and fuses $P'$'s completion bit into $[0,0]@\varepsilon$, 
giving $\mathit{ri}_2=[\,]@([1]@Q \oplus [0,0]@\varepsilon)$.
Unlike the standard construction, 
the bit-coded one may apply simplification to keep expressions bounded. 
$\mathit{simp}$ from \citep[Fig.~6]{sulzmannlu2014} 
discards dead branches and collapses finished subexpressions, 
and $\mathit{fuse}$ preserves bits on surviving nodes, 
as when $P$ collapses into $P'$ and then onto $Q$.

After $\mathtt{ab}$ has been consumed, 
$\mathit{mkEpsBC}$ walks $\mathit{ri}_2$ 
and collects the bits of the leftmost nullable branch at each choice, giving $[1,1]$. 
$\mathit{decode}_{r_0}$ replays them against the original $r_0$.
The first $1$ selects $a+ab$'s right branch and the second $b+\varepsilon$'s,
giving $(\mathit{Right}(a,b),\mathit{Right}\,())$. 
The tree is thus reconstructed in a single step, 
whereas the direct construction reverses the residuals step by step.

\subsection{Annotated Expressions}
\label{sec:annotated-expressions}

An annotated expression $\mathit{ri}$ extends $r$
by associating each non-$\emptyset$ node with a bit-sequence $bs$
that records the choices made during forward pass \citep[Fig.~5]{sulzmannlu2014}:
\begin{equation}\label{eq:aregex-grammar}
\mathit{ri} ::= \emptyset \mid (bs@\varepsilon) \mid (bs@x) \mid
(bs@\mathit{ri}_1 \oplus \mathit{ri}_2) \mid
(bs@\mathit{ri}_1\,\mathit{ri}_2) \mid
(bs@\mathit{ri}^{*}).
\end{equation}

%

\paragraph{In Rust.}
\label{sec:aregex-type}
Figure~\ref{fig:aregex-enum} defines \texttt{ARegex}, 
the annotated counterpart of \texttt{Regex}, 
in which every variant except \texttt{Phi} carries a leading \texttt{Bits} field
(Equation~\eqref{eq:aregex-grammar}). 
\texttt{Bits} is a persistent, 
\texttt{Rc}-backed cons list rather than a \texttt{Vec<bool>}, 
so prepending costs only the new prefix and not the accumulated history,
which keeps an $n$-character run $O(n)$ rather than $O(n^2)$.
\begin{figure}[H]
\small
\begin{verbatim}
pub enum ARegex {
    Phi,                   
    Eps(Bits), Lit(Bits, char),
    Alt(Bits, Box<ARegex>, Box<ARegex>),
    Seq(Bits, Box<ARegex>, Box<ARegex>),
    Star(Bits, Box<ARegex>),
}
\end{verbatim}
\caption{The annotated-expression type extends \texttt{Regex} with a leading
bit-sequence, \texttt{Bits}.}
\label{fig:aregex-enum}
\end{figure}

Every subsequent operation uses this type 
and must preserve annotations when derivative or simplification steps remove nodes.

\subsection{Fusing Bit-Lists}
\label{sec:fuse}
$\mathit{fuse}$, defined in \citep[Fig.~5]{sulzmannlu2014}, 
transfers bits from a node that is about to be removed 
onto the node that survives in its place. 
It prepends $bs$ to the top node's annotation $bs'$ 
without descending into its children, 
so outer reconstruction choices precede those 
already recorded in the subtree.
\begin{equation}\label{eq:fuse}
\begin{aligned}
\mathit{fuse}(bs, \emptyset) &= \emptyset \\
\mathit{fuse}(bs, (bs'@\varepsilon)) &= (bs \mathbin{+\!\!+} bs')@\varepsilon \\
\mathit{fuse}(bs, (bs'@x)) &= (bs \mathbin{+\!\!+} bs')@x \\
\mathit{fuse}(bs, (bs'@\mathit{ri}_1 \oplus \mathit{ri}_2))
  &= (bs \mathbin{+\!\!+} bs')@(\mathit{ri}_1 \oplus \mathit{ri}_2) \\
\mathit{fuse}(bs, (bs'@\mathit{ri}_1\,\mathit{ri}_2))
  &= (bs \mathbin{+\!\!+} bs')@(\mathit{ri}_1\,\mathit{ri}_2) \\
\mathit{fuse}(bs, (bs'@\mathit{ri}^{*}))
  &= (bs \mathbin{+\!\!+} bs')@\mathit{ri}^{*}.
\end{aligned}
\end{equation}

%

\paragraph{In Rust.}
\label{sec:fuse-impl}

Figure~\ref{fig:fuse-rust} implements the six rules of 
Equation~\eqref{eq:fuse}, one per variant. 
All arms except \texttt{Phi} prepend \texttt{bs} to the top node's own annotation 
and moves its children through unchanged.
Because the operation touches exactly one node 
regardless of the size of the subtree below it, 
\texttt{fuse} is non-recursive and no subtree is copied. 
\texttt{ri} is consumed by value,
so its untouched children move into the rebuilt node without a clone.
\texttt{Bits::prepend} wraps the existing chain 
in a new \texttt{Rc} rather than copying it, 
so the allocation is proportional to the length of \texttt{bs} alone, 
independent of how many bits the node already carries. 
Concretely, \texttt{Bits} is backed by a persistent \texttt{Node} enum:
\texttt{Node::Prepend} stores only the new prefix 
plus an \texttt{Rc} link to the previous chain, 
not a flattened copy. 
So reconstructing the full sequence later walks this chain once,
from newest to oldest. 

That walk is deferred to the end of parsing
rather than repeated at every \texttt{fuse} call.
With a plain \texttt{Vec<bool>}, 
prepending would instead copy the combined content on every call, 
and since a node's history grows with the input consumed so far, 
a single \texttt{fuse} would cost as much as the whole parse up to that point. 
\begin{figure}[H]
\small
\begin{verbatim}
pub fn fuse(bs: &[bool], ri: ARegex) -> ARegex {
    if bs.is_empty() { return ri; }
    match ri {
        ARegex::Phi => ARegex::Phi,
        ARegex::Eps(p) => ARegex::Eps(p.prepend(bs)),
        ARegex::Lit(p, c) => ARegex::Lit(p.prepend(bs), c),
        ARegex::Alt(p, r1, r2) => ARegex::Alt(p.prepend(bs), r1, r2),
        ARegex::Seq(p, r1, r2) => ARegex::Seq(p.prepend(bs), r1, r2),
        ARegex::Star(p, r) => ARegex::Star(p.prepend(bs), r),
    }
}

impl Bits {
    pub fn prepend(&self, prefix: &[bool]) -> Bits {
        if prefix.is_empty() { return self.clone(); }
        Bits(Rc::new(Node::Prepend(Rc::from(prefix), self.0.clone())))
    }
}
\end{verbatim}
\caption{\texttt{fuse}: prepend a bit-list to the annotation of the
top node.}
\label{fig:fuse-rust}
\end{figure}

\subsection{Internalizing Expressions}
\label{sec:internalize}

The forward pass operates on annotated expressions, but the input is a
plain expression, so $r$ must first be converted into its annotated
counterpart $\mathit{ri}$. The function $\mathit{internalize}$, following
\citep[Fig.~5]{sulzmannlu2014}, performs this conversion recursively.
\begin{equation}\label{eq:internalize}
\begin{aligned}
\mathit{internalize}(\emptyset) &= \emptyset \\
\mathit{internalize}(\varepsilon) &= [\,]@\varepsilon \\
\mathit{internalize}(x) &= [\,]@x \\
\mathit{internalize}(r_1+r_2) &=
  [\,]@\big(\mathit{fuse}([0],\mathit{internalize}(r_1))
  \oplus \mathit{fuse}([1],\mathit{internalize}(r_2))\big) \\
\mathit{internalize}(r_1\,r_2) &=
  [\,]@\big(\mathit{internalize}(r_1)\,\mathit{internalize}(r_2)\big) \\
\mathit{internalize}(r^{*}) &= [\,]@\mathit{internalize}(r)^{*}.
\end{aligned}
\end{equation}

The tags $[0]$ and $[1]$ mark the left and right branch of an alternation, 
so the decoder can later recover which one was taken. 
Every other case uses only the empty list, 
so the two $\mathit{fuse}$ calls in the alternation case 
are the only points where new bits are introduced.

%

\paragraph{In Rust.}
\label{sec:internalize-impl}

Figure~\ref{fig:internalize-rust} directly maps the constructors of
\texttt{Regex} to their annotated counterparts.
Each recursive call applies \texttt{internalize} to the corresponding subexpression, 
preserving the structure of the original expression in the annotated representation.
\texttt{Alt} is the only case that calls \texttt{fuse} with a non-empty bit-list, 
matching Equation~\eqref{eq:internalize}.
Star iteration choices are determined later, during derivative computation,
since the iteration count is not known until the input is actually consumed.

\begin{figure}[H]
\small
\begin{verbatim}
pub fn internalize(r: &Regex) -> ARegex {
    match r {
        Regex::Phi => ARegex::Phi,
        Regex::Eps => ARegex::Eps(Bits::empty()),
        Regex::Lit(c) => ARegex::Lit(Bits::empty(), *c),
        Regex::Alt(r1, r2) => {
            let ri1 = fuse(&[false], internalize(r1));
            let ri2 = fuse(&[true], internalize(r2));
            ARegex::Alt(Bits::empty(), Box::new(ri1), Box::new(ri2))
        }
        Regex::Seq(r1, r2) => ARegex::Seq(Bits::empty(),
            Box::new(internalize(r1)), Box::new(internalize(r2))),
        Regex::Star(r1) => ARegex::Star(Bits::empty(),
            Box::new(internalize(r1))),
    }
}
\end{verbatim}
\caption{\texttt{internalize} converts a \texttt{Regex} into an \texttt{ARegex}.
Each alternation branch receives a tag recording its side, and the two
\texttt{fuse} calls are the only points where new bits are introduced.}
\label{fig:internalize-rust}
\end{figure}

\subsection{Extracting Bits}
\label{sec:mkepsbc-theory}

$\mathit{mkEpsBC}$, from \citep[Fig.~5]{sulzmannlu2014}, 
is the bit-list counterpart of $\mathit{mkEps}$. 
It keeps the left preference and star closing bit, 
but extracts bits instead of building a tree. 
Each rule prepends the current node's bits to those returned recursively.
\begin{equation}\label{eq:mkepsbc}
\begin{aligned}
\mathit{mkEpsBC}_{(bs@\varepsilon)} &= bs \\[2pt]
\mathit{mkEpsBC}_{(bs@\mathit{ri}^{*})} &= bs \mathbin{+\!\!+} [1] \\[2pt]
\mathit{mkEpsBC}_{(bs@\mathit{ri}_1\, \mathit{ri}_2)} &=
  bs \mathbin{+\!\!+} \mathit{mkEpsBC}_{\mathit{ri}_1}
  \mathbin{+\!\!+} \mathit{mkEpsBC}_{\mathit{ri}_2} \\[2pt]
\mathit{mkEpsBC}_{(bs@\mathit{ri}_1\oplus\mathit{ri}_2)} &=
  bs \mathbin{+\!\!+}
  \begin{cases}
    \mathit{mkEpsBC}_{\mathit{ri}_1} & \varepsilon \in L(\mathit{ri}_1) \\
    \mathit{mkEpsBC}_{\mathit{ri}_2} & \text{otherwise.}
  \end{cases}
\end{aligned}
\end{equation}

As with $\mathit{mkEps}$, the rules cover only the four nullable forms.
$\emptyset$ and literals cannot match the empty word, 
so $\mathit{mkEpsBC}$ is called only on nullable expressions 
and both are handled as preconditions.

%

\paragraph{In Rust.}
Figure~\ref{fig:mkepsbc-rust} implements \texttt{mk\_eps\_bc} 
alongside \texttt{mk\_eps} (Figure~\ref{fig:mkeps-rust}), 
with one difference. 
Where \texttt{mk\_eps} builds a \texttt{ParseTree}, 
\texttt{mk\_eps\_bc} concatenates bit-lists, 
calling \texttt{bs.to\_vec()} where \texttt{mk\_eps} would borrow or clone.
This is the point where a node's \texttt{Bits} chain (Section~\ref{sec:aregex-type}) 
is walked and materialized into a concrete \texttt{Vec<bool>}, 
something \texttt{fuse} deliberately avoids doing on every derivative step. 
Like \texttt{mk\_eps}'s own \texttt{Star} arm, 
this one does not recurse into the child expression either.
A star matching the empty word always represents zero iterations 
regardless of what its body is, 
so there is nothing in the body left to inspect. 
It therefore only appends the closing \texttt{true} bit to \texttt{bs.to\_vec()}, 
a constant-cost step no matter how large the body's own subtree is.
\begin{figure}[H]
\small
\begin{verbatim}
pub fn mk_eps_bc(ri: &ARegex) -> Vec<bool> {
    match ri {
        ARegex::Phi => panic!("mk_eps_bc called on Phi"),
        ARegex::Lit(_, c) => panic!("mk_eps_bc called on Lit('{}')", c),
        ARegex::Eps(bs) => bs.to_vec(),
        ARegex::Alt(bs, r1, r2) => {
            let mut result = bs.to_vec();
            if nullable_bc(r1) { result.extend(mk_eps_bc(r1)); } 
            else { result.extend(mk_eps_bc(r2)); }
            result
        }
        ARegex::Seq(bs, r1, r2) => {
            let mut result = bs.to_vec();
            result.extend(mk_eps_bc(r1));
            result.extend(mk_eps_bc(r2));
            result
        }
        ARegex::Star(bs, _) => {
            let mut result = bs.to_vec();
            result.push(true);
            result
        }
    }
}
\end{verbatim}
\caption{\texttt{mk\_eps\_bc} implements Equation~\eqref{eq:mkepsbc}. 
\texttt{Phi}, \texttt{Lit} panic, since neither is nullable.}
\label{fig:mkepsbc-rust}
\end{figure}

\subsection{Annotated Derivatives}
\label{sec:deriv-bc-theory}

$\mathit{ri}\backslash_b l$ has the same case structure 
as the plain derivative in Equation~\eqref{eq:derivative}, 
but extended with bits threaded through the rules~\citep[Fig.~5]{sulzmannlu2014}.
\begin{equation}\label{eq:bderiv}
\begin{aligned}
\emptyset \backslash_b x &= \emptyset
  &&\hspace{-1em}(\mathsf{B}_{\emptyset}) \\
(bs@\varepsilon) \backslash_b x &= \emptyset
  &&\hspace{-1em}(\mathsf{B}_{\varepsilon}) \\
(bs@c) \backslash_b x &=
  \begin{cases}
    bs@\varepsilon & c = x \\
    \emptyset & \text{otherwise}
  \end{cases}
  &&\hspace{-1em}(\mathsf{B}_{\mathrm{lit}}) \\
(bs@\mathit{ri}_1 \oplus \mathit{ri}_2) \backslash_b x &=
  (bs@(\mathit{ri}_1 \backslash_b x) \oplus (\mathit{ri}_2 \backslash_b x))
  &&\hspace{-1em}(\mathsf{B}_{+}) \\
(bs@\mathit{ri}_1\,\mathit{ri}_2) \backslash_b x &=
  (bs@(\mathit{ri}_1 \backslash_b x)\,\mathit{ri}_2)
  &&\hspace{-1em}(\mathsf{B}_{\mathrm{seq}}),\ \varepsilon \notin L(\mathit{ri}_1) \\
(bs@\mathit{ri}_1\,\mathit{ri}_2) \backslash_b x &=
  bs@\Big(
    ([\,]@(\mathit{ri}_1 \backslash_b x)\,\mathit{ri}_2)
    \oplus
    \mathit{fuse}(\mathit{mkEpsBC}_{\mathit{ri}_1},
                   \mathit{ri}_2 \backslash_b x)
  \Big)
  &&\hspace{-1em}(\mathsf{B}_{\mathrm{seq}}^{\,n}),\ \varepsilon \in L(\mathit{ri}_1) \\
(bs@\mathit{ri}^{*}) \backslash_b x &=
  (bs@\mathit{fuse}([0],\mathit{ri} \backslash_b x)\,
  ([\,]@\mathit{ri}^{*}))
  &&\hspace{-1em}(\mathsf{B}_{*}).
\end{aligned}
\end{equation}

The rules $\mathsf{B}_{+}$, $\mathsf{B}_{\mathrm{seq}}$, 
and $\mathsf{B}_{*}$ preserve the outer $bs$, 
since derivation changes the residual but not the choices already recorded above it. 
The nullable sequence case $\mathsf{B}_{\mathrm{seq}}^{\,n}$ is the exception. 
Since $\mathit{ri}_1$ is nullable, $x$ may be matched by either factor, 
so the rule introduces a new alternation. 
Its left branch continues into $\mathit{ri}_1$, 
while its right branch recurses into $\mathit{ri}_2$, 
with the empty match's bits extracted by $\mathit{mkEpsBC}$ 
and fused onto $\mathit{ri}_2$'s derivative, 
so the choice inside $\mathit{ri}_1$ survives. 
This mirrors the role of $\mathsf{I}_{\mathrm{seq}}^{R}$ during injection.
The outer $bs$ attaches to the new alternation,
since it is the derivative of $\mathit{ri}_1\,\mathit{ri}_2$.

%

\paragraph{In Rust.}
\label{sec:deriv-bc-impl}

Figure~\ref{fig:derivbc-rust} implements Equation~\eqref{eq:bderiv}, 
following the case structure of plain \texttt{deriv} 
with bits threaded through the constructors. 
The base cases \texttt{Phi}, \texttt{Eps}, and \texttt{Lit} match plain \texttt{deriv}, 
except that \texttt{Lit} carries its bit-list onto the resulting \texttt{Eps}.
The \texttt{Alt} arm derives both operands and rebuilds the alternation
with the outer \texttt{bs} on the wrapper, not pushed into either branch.
This matches $\mathsf{B}_{+}$, 
where the recorded choice belongs to the alternation itself 
and derivation does not change it, 
so the bit stays on the outer constructor until the decoder reads it.

The \texttt{Seq} arm reflects $\mathsf{B}_{\mathrm{seq}}$ 
and $\mathsf{B}_{\mathrm{seq}}^{\,n}$. 
In the non-nullable case, \texttt{r1} must consume the character, 
so only its derivative is needed 
and \texttt{r2} moves directly into the rebuilt sequence. 
In the nullable case, both alternatives are possible. 
The bits of \texttt{r1}'s empty match are extracted 
by \texttt{mk\_eps\_bc} \emph{before} \texttt{r1} is consumed 
by \texttt{deriv\_bc}, since after that call the original \texttt{r1} is gone. 
Those bits are then fused onto the derivative of \texttt{r2}, 
so the choice made inside \texttt{r1} reaches the surviving branch. 
The left branch is wrapped in a fresh \texttt{Seq} with an empty bit-list, 
since the outer \texttt{bs} moves to the new \texttt{Alt} wrapper, 
matching $\mathsf{B}_{\mathrm{seq}}^{\,n}$. \texttt{r2} is needed twice. 
Once moved into the left branch, once cloned to compute its own derivative, 
so exactly one clone (\texttt{r2.clone()}) is required, 
while \texttt{nullable\_bc} only borrows \texttt{r1} 
before \texttt{deriv\_bc} consumes it.

The \texttt{Star} arm follows the same pattern as the nullable case of \texttt{Seq}. 
The body is needed twice: 
once cloned to compute its own derivative (\texttt{r.clone()}), and 
once moved, unchanged, into the reconstructed \texttt{Star}, 
wrapped with an empty bit-list for the same reason as the left branch above.
The leading \texttt{[false]} prepended to the derivative 
matches the \texttt{[0]} that $\mathsf{B}_{*}$ 
fuses onto $\mathit{ri}\backslash_b x$ itself, 
not the outer $bs$, which the Rust code leaves untouched on the surrounding \texttt{Seq}.

\begin{figure}[H]
\small
\begin{verbatim}
pub fn deriv_bc(ri: ARegex, l: char) -> ARegex {
    match ri {
        // ...
        ARegex::Alt(bs, r1, r2) => ARegex::Alt(bs,
            Box::new(deriv_bc(*r1, l)), Box::new(deriv_bc(*r2, l))),
        ARegex::Seq(bs, r1, r2) => {
            if nullable_bc(&r1) {
                let eps_bits = mk_eps_bc(&r1);
                let d2 = deriv_bc(*r2.clone(), l);
                let left = ARegex::Seq(Bits::empty(),
                    Box::new(deriv_bc(*r1, l)), r2);
                ARegex::Alt(bs, Box::new(left),
                    Box::new(fuse(&eps_bits, d2)))
            } else {
                ARegex::Seq(bs, Box::new(deriv_bc(*r1, l)), r2)
            }
        }
        ARegex::Star(bs, r) => ARegex::Seq(bs,
            Box::new(fuse(&[false], deriv_bc(*r.clone(), l))),
            Box::new(ARegex::Star(Bits::empty(), r))),
    }
}
\end{verbatim}

\subsection{Simplification}
\label{sec:simp}

$\mathit{simp}$, from \citep[Fig.~6]{sulzmannlu2014}, 
keeps the annotated expression's size bounded as derivation proceeds.
It discards dead ($\emptyset$) branches, 
collapses an $\varepsilon$ operand out of a concatenation, 
and removes duplicate alternation branches, 
fusing (Section~\ref{sec:fuse}) each removed node's bits onto whatever replaces it. 
A single bottom-up pass does not always reach a fixpoint.
Collapsing a branch at one level can expose a new collapse at the level above,
so $\mathit{simp}$ re-applies itself until the shape stops changing.
The \texttt{Alt} case's own cost follows the same logic: 
Flattening a nested alternation into one list 
before deduplicating keeps the cost of checking $p$ alternatives linear in $p$, 
rather than multiplying it by the chain's own depth 
the way deduplicating pairwise at each level of nesting would.
\begin{equation}\label{eq:isphi}
\begin{aligned}
\mathit{isPhi}(\emptyset) &= \mathrm{true} \\
\mathit{isPhi}(bs@\varepsilon) &= \mathrm{false} \\
\mathit{isPhi}(bs@x) &= \mathrm{false} \\
\mathit{isPhi}(bs@\mathit{ri}_1\,\mathit{ri}_2) &= \mathit{isPhi}(\mathit{ri}_1) \lor \mathit{isPhi}(\mathit{ri}_2) \\
\mathit{isPhi}(bs@\mathit{ri}_1 \oplus \mathit{ri}_2) &= \mathit{isPhi}(\mathit{ri}_1) \land \mathit{isPhi}(\mathit{ri}_2) \\
\mathit{isPhi}(bs@\mathit{ri}^{*}) &= \mathrm{false}
\end{aligned}
\end{equation}

We assume $\oplus$ takes a list of operands, written $bs@\oplus\,[\mathit{ri}_1,\ldots,\mathit{ri}_n]$.
{\small
\begin{equation}\label{eq:simp-theory}
\begin{aligned}
\mathit{simp}(bs@(bs'@\varepsilon)\,\mathit{ri}) &=
  \begin{cases}
    \emptyset & \text{if } \mathit{isPhi}(\mathit{ri}) \\
    \mathit{fuse}(bs \mathbin{+\!\!+} bs',\ \mathit{ri}) & \text{otherwise}
  \end{cases} \\[8pt]
\mathit{simp}(bs@\mathit{ri}_1\,\mathit{ri}_2) &=
  \begin{cases}
    \emptyset & \text{if } \mathit{isPhi}(\mathit{ri}_1) \lor \mathit{isPhi}(\mathit{ri}_2) \\
    bs@(\mathit{simp}(\mathit{ri}_1))\,(\mathit{simp}(\mathit{ri}_2)) & \text{otherwise}
  \end{cases} \\[8pt]
\mathit{simp}(bs@\oplus\,[\,]) &= \emptyset \\
\mathit{simp}(bs@\oplus\,((bs'@\oplus\,\mathit{rsi}_1) : \mathit{rsi}_2)) &=
  bs@\oplus\,\bigl(\mathit{map}(\mathit{fuse}\ bs')(\mathit{rsi}_1) \mathbin{+\!\!+} \mathit{rsi}_2\bigr) \\
\mathit{simp}(bs@\oplus\,[\mathit{ri}]) &= \mathit{fuse}(bs,\ \mathit{simp}(\mathit{ri})) \\
\mathit{simp}(bs@\oplus\,(\mathit{ri} : \mathit{rsi})) &=
  bs@\oplus\,\bigl(\mathit{nub}(\mathit{filter}(\lnot\,\mathit{isPhi})
  (\mathit{simp}(\mathit{ri}) : \mathit{map}(\mathit{simp})(\mathit{rsi})))\bigr)
\end{aligned}
\end{equation}
}

pub fn simp(ri: ARegex) -> ARegex {

        let next = simp_once(cur.clone());
        if same_shape(&next, &cur) { return next; }
        cur = next;
    }
}

\begin{figure}[H]
\small
\begin{verbatim}
fn simp_once(ri: ARegex) -> ARegex {
    match ri {
        ARegex::Phi | ARegex::Eps(_) | ARegex::Lit(_, _) => ri,

        ARegex::Seq(bs, r1, r2) => {
            let (r1s, r2s) = (simp_once(*r1), simp_once(*r2));
            if is_phi(&r1s) || is_phi(&r2s) { return ARegex::Phi; }
            if let ARegex::Eps(bs2) = r1s {
                return fuse_bits(&bs, fuse_bits(&bs2, r2s));  // eps.r -> r
            }
            if let ARegex::Eps(bs2) = &r2s {
                if bs2.is_empty() { return fuse_bits(&bs, r1s); } // r.eps -> r
            }
            ARegex::Seq(bs, Box::new(r1s), Box::new(r2s))
        }

        ARegex::Alt(bs, r1, r2) => {
            let mut branches: Vec<ARegex> = collect_alt_branches(*r1, *r2)
                .into_iter().map(simp_once).filter(|b| !is_phi(b)).collect();
            dedup_first(&mut branches);
            match branches.len() {
                0 => ARegex::Phi,
                1 => fuse_bits(&bs, branches.remove(0)),
                _ => fuse_bits(&bs, fold_alt(branches)),
            }
        }

        ARegex::Star(bs, r) => ARegex::Star(bs, Box::new(simp_once(*r))),
    }
}
\end{verbatim}
\caption{\texttt{simp\_once}: \texttt{Seq}/\texttt{Alt} simplification for
annotated expressions. \texttt{Seq} removes dead ($\emptyset$) or
already-\texttt{Eps} operands, while \texttt{Alt} removes dead and
duplicate branches. Removed bits are transferred using \texttt{fuse\_bits},
the \texttt{Bits}-native counterpart of \texttt{fuse} (Section~\ref{sec:fuse}),
avoiding a slice conversion and copy of the accumulated bit history.
}
\label{fig:simp-rust}
\end{figure}

%

Equation~\eqref{eq:simp-theory}'s alternation is list-based, 
but \texttt{ARegex::Alt} is binary (Section~\ref{sec:aregex-type}), 
so the implementation flattens nested \texttt{Alt} nodes, 
applies \texttt{map}, \texttt{filter}, and \texttt{nub}, then rebuilds the tree.
\texttt{collect\_alt\_branches}/\texttt{push\_branches} flatten
(Figure~\ref{fig:collect-alt-branches-rust})
and \texttt{fold\_alt} rebuilds that list into a binary \texttt{Alt} chain
(Figure~\ref{fig:fold-alt-rust}).
\texttt{map} and \texttt{filter} are exactly \texttt{.map(simp\_once)} 
and \texttt{.filter(|b| !is\_phi(b))} in Figure~\ref{fig:simp-rust}'s \texttt{Alt} arm.
and \texttt{nub} is \texttt{dedup\_first}, called right after. 
Only what \texttt{nub} treats as a `duplicate' 
is left unspecified by \citep[Fig.~6]{sulzmannlu2014}.
Here, bits are ignored when comparing expressions, 
following the pattern equality in \citep[Fig.~9]{sulzmannlu2012}. 
But this is not a form of disambiguation. 
\texttt{simp} works on one expression, not a set of states, 
so there is nothing to choose between. 
\texttt{same\_shape} only merges branches that are structurally identical, 
so they always derive and decode the same way. 
Discarding one of them has no effect on which parse tree is selected.
\texttt{collect\_alt\_branches} flattens nested \texttt{Alt} nodes 
via \texttt{push\_branches}, 
fusing each node's bits onto its children so no choice is lost. 
This lets \texttt{dedup\_first} compare every branch together, 
instead of once per nesting level,
removing survivors that still share the same regex. 
\texttt{dedup\_first} is shown later in full in Figure~\ref{fig:dedup-first-rust}.

\begin{figure}[H]
\small
\begin{verbatim}
fn collect_alt_branches(r1: ARegex, r2: ARegex) -> Vec<ARegex> {
    let mut out = Vec::new();
    push_branches(r1, &mut out);
    push_branches(r2, &mut out);
    out
}

fn push_branches(ri: ARegex, out: &mut Vec<ARegex>) {
    match ri {
        ARegex::Alt(bs, r1, r2) => {
            if bs.is_empty() {
                push_branches(*r1, out);
                push_branches(*r2, out);
            } else {
                let r1f = fuse_bits(&bs, *r1);
                let r2f = fuse_bits(&bs, *r2);
                push_branches(r1f, out);
                push_branches(r2f, out);
            }
        }
        other => out.push(other),
    }
}
\end{verbatim}
\caption{\texttt{collect\_alt\_branches} and \texttt{push\_branches}:
flattening nested \texttt{Alt} chains into one list,
fusing a parent's bits onto each child first.}
\label{fig:collect-alt-branches-rust}
\end{figure}

%

Figure~\ref{fig:fold-alt-rust} shows \texttt{fold\_alt}, 
which reconstructs a right-associated \texttt{Alt} tree 
while preserving the original left-to-right order. 
Reversing the list makes the last branch the initial value, 
so each preceding branch is nested outside it, 
leaving the first branch outermost.
\begin{figure}[H]
\small
\begin{verbatim}
fn fold_alt(mut branches: Vec<ARegex>) -> ARegex {
    branches.reverse();
    let mut acc = branches.remove(0);
    for b in branches {
        acc = ARegex::Alt(Bits::empty(), Box::new(b), Box::new(acc));
    }
    acc
}
\end{verbatim}
\caption{\texttt{fold\_alt}: rebuilds a flat, 
deduplicated branch list into a right-associated \texttt{Alt}.}
\label{fig:fold-alt-rust}
\end{figure}

The \texttt{Seq} case implements $\varepsilon \cdot r = r$ 
and $r \cdot \varepsilon = r$, 
but collapses the right operand only when its bits are empty. 
Otherwise, removing them would change the bit order 
in $\mathit{mkEpsBC}$'s left-to-right concatenation.
\texttt{same\_shape}, used by the fixpoint check and \texttt{dedup\_first}, 
compares expressions while ignoring bits (Section~\ref{sec:simp-impl}). 
This keeps the fixpoint check linear in the expression size, 
since bit lists are skipped rather than compared or copied. 
Derived structural equality would include them,
undermining the efficiency of the persistent \texttt{Bits} representation 
(Section~\ref{sec:aregex-type}).

\subsection{Decoding Bits}
\label{sec:decode}

$\mathit{decode}_r$ reconstructs a \texttt{ParseTree} 
from the bit sequence of $\mathit{mkEpsBC}$, 
walking $r$ with one bit per alternation 
to choose a branch~\citep[Fig.~4]{sulzmannlu2014}.
Its worker $\mathit{decodeInner}$ returns the current tree 
and the remaining bits, so the recursion continues at the correct position:
{\small
\begin{equation}\label{eq:decode}
\begin{aligned}
\mathit{decode}_r(bs) &= v \quad\text{if } \mathit{decodeInner}_r(bs)=(v,[\,]) \\[0.8em]
\mathit{decodeInner}_{\varepsilon}(bs)
  &= (\mathit{Empty},\ bs) \\
\mathit{decodeInner}_{x}(bs)
  &= (\mathit{Char}(x),\ bs) \\
\mathit{decodeInner}_{r_1+r_2}(0{:}bs)
  &= \bigl(\mathit{Left}(v),\ bs_1\bigr)
  \quad\text{if } \mathit{decodeInner}_{r_1}(bs)=(v,bs_1) \\
\mathit{decodeInner}_{r_1+r_2}(1{:}bs)
  &= \bigl(\mathit{Right}(v),\ bs_1\bigr)
  \quad\text{if } \mathit{decodeInner}_{r_2}(bs)=(v,bs_1) \\[4pt]
\mathit{decodeInner}_{r_1r_2}(bs)
  &= \bigl(\mathit{Pair}(v_1,v_2),\ bs_2\bigr) \\
  &\quad\text{if } \mathit{decodeInner}_{r_1}(bs)=(v_1,bs_1)
    \text{ and } \mathit{decodeInner}_{r_2}(bs_1)=(v_2,bs_2) \\[4pt]
\mathit{decodeInner}_{r^{*}}(1{:}bs)
  &= (\mathit{Star}([\,]),\ bs) \\
\mathit{decodeInner}_{r^{*}}(0{:}bs)
  &= \bigl(\mathit{Star}(v{:}vs),\ bs_2\bigr) \\
  &\quad\text{if } \mathit{decodeInner}_{r}(bs)=(v,bs_1)
    \text{ and } \mathit{decodeInner}_{r^{*}}(bs_1)=(\mathit{Star}(vs),bs_2)
\end{aligned}
\end{equation}
}

%

\paragraph{In Rust.}
\texttt{decode}, shown in Figure~\ref{fig:decode-rust}, 
is the public entry point.
It calls \texttt{decode\_inner} and asserts that no bits remain afterward. 
This assertion is the side condition under which $\mathit{decode}_r$ is defined.
The worker must consume the entire bit-string.
\begin{figure}[H]
\small
\begin{verbatim}
pub fn decode(r: &Regex, bs: &[bool]) -> ParseTree {
    let (v, rest) = decode_inner(r, bs);
    assert!(
        rest.is_empty(),
        "decode: {} leftover bit(s) after decoding {:?}",
        rest.len(),
        r
    );
    v
}
\end{verbatim}
\caption{\texttt{decode}: the public entry point, asserting that
\texttt{decode\_inner} consumed every bit.}
\label{fig:decode-rust}
\end{figure}

%

Figure~\ref{fig:decode-inner-rust} shows \texttt{decode\_inner}, 
the worker behind \texttt{decode}, one arm per expression form. 
It consumes the \texttt{\&[bool]} one bit per step using Rust's slice patterns:
\texttt{[false, rest @ ..]} binds a leading \texttt{false} 
and the remainder to \texttt{rest}, 
and \texttt{[true, rest @ ..]} does the same for \texttt{true}. 
The \texttt{Alt} arm reads the leading bit and recurses into the named branch, 
leaving \texttt{rest}.
Only that bit belongs to the alternation. 
\texttt{Seq} recurses twice, so the worker returns a pair.
The first factor's bits tell the second where to continue.
\texttt{Star}'s iteration count is encoded in the bits.
Each leading \texttt{false} recurses once more, resuming from the bits it returns,
until \texttt{mk\_eps\_bc}'s trailing \texttt{true} ends the loop.

\begin{figure}[H]
\small
\begin{verbatim}
fn decode_inner<'a>(r: &Regex, bs: &'a [bool]) -> (ParseTree, &'a [bool]) {
    match r {
        Regex::Eps => (ParseTree::Empty, bs),
        Regex::Lit(c) => (ParseTree::Char(*c), bs),
        Regex::Alt(r1, r2) => match bs {
            [false, rest @ ..] => {
                let (v, remaining) = decode_inner(r1, rest);
                (ParseTree::Left(Box::new(v)), remaining)
            }
            [true, rest @ ..] => {
                let (v, remaining) = decode_inner(r2, rest);
                (ParseTree::Right(Box::new(v)), remaining)
            }
            [] => panic!("decode: unexpected end of bits at Alt"),
        },
        Regex::Seq(r1, r2) => {
            let (v1, after_r1) = decode_inner(r1, bs);
            let (v2, after_r2) = decode_inner(r2, after_r1);
            (ParseTree::Pair(Box::new(v1), Box::new(v2)), after_r2)
        }
        Regex::Star(r1) => {
            let mut iterations = Vec::new();
            let mut remaining = bs;
            loop {
                match remaining {
                    [true, rest @ ..] => {
                        remaining = rest;
                        break;
                    }
                    [false, rest @ ..] => {
                        let (v, after) = decode_inner(r1, rest);
                        iterations.push(v);
                        remaining = after;
                    }
                    [] => panic!("decode: unexpected end of bits inside Star"),
                }
            }
            (ParseTree::Star(iterations), remaining)
        }
        Regex::Phi => panic!("decode: called on Phi"),
    }
}
\end{verbatim}
\caption{\texttt{decode\_inner}: the worker behind \texttt{decode},
one arm per expression form.}
\label{fig:decode-inner-rust}
\end{figure}

\newpage
\subsection{Parser}
\label{sec:deriv-bc-driver}

The bit-coded parser performs three steps on the input. 
First, $\mathit{internalize}$ converts the pattern $r$ 
into an annotated expression $\mathit{ri}$. 
Then, for each input character $c$, 
the parser takes the annotated derivative $\mathit{ri} \backslash_b c$ 
and simplifies it, 
replacing $\mathit{ri}$ with $\mathit{simp}(\mathit{ri} \backslash_b c)$.
After the last character, 
the parser checks whether the final $\mathit{ri}$ is nullable. 
If it is, the parser extracts the bits with $\mathit{mkEpsBC}$ 
and decodes them against the original $r$:
\begin{equation}\label{eq:bitcoded-driver}
\begin{aligned}
\mathit{ri}_0 &= \mathit{internalize}(r), \\
\mathit{ri}_i &= \mathit{simp}(\mathit{ri}_{i-1} \backslash_b x_i)
  \quad (1 \leq i \leq n), \\
\mathit{result} &=
  \begin{cases}
    \mathit{decode}_r(\mathit{mkEpsBC}(\mathit{ri}_n))
      & n(\mathit{ri}_n) \\
    \text{no match} & \text{otherwise.}
  \end{cases}
\end{aligned}
\end{equation}

The loop holds only the current $\mathit{ri}$. 
Unlike the standard derivative parser, 
which keeps a growing vector of residuals for the backward reconstruction, 
the bit-coded parser needs no history. 
The bits record everything needed to decode, 
so the forward pass can discard each intermediate expression 
as soon as the next one is computed.

%

\paragraph{In Rust.}
Figure~\ref{fig:deriv-bc-loop-rust} implements~\eqref{eq:bitcoded-driver}.

\begin{figure}[H]
\small
\begin{verbatim}
fn derive_and_simplify(ri: ARegex, chars: &[char]) -> ARegex {
    let mut cur = ri;
    for &l in chars { cur = simp(deriv_bc(cur, l)); }
    cur
}

pub fn parse_bitcoded_loop(input: &str, r: &Regex) -> Option<ParseTree> {
    let ri = internalize(r);
    let chars: Vec<char> = input.chars().collect();
    let final_ri = derive_and_simplify(ri, &chars);
    if !nullable_bc(&final_ri) { return None; }
    Some(decode(r, &mk_eps_bc(&final_ri)))
}
\end{verbatim}
\caption{\texttt{parse\_bitcoded\_loop}: the bit-coded parser's driver.
\texttt{derive\_and\_simplify} is factored out because the
recursive entry point (Section~\ref{sec:deriv-std-parser}'s counterpart for this
parser) shares the same per-character stepping and differs only in how
it reaches \texttt{ri} in the first place.}
\label{fig:deriv-bc-loop-rust}
\end{figure}

The loop matches the three cases of~\eqref{eq:bitcoded-driver} one for one. 
\texttt{internalize} initialises \texttt{ri}, \texttt{derive\_and\_simplify}
applies \texttt{simp(deriv\_bc(ri, l))} to each character 
and the nullability check gates the final \texttt{decode(mk\_eps\_bc(ri))}.

\newpage
\subsection{Worked Example: Bitcoded Derivative Parser}
\label{sec:deriv-bc-worked}

Consider the same input $\texttt{ab}$ and regular expression
$r_0=(a+ab)(b+\varepsilon)$ as in Section~\ref{sec:worked-example}.

%

\paragraph{Internalize.}
Before consuming input, $\mathit{internalize}$ tags each alternative 
with $[0]$ for the left branch and $[1]$ for the right branch:
\begin{equation}\label{eq:dpbc-internalize}
\mathit{internalize}(r_0) = \mathit{ri}_0 =
[\,]@\big(
  [\,]@([0]@a \oplus [1]@(a\,b))
  \cdot
  [\,]@([0]@b \oplus [1]@\varepsilon)
\big).
\end{equation}

%

\paragraph{Bit-Threaded Derivatives.}
Each input symbol is consumed by a bit-threaded derivative, 
with $\mathit{simp}$ applied after each step. 
The first uses $\mathsf{B}_{\mathrm{seq}}$.
Once $\mathtt{a}$ makes the first factor nullable, 
the second uses $\mathsf{B}_{\mathrm{seq}}^{\,n}$:
{\small
\begin{equation}\label{eq:dpbc-forward}
\begin{aligned}
\mathit{ri}_0
  &\xrightarrow[\mathsf{B}_{\mathrm{seq}}]{\ a\ }
  \mathit{ri}_1 =
  [\,]@\big(
    [\,]@([0]@\varepsilon \oplus [1]@b)
    \cdot
    [\,]@([0]@b \oplus [1]@\varepsilon)
  \big) \\
\mathit{ri}_1
  &\xrightarrow[\mathsf{B}_{\mathrm{seq}}^{\,n}]{\ b\ }
  \mathit{ri}_2' =
  [\,]@\Big(
    \underbrace{[\,]@(\emptyset \oplus [1]@\varepsilon)
      \cdot [\,]@([0]@b \oplus [1]@\varepsilon)}_{X}
    \;\oplus\;
    \underbrace{[0]@\big([0]@\varepsilon \oplus \emptyset\big)}_{Y}
  \Big) \\
  &\xrightarrow{\ \mathit{simp}\ }
  \mathit{ri}_2 =
  [\,]@\big(
    [1]@([0]@b \oplus [1]@\varepsilon)
    \oplus
    [0,0]@\varepsilon
  \big).
\end{aligned}
\end{equation}
}

Each disjunct of $\mathit{ri}_2'$ has a dead branch. 
In $X$, the first factor's derivative 
by $\mathtt{b}$ is $\emptyset \oplus [1]@\varepsilon$: 
$[0]$ cannot consume $\mathtt{b}$, and $[1]$ still owes one. 
In $Y$, the second factor's derivative by $\mathtt{b}$ 
is $[0]@\varepsilon \oplus \emptyset$: $[0]$ matches, $[1]$ cannot. 
$Y$'s outer $[0]$ is the bit $\mathsf{B}_{\mathrm{seq}}^{\,n}$ 
fused on from the first factor's empty match.

$\mathit{simp}$ drops the dead branches. 
$X$'s survivor is $[1]@\varepsilon$.
Since $\varepsilon$ contributes nothing to the concatenation, 
its $[1]$ carries onto the second factor, 
giving $[1]@([0]@b \oplus [1]@\varepsilon)$. 
$Y$'s survivor is $[0]@\varepsilon$.
Its outer and inner $[0]$s merge into $[0,0]@\varepsilon$. 
These two results become the disjuncts of $\mathit{ri}_2$, 
recording both bits so the tree can later be decoded from them alone.

%

\paragraph{Extracting the bits.}
Both disjuncts of $\mathit{ri}_2$ are nullable, 
so $\mathsf{EB}_{+}^{L}$ selects the left one. 
Inside, $b$ is not nullable while $\varepsilon$ is, 
so $\mathsf{EB}_{+}^{R}$ contributes its $[1]$ tag:
{\small
\begin{equation}\label{eq:dpbc-mkepsbc}
\mathit{mkEpsBC}(\mathit{ri}_2)
  \xrightarrow{\mathsf{EB}_{+}^{L}}
  \mathit{mkEpsBC}\big(
    [1]@([0]@b \oplus [1]@\varepsilon)
  \big)
  \xrightarrow{\mathsf{EB}_{+}^{R}}
  [1,1].
\end{equation}
}

Unlike $\mathit{mkEps}$, which builds a partial parse tree,
$\mathit{mkEpsBC}$ extracts only the committed choices, as a bit-string.

%

\paragraph{Decoding the bits.}
The decoder reads $[1,1]$ against $r_0$: 
The first bit takes the right branch of $a+ab$ (giving $ab$), 
the second the right branch of $b+\varepsilon$ (giving $\varepsilon$):
\begin{equation}\label{eq:dpbc-decode}
\mathit{decode}_{r_0}(\,[1,1]\,)
  = \big(
      \mathit{Right}(a,b),
      \mathit{Right}(\,)
    \big)
  = v_0.
\end{equation}
The decoder consumes bits left to right, one per alternation, 
in the order $\mathit{internalize}$ introduced them.
Since $\mathit{mkEpsBC}$ preserves that order when fusing and prepending bits, 
the first bit always belongs to the outermost alternation, and so on inward.

Flattening gives $\mathit{flatten}(v_0) = a \cdot b \cdot \varepsilon = \mathtt{ab}$,
confirming the parse. 
The bit-coded construction yields the same tree as the direct one, 
but stores only $\mathit{ri}_2$:
One expression bounded by the pattern, not one residual per character.
