\chapter{Derivative-Based Parser}
\label{sec:derivative-parser}

Chapter~\ref{sec:derivatives} showed how a Brzozowski-derivative matcher
determines whether $w \in L(r)$ and Chapter~
\ref{sec:matching-vs-parsing} showed that a matching word may admit multiple
valid parse trees. A parser must therefore select a single parse tree
according to a disambiguation policy.

Following Sulzmann and Lu \citep{sulzmannlu2014}, this chapter presents two
derivative-based methods for constructing POSIX parse trees. The direct
method performs a forward derivative pass followed by a backward pass for tree
reconstruction. The bit-coded method records parse-tree information during
the forward pass, avoiding a separate backward pass.

%
%
%

\section{The Standard Derivative-Based Parser}
\label{sec:core-algorithm}
Consider the ambiguous example from Chapter~\ref{sec:matching-vs-parsing},
$r = (a + ab)(b + \varepsilon)$ with input $w = \mathtt{ab}$, and ask
whether a parse tree can be recovered from the final derivative.
\begin{equation}\label{eq:deriv-std-example}
\begin{aligned}
r
  &\xrightarrow{\ a\ }
    (\varepsilon + \varepsilon b)(b + \varepsilon) \\[2pt]
  &\xrightarrow{\ b\ }
    (\phi + (\phi b + \varepsilon))(b + \varepsilon) + (\varepsilon + \phi).
\end{aligned}
\end{equation}

The final derivative is nullable, so \(w \in L(r)\) and
both disjuncts accept the empty word. Its first disjunct,
\((\phi+(\phi b+\varepsilon))(b+\varepsilon)\), reflects
\(ab\cdot\varepsilon\), and its second,
\((\varepsilon+\phi)\), reflects \(a\cdot b\). 

Since a derivative step only records the remaining input language and not
how consumed characters were matched, the final derivative alone does not
indicate which decomposition was selected, and therefore cannot be used
to recover the parse tree.

However, the derivation sequence itself contains this information. Each step
consumed one character and is invertible given that character, so
reversing the steps recovers the tree. Figure~\ref{fig:two-pass} shows
the forward pass as the derivation sequence and the backward pass as the
reconstruction.

\paragraph{The two-pass pipeline.}
The direct construction uses two passes. The forward pass applies
\texttt{deriv} ~\ref{fig:deriv-rust} and \texttt{nullable} ~\ref{fig:nullable-rust} 
to process the input, as shown in Chapter~\ref{sec:brzozowski-derivatives}.

The backward pass applies two new functions to walk the derivation
sequence in reverse and reconstruct the parse tree. 
First $\mathit{mkEps}$ builds a parse tree for the empty word
from the final nullable expression. 
Then injection steps are applied, 
with $\mathit{inj}$ reinserting one consumed character into the parse tree, 
moving in $w$ from right to left.
Each injection step takes the current parse tree, the corresponding
derivative step, and its consumed character, 
and returns the parse tree for the preceding expression.

As shown in Figure~\ref{fig:two-pass} after the first injection of $b$, the tree is
\((\mathit{Right}((),b),\mathit{Right}())\), where \(()\) marks the
position still to be filled. After the second injection of $a$, that position is
replaced by the subtree \(\mathit{Right}(a,b)\), giving the complete parse
tree \((\mathit{Right}(a,b),\mathit{Right}())\). 

In the following the operations for the standard
derivative parser are shown in more detail.

%

\subsection{Building the Empty-Word Tree}
\label{sec:mkeps-theory}

The backward pass begins with $\mathit{mkEps}$, which reads a parse tree
for the empty word off the final nullable expression.
The function is defined recursively:
\begin{equation}\label{eq:mkeps}
\begin{aligned}
\mathit{mkEps}_{\varepsilon} &= () &&(\mathsf{E}_{\varepsilon}) \\
\mathit{mkEps}_{r^{*}} &= [\,] &&(\mathsf{E}_{*}) \\
\mathit{mkEps}_{r_1 r_2} &= (\mathit{mkEps}_{r_1}, \mathit{mkEps}_{r_2})
  &&(\mathsf{E}_{\mathrm{seq}}) \\
\mathit{mkEps}_{r_1+r_2} &=
  \begin{cases}
    \mathit{Left}\ \mathit{mkEps}_{r_1} & \text{if } n(r_1) \\
    \mathit{Right}\ \mathit{mkEps}_{r_2} & \text{otherwise}
  \end{cases}
  &&\begin{array}{l}(\mathsf{E}_{+}^{L}) \\ (\mathsf{E}_{+}^{R})\end{array}
\end{aligned}
\end{equation}

The first three rules follow from the structure of the expression:
$(\mathsf{E}_{\varepsilon})$ gives $\varepsilon$ an empty parse tree,
$(\mathsf{E}_{*})$ treats a star matching the empty word as zero
iterations, and $(\mathsf{E}_{\mathrm{seq}})$ matches a concatenation
against $\varepsilon$ only when both factors do. No rules are needed for
$\emptyset$ or literals, since neither can match the empty word.
The alternation rule is where disambiguation occurs. If exactly one of
\(r_1\) and \(r_2\) is nullable, that branch is the only possible witness.
If both are, $(\mathsf{E}_{+}^{L})$ breaks the
tie by preferring the left one, following POSIX's leftmost-longest policy
\citep{sulzmannlu2014}.
In the example, the final expression is:
\[
(\phi + (\phi b + \varepsilon))(b + \varepsilon) + (\varepsilon + \phi).
\]
At top-level \(+\), both summands are nullable, so
$(\mathsf{E}_{+}^{L})$ applies and picks the left one. Within the left
summand's first factor \(\phi + (\phi b + \varepsilon)\), only the right
alternative is nullable, so $(\mathsf{E}_{+}^{R})$ applies, and within it
only the right sub-alternative \(\varepsilon\) is nullable, so
$(\mathsf{E}_{+}^{R})$ applies again, contributing
\(\mathit{RightRight}()\). The second factor \(b + \varepsilon\)
contributes \(\mathit{Right}()\) via $(\mathsf{E}_{+}^{R})$, giving:
\[
\mathit{Left}(\mathit{RightRight}(),\mathit{Right}()).
\]

Because disambiguation is deferred to \(\mathit{mkEps}\), the forward pass
cannot simplify. The second injection recovers
\(\mathit{Right}(a,b)\) only because the forward pass preserved the branch
that consumed \(a\). Had it been simplified away, the backward pass would
have had no node to reinsert \(a\) into. For example, simplifying at each
step collapses the derivation to:
\[
r \xrightarrow{\ a\ } (\varepsilon + b)(b + \varepsilon)
  \xrightarrow{\ b\ } \varepsilon,
\]
This still witnesses \(w \in L(r)\) but keeps no record of which
alternative consumed \(a\) or \(b\). The matcher accepts, but a parser
cannot recover \(\mathit{Right}(a,b)\) from \(\varepsilon\).

%

\paragraph{In Rust.}
\label{sec:mk-eps-impl}

The recursive definition of $\mathit{mkEps}$~\eqref{eq:mkeps} is implemented directly in
Rust, as shown in Figure~\ref{fig:mkeps-rust}, following the same cases for each expression form.

\begin{figure}[H]
\small
\begin{verbatim}
pub fn mk_eps(r: &Regex) -> ParseTree {
    match r {
        Regex::Eps         => ParseTree::Empty,
        Regex::Star(_)     => ParseTree::Star(Vec::new()),
        Regex::Seq(r1, r2) => ParseTree::Pair(
                              Box::new(mk_eps(r1)), Box::new(mk_eps(r2))),
        Regex::Alt(r1, r2) => 
            if nullable(r1)   {ParseTree::Left(Box::new(mk_eps(r1)))} 
            else              {ParseTree::Right(Box::new(mk_eps(r2)))},
        Regex::Lit(c)      => panic!("mk_eps called on Lit('{}')", c),
        Regex::Phi         => panic!("mk_eps called on Phi"),
    }
}
\end{verbatim}
\caption{\texttt{mk\_eps}: construct a parse tree for the empty word.}
\label{fig:mkeps-rust}
\end{figure}

The expression $r$ is borrowed rather than consumed because the backward
pass needs it again during injection. 
The alternation arm encodes disambiguation as a conditional,
examining \texttt{r2} only when \texttt{nullable(r1)} is false. The panic
arms enforce the precondition that $\mathit{mkEps}$ applies only to
nullable expressions, rejecting the non-nullable $\phi$ and literals.

\subsection{Reinserting Characters via Injection}
\label{sec:inj-theory}

After $\mathit{mkEps}$ constructed the parse tree $v$ for the empty input, 
the reconstruction starts
from this initial tree and proceeds backwards through the derivation sequence.
Each application of $\mathit{inj}$ takes the current tree, the corresponding
derivative step, and its consumed character, returning a tree for the
preceding expression.
$\mathit{inj}$ recursively follows the structure of
the residual until it reaches the subexpression containing the literal that
consumed the character. It reinserts the character there and then unwinds to
rebuild the surrounding tree. After all characters have been reinserted, 
the parse tree for the original expression and input is recovered. 
The injection function is defined by the following rules:
\begin{equation}\label{eq:inj}
\begin{aligned}
\mathit{inj}_{x \backslash x}() &= x
  &&(\mathsf{I}_{\mathrm{lit}}) \\
\mathit{inj}_{(r_1+r_2) \backslash x}(\mathit{Left}\ v_1)
  &= \mathit{Left}\ (\mathit{inj}_{r_1 \backslash x}\ v_1)
  &&(\mathsf{I}_{+}^{L}) \\
\mathit{inj}_{(r_1+r_2) \backslash x}(\mathit{Right}\ v_2)
  &= \mathit{Right}\ (\mathit{inj}_{r_2 \backslash x}\ v_2)
  &&(\mathsf{I}_{+}^{R}) \\
\mathit{inj}_{r^{*} \backslash x}(v, vs)
  &= (\mathit{inj}_{r \backslash x}\ v) : vs
  &&(\mathsf{I}_{*}) \\
\mathit{inj}_{(r_1 r_2) \backslash x}(v_1, v_2)
  &= (\mathit{inj}_{r_1 \backslash x}\ v_1,\ v_2)
  &&(\mathsf{I}_{\mathrm{seq}}),\ n(r_1) = \mathrm{false} \\
\mathit{inj}_{(r_1 r_2) \backslash x}(\mathit{Left}(v_1, v_2))
  &= (\mathit{inj}_{r_1 \backslash x}\ v_1,\ v_2)
  &&(\mathsf{I}_{\mathrm{seq}}^{L}),\ n(r_1) = \mathrm{true} \\
\mathit{inj}_{(r_1 r_2) \backslash x}(\mathit{Right}\ v_2)
  &= (\mathit{mkEps}_{r_1},\ \mathit{inj}_{r_2 \backslash x}\ v_2)
  &&(\mathsf{I}_{\mathrm{seq}}^{R}),\ n(r_1) = \mathrm{true}
\end{aligned}
\end{equation}

Rules $(\mathsf{I}_{\mathrm{lit}})$ and $(\mathsf{I}_{*})$ invert their
derivative rules directly, reconstructing the consumed character and the
current iteration, the latter prepended to the remaining ones.

Since the consumed character lies in exactly one branch of an
alternation, the incoming tree is either $\mathit{Left}\ v_1$ or
$\mathit{Right}\ v_2$. Rule $(\mathsf{I}_{+}^{L})$ recurses into $v_1$
and rebuilds the $\mathit{Left}$ node, and $(\mathsf{I}_{+}^{R})$
recurses into $v_2$ and rebuilds the $\mathit{Right}$ node.

The concatenation rules cover the three cases of the sequence derivative. If
$n(r_1) = \mathrm{false}$, $r_1$ cannot match $\varepsilon$ and must consume
$x$, so $(\mathsf{I}_{\mathrm{seq}})$ recurses into $v_1$. If
$n(r_1) = \mathrm{true}$, the derivative recorded which component consumed
$x$ as a tag: $(\mathsf{I}_{\mathrm{seq}}^{L})$ handles an incoming
$\mathit{Left}(v_1, v_2)$ tag and recurses into $v_1$, while
$(\mathsf{I}_{\mathrm{seq}}^{R})$ handles a $\mathit{Right}\ v_2$ tag by
reconstructing $r_1$'s empty match with $\mathit{mkEps}_{r_1}$ and recursing
into $v_2$.

Since $\phi$ consumes no characters, $\mathit{inj}$ is never applied with
$\phi$ as the residual.

\paragraph{In Rust.}
\label{sec:inject-impl}

\begin{figure}[H]
\small
\begin{verbatim}
pub fn inject(r: &Regex, l: char, v: ParseTree) -> ParseTree {
    match r {
        Regex::Lit(c) => { assert!(*c == l);
            ParseTree::Char(l) }
        Regex::Alt(r1, r2) => match v {
            ParseTree::Left(v1) =>
                ParseTree::Left(Box::new(inject(r1, l, *v1))),
            ParseTree::Right(v2) =>
                ParseTree::Right(Box::new(inject(r2, l, *v2))),
            _ => panic!("inject/Alt: want Left|Right"),
        },
        Regex::Star(r1) => match v {
            ParseTree::Pair(v1, vs) => {
                let mut it = vec![inject(r1, l, *v1)];
                if let ParseTree::Star(rest) = *vs { it.extend(rest); }
                ParseTree::Star(it)
            }
            _ => panic!("inject/Star: want Pair"),
        },
        Regex::Seq(r1, r2) => if !nullable(r1) {
            match v {
                ParseTree::Pair(v1, v2) => ParseTree::Pair(
                    Box::new(inject(r1, l, *v1)), v2),
                _ => panic!("inject/Seq: want Pair"),
            }
        } else {
            match v {
                ParseTree::Left(vp) => match *vp {
                    ParseTree::Pair(v1, v2) => ParseTree::Pair(
                        Box::new(inject(r1, l, *v1)), v2),
                    o => panic!("inject/SeqL: want Pair, got {:?}", o),
                },
                ParseTree::Right(v2) => ParseTree::Pair(
                    Box::new(mk_eps(r1)),
                    Box::new(inject(r2, l, *v2))),
                _ => panic!("inject/Seq: want Left|Right"),
            }
        },
        Regex::Eps | Regex::Phi => panic!("inject called on Eps/Phi"),
    }
}
\end{verbatim}
\caption{\texttt{inject}: reinsert a character into a parse tree.}
\label{fig:inject-rust}
\end{figure}

\texttt{inject(r, l, v)} takes three arguments because $\mathit{inj}$ is
indexed by both an expression and a character. Figure~\ref{fig:inject-rust}
shows the complete implementation.

The function matches on the expression \texttt{r} first and on the tree
\texttt{v} second, following the order in which \eqref{eq:inj} indexes its
rules. This order matters because a tree tag is interpreted relative to the
expression that produced it. Under an alternation, \texttt{Left} selects the
left disjunct, while under a nullable concatenation it indicates that the
derivative continued inside the left operand. The \texttt{Lit} arm
reconstructs a leaf after asserting that the consumed character matches,
and the \texttt{Star} arm inverts $(\mathsf{I}_{*})$, reinserting the
character into the current iteration and prepending it to the remaining
ones.

The expression \texttt{r} is borrowed and read only, while the tree
\texttt{v} is consumed and decomposed. In the concatenation arms where the
right operand was not derived, \texttt{v2} moves directly into the new pair,
since \eqref{eq:inj} leaves it unchanged. The \texttt{Right} arm of
concatenation is the only concatenation case that synthesizes content,
calling \texttt{mk\_eps(r1)} because the derivative skipped \texttt{r1} and
the forward pass produced no tree for that half of the pair.

Calling \texttt{nullable(r1)} in the \texttt{Seq} arm recomputes a decision
the forward pass already made when it chose between
$\mathsf{D}_{\mathrm{seq}}$ and $\mathsf{D}_{\mathrm{seq}}^{\,n}$. Carrying
this decision through the expression sequence would require storing an
additional flag at every step, while \texttt{nullable} is cheap to evaluate
on demand.

\subsection{Parser}
\label{sec:deriv-std-parser}
The parser composes \texttt{mkEps} and \texttt{inject} by storing every
forward-pass expression, then reconstructing the tree in reverse.
Figure~\ref{fig:deriv-std-drivers-rust} implements this iteratively. A
recursive implementation would keep the expression sequence on the call
stack, whose size is fixed, whereas the loop variant uses a \texttt{Vec}
that grows dynamically on the heap. The loop variant therefore accommodates
longer inputs without stack overflow.
\begin{figure}[H]
\small
\begin{verbatim}
pub fn parse_deriv_std_loop(input: &str, r: &Regex)
    -> Option<ParseTree>
{
    let chars: Vec<char> = input.chars().collect();
    let mut expressions = Vec::with_capacity(chars.len() + 1);
    expressions.push(r.clone());
    for &c in &chars {
        expressions.push(deriv(expressions.last().unwrap(), c));
    }
    if !nullable(expressions.last().unwrap()) { return None; }
    let mut tree = mk_eps(expressions.last().unwrap());
    for i in (0..chars.len()).rev() {
        tree = inject(&expressions[i], chars[i], tree);
    }
    Some(tree)
}
\end{verbatim}
\caption{The standard derivative-based parser. The forward pass sets
\texttt{expressions[0]}=$r$ and appends \texttt{deriv} for each character,
so entry $i$ is the residual after $i$ characters; a non-nullable final
entry returns \texttt{None}. The backward pass starts from \texttt{mk\_eps}
of the final entry and applies \texttt{inject} to entries $n-1$ down to $0$
with the corresponding characters, undoing one derivative step per
character and yielding the parse tree for $r$.}
\label{fig:deriv-std-drivers-rust}
\end{figure}

\subsection{Worked Example: Ambiguous Expression}
\label{sec:worked-example}
Recall the ambiguous example of Section~\ref{par:ambiguous-example},
$r_0=(a\mid ab)(b\mid\varepsilon)$ on input $\texttt{ab}$.

%

\paragraph{Forward pass.}
There are two derivative steps, one per input symbol. After
deriving \texttt{a}, the left factor $\varepsilon+\varepsilon b$
is nullable, so the second derivation on \texttt{b} uses
$\mathsf{D}_{\mathrm{seq}}^{\,n}$ rather than $\mathsf{D}_{\mathrm{seq}}$.
\[
\begin{aligned}
r_0 = (a+ab)(b+\varepsilon)
  &\xrightarrow[\mathsf{D}_{\mathrm{seq}}]{a}
    r_1 = (\varepsilon+\varepsilon b)(b+\varepsilon) \\
  &\xrightarrow[\mathsf{D}_{\mathrm{seq}}^{\,n}]{b}
    r_2 = \underbrace{(\phi+(\phi b+\varepsilon))(b+\varepsilon)}_{X}
       + \underbrace{(\varepsilon+\phi)}_{Y}.
\end{aligned}
\]

The resulting final expression is $r_2$, both $X$ and $Y$ are nullable. 
The disjunct $X$ is the residual of the
$ab$ alternative in the first factor, and $Y$ is the residual of the $a$
alternative. 

%

\paragraph{Backward pass.}
The backward pass starts by building the parse tree for the empty word: $\mathit{mkEps}(r_2)$. 
Since $r_2 = X + Y$ and both disjuncts are nullable,
$\mathsf{E}_{+}^{L}$ selects $X$.
As $X$ is a concatenation, $\mathsf{E}_{\mathrm{seq}}$ combines
the trees for its two factors:
\[
\begin{aligned}
\mathit{mkEps}(r_2)
  &= \mathit{mkEps}(X+Y)
     \xrightarrow{\ \mathsf{E}_{+}^{L}\ }
     \mathit{Left}\,\mathit{mkEps}(X)
\\[0.8em]
  \mathit{mkEps}(X)
  &\xrightarrow{\ \mathsf{E}_{\mathrm{seq}}\ }
     \bigl(
       \mathit{mkEps}(\phi+(\phi b+\varepsilon)),
       \mathit{mkEps}(b+\varepsilon)
     \bigr).
\end{aligned}
\]

Since $\phi$ and $\phi b$ are not nullable, the first factor
selects $\varepsilon$ through two applications of
$\mathsf{E}_{+}^{R}$. Similarly, since $b$ is not nullable,
the second factor selects $\varepsilon$ through $\mathsf{E}_{+}^{R}$:
\[
\begin{array}{@{}c@{\hspace{1em}}c@{}}
\begin{aligned}
\mathit{mkEps}(\phi+(\phi b+\varepsilon))
  &\xrightarrow{\ \mathsf{E}_{+}^{R}\ }
    \mathit{Right}\,\mathit{mkEps}(\phi b+\varepsilon)\\
  &\xrightarrow{\ \mathsf{E}_{+}^{R}\ }
    \mathit{Right}\,\mathit{Right}\,
    \mathit{mkEps}(\varepsilon)\\
  &\xrightarrow{\ \mathsf{E}_{\varepsilon}\ }
    \mathit{Right}\,\mathit{Right}\,()
\end{aligned}
&
\begin{aligned}
\mathit{mkEps}(b+\varepsilon)
  &\xrightarrow{\ \mathsf{E}_{+}^{R}\ }
    \mathit{Right}\,\mathit{mkEps}(\varepsilon)\\
  &\xrightarrow{\ \mathsf{E}_{\varepsilon}\ }
    \mathit{Right}\,()
\end{aligned}
\end{array}
\]

Combining the two factors gives:
\[
v_2 = \mathit{mkEps}(r_2)
    = \mathit{Left}\bigl(
        \mathit{Right}\,\mathit{Right}\,(),
        \mathit{Right}\,()
      \bigr).
\]

Reinsertion begins with $\mathtt{b}$, mapping $v_2$ to a tree for
$r_1=(\varepsilon+\varepsilon b)(b+\varepsilon)$. Since $v_2$ carries a
$\mathit{Left}$ tag, $\mathsf{I}_{\mathrm{seq}}^{L}$ fires at this outer
concatenation: it recurses into the first factor $\varepsilon+\varepsilon b$
and leaves the second factor's component, $\mathit{Right}\,()$, exactly as
$\mathit{mkEps}$ left it, since $(b+\varepsilon)$ is not derived at this
step. Inside $\varepsilon+\varepsilon b$ the incoming tag is
$\mathit{Right}$, so $\mathsf{I}_{+}^{R}$ selects $\varepsilon b$, the
residual of the $ab$ alternative. Inside $\varepsilon b$,
$\mathsf{I}_{\mathrm{seq}}^{R}$ fires again, now at this concatenation's own
nullable left factor, giving $\mathit{mkEps}(\varepsilon)=()$ 
and recursing into $\mathtt{b}$, where
$\mathsf{I}_{\mathrm{lit}}$ reinserts the character:
\[
\begin{aligned}
\mathit{inj}_{r_1 \backslash \mathtt{b}}(v_2)
  &= \mathit{inj}_{r_1 \backslash \mathtt{b}}\bigl(
       \mathit{Left}(\mathit{Right}\,\mathit{Right}\,(),\;
                    \mathit{Right}\,())\bigr)\\
  &\xrightarrow{\ \mathsf{I}_{\mathrm{seq}}^{L}\ }
    \bigl(\mathit{inj}_{(\varepsilon+\varepsilon b)
          \backslash \mathtt{b}}(\mathit{Right}\,\mathit{Right}\,()),\;
          \mathit{Right}\,()\bigr)\\
  &\xrightarrow{\ \mathsf{I}_{+}^{R}\ }
    \bigl(\mathit{Right}\,
          \mathit{inj}_{\varepsilon b \backslash \mathtt{b}}
          (\mathit{Right}\,()),\;
          \mathit{Right}\,()\bigr)\\
  &\xrightarrow{\ \mathsf{I}_{\mathrm{seq}}^{R}\ }
    \bigl(\mathit{Right}\,
          (\mathit{mkEps}(\varepsilon),\;
           \mathit{inj}_{b \backslash \mathtt{b}}()),\;
          \mathit{Right}\,()\bigr)\\
  &\xrightarrow{\ \mathsf{E}_{\varepsilon},\ \mathsf{I}_{\mathrm{lit}}\ }
    \bigl(\mathit{Right}((), b),\;
          \mathit{Right}\,()\bigr)
    = v_1
\end{aligned}
\]

$(b+\varepsilon)$ is never visited during this step. Under the
$ab\cdot\varepsilon$ decomposition every consumed character belongs to the
first factor, so the second factor's tree is settled once, by
$\mathit{mkEps}$, and simply carries through unchanged.

Reinsertion of $\mathtt{a}$ maps $v_1$ to a parse tree for
$r_0=(a+ab)(b+\varepsilon)$. The outer sequence's first factor $a+ab$ is
not nullable, so $\mathsf{I}_{\mathrm{seq}}$ fires directly on $v_1$'s
first component, again leaving the second component $\mathit{Right}\,()$
untouched. That first component, $\mathit{Right}((),b)$, carries a
$\mathit{Right}$ tag, so $\mathsf{I}_{+}^{R}$ selects $ab$. Inside
$ab=\mathit{Seq}(a,b)$ the first factor $a$ is again not nullable, so
$\mathsf{I}_{\mathrm{seq}}$ fires once more and recurses into $a$, where
$\mathsf{I}_{\mathrm{lit}}$ reinserts the character:
\[
\begin{aligned}
\mathit{inj}_{r_0 \backslash \mathtt{a}}(v_1)
  &= \mathit{inj}_{r_0 \backslash \mathtt{a}}\bigl(
       (\mathit{Right}((), b),\;
        \mathit{Right}\,())\bigr)\\
  &\xrightarrow{\ \mathsf{I}_{\mathrm{seq}}\ }
    \bigl(\mathit{inj}_{(a+ab) \backslash \mathtt{a}}
          (\mathit{Right}((), b)),\;
          \mathit{Right}\,()\bigr)\\
  &\xrightarrow{\ \mathsf{I}_{+}^{R}\ }
    \bigl(\mathit{Right}\,
          \mathit{inj}_{ab \backslash \mathtt{a}}
          (((), b)),\;
          \mathit{Right}\,()\bigr)\\
  &\xrightarrow{\ \mathsf{I}_{\mathrm{seq}}\ }
    \bigl(\mathit{Right}\,
          (\mathit{inj}_{a \backslash \mathtt{a}}(()),\;
           b),\;
          \mathit{Right}\,()\bigr)\\
  &\xrightarrow{\ \mathsf{I}_{\mathrm{lit}}\ }
    \bigl(\mathit{Right}(a, b),\;
          \mathit{Right}\,()\bigr)
    = v_0.
\end{aligned}
\]

Flattening confirms $\mathit{flatten}(v_0) = a \cdot b \cdot \varepsilon = \mathtt{ab}$.

\section{The Bit-Coded Derivative-Based Parser}
\label{sec:bitcoded-construction-formal}

The direct construction cannot build any part of the parse tree until the
entire input has been consumed, because each injection step in the backward
pass needs the expression that preceded it. 
The bit-coded construction \citep{sulzmannlu2014} removes this dependency
by recording the reconstruction information during the forward pass.

Figure~\ref{fig:single-pass} shows the process on the same ambiguous
example as before:

\begin{figure}[ht]

\paragraph{The bit-coded pipeline.}
$\mathit{internalize}$ converts the pattern $r$ into an annotated
expression, tagging each alternation branch with an initial bit. The tag
records which branch was written first, and it is what eventually lets
$\mathit{decode}_r$ reconstruct the tree.

$\mathit{fuse}$ prepends a bit-list to the annotation of a node. It is how
the bits travel from the point where a choice was made in the forward pass
to the point where $\mathit{mkEpsBC}$ reads them back, since the choice is
recorded not on the node that made it but on the node that survives from it.

At each character the annotated expression is derived using the
bit-threaded derivative $\mathit{deriv}_{\mathit{bc}}$, and then simplified
by $\mathit{simp}$. Unlike the direct construction, simplification is safe
here, because the bits preserve the information that the direct construction
would lose. Removing a node does not remove the bit that was attached to
it. The bit moves outward through $\mathit{fuse}$ until it reaches a node
that survives. The residuals in Figure~\ref{fig:single-pass} are therefore
small, in contrast to those in Figure~\ref{fig:two-pass}.

Once the input is consumed, $\mathit{mkEpsBC}$ extracts the accumulated
bits from the final expression, applying the same left-preference rule at
alternations that $\mathit{mkEps}$ applies in the direct construction. The
bit sequence it produces is the complete record of the choices the forward
pass made. $\mathit{decode}_r$ then interprets this sequence against the
original pattern $r$ to reconstruct the parse tree, without referring to
any intermediate residual.

The two constructions therefore produce the same tree by different
routes. The direct construction stores the full residual at every step and
reverses them one at a time. The bit-coded construction stores only a bit
at every step and reverses them all at once, at the cost of carrying the
annotation through each derivative and each simplification.

\subsection{Annotated Expressions}
\label{sec:annotated-expressions}

Building parse-tree information during the forward pass extends the
derivative computation with bit-list annotations, propagated by the
bit-threaded derivative $\mathit{ri}\backslash_b l$.

An annotated expression $\mathit{ri}$ extends $r$ by associating each
non-$\emptyset$ node with a bit-list $bs$ recording the reconstruction
choices made during the forward pass.

\[
\mathit{ri} ::= \emptyset \mid (bs@\varepsilon) \mid (bs@x) \mid
(bs@\mathit{ri}_1 \oplus \mathit{ri}_2) \mid
(bs@\mathit{ri}_1\,\mathit{ri}_2) \mid
(bs@\mathit{ri}^{*}).
\]

%

\paragraph{In Rust.}
\label{sec:aregex-type}

Figure~\ref{fig:aregex-enum} defines \texttt{ARegex} as the annotated
counterpart of \texttt{Regex}. Every variant except \texttt{Phi} carries a
leading \texttt{Vec<bool>} corresponding to the theoretical bit-list $bs$,
with one \texttt{bool} per bit. The \texttt{Phi} variant has no annotation
because it cannot contribute to a successful parse. Thus, \texttt{ARegex}
adds the storage needed to thread parse-tree information through the
expression, directly mirroring the theoretical $bs$ lists in
~\eqref{eq:bderiv}.

pub enum ARegex {

    Eps(Vec<bool>), Lit(Vec<bool>, char),
    Alt(Vec<bool>, Box<ARegex>, Box<ARegex>),
    Seq(Vec<bool>, Box<ARegex>, Box<ARegex>),
    Star(Vec<bool>, Box<ARegex>),
}

\subsection{Fusing Bit-Lists}
\label{sec:fuse}
$\mathit{fuse}$ prepends $bs$ to the top node's annotation $bs'$ without
descending into its children, so outer reconstruction choices precede
those already recorded in the subtree.

\begin{equation}\label{eq:fuse}
\begin{aligned}
\mathit{fuse}(bs, \emptyset) &= \emptyset \\
\mathit{fuse}(bs, (bs'@\varepsilon)) &= (bs \mathbin{+\!\!+} bs')@\varepsilon \\
\mathit{fuse}(bs, (bs'@x)) &= (bs \mathbin{+\!\!+} bs')@x \\
\mathit{fuse}(bs, (bs'@\mathit{ri}_1 \oplus \mathit{ri}_2))
  &= (bs \mathbin{+\!\!+} bs')@(\mathit{ri}_1 \oplus \mathit{ri}_2) \\
\mathit{fuse}(bs, (bs'@\mathit{ri}_1\,\mathit{ri}_2))
  &= (bs \mathbin{+\!\!+} bs')@(\mathit{ri}_1\,\mathit{ri}_2) \\
\mathit{fuse}(bs, (bs'@\mathit{ri}^{*}))
  &= (bs \mathbin{+\!\!+} bs')@\mathit{ri}^{*}.
\end{aligned}
\end{equation}

%

\paragraph{In Rust.}
\label{sec:fuse-impl}

Figure~\ref{fig:fuse-rust} implements this operation. \texttt{combine}
concatenates the bit-lists, while \texttt{fuse} rebuilds only the top node.
An empty \texttt{bs} returns it unchanged.
\begin{figure}[H]
\small
\begin{verbatim}
pub fn fuse(bs: &[bool], ri: ARegex) -> ARegex {
    if bs.is_empty() { return ri; }
    match ri {
        ARegex::Phi => ARegex::Phi,
        ARegex::Eps(p) => ARegex::Eps(combine(bs, p)),
        ARegex::Lit(p, c) => ARegex::Lit(combine(bs, p), c),
        ARegex::Alt(p, r1, r2) => ARegex::Alt(combine(bs, p), r1, r2),
        ARegex::Seq(p, r1, r2) => ARegex::Seq(combine(bs, p), r1, r2),
        ARegex::Star(p, r) => ARegex::Star(combine(bs, p), r),
    }
}

fn combine(bs: &[bool], p: Vec<bool>) -> Vec<bool> {
    let mut new = bs.to_vec();
    new.extend(p);
    new
}
\end{verbatim}

top node.}

\end{figure}

\subsection{Extracting Bits}
\label{sec:mkepsbc-theory}

$\mathit{mkEpsBC}$ mirrors $\mathit{mkEps}$ but extracts the corresponding
bit-list, using the same left preference at alternation and a closing $1$
for a star. Unlike $\mathit{mkEps}$, it constructs no parse-tree nodes.
Each rule prepends the current node's bits to those returned recursively.
\begin{equation}\label{eq:mkepsbc}
\begin{aligned}
\mathit{mkEpsBC}_{(bs@\varepsilon)} &= bs,
\qquad
\mathit{mkEpsBC}_{(bs@\mathit{ri}^{*})} = bs \mathbin{+\!\!+} [1], \\
\mathit{mkEpsBC}_{(bs@\mathit{ri}_1\, \mathit{ri}_2)} &=
  bs \mathbin{+\!\!+} \mathit{mkEpsBC}_{\mathit{ri}_1} \mathbin{+\!\!+} \mathit{mkEpsBC}_{\mathit{ri}_2}, \\
\mathit{mkEpsBC}_{(bs@\mathit{ri}_1\oplus\mathit{ri}_2)} &=
  bs \mathbin{+\!\!+}
  \begin{cases}
    \mathit{mkEpsBC}_{\mathit{ri}_1} & \varepsilon \in L(\mathit{ri}_1) \\
    \mathit{mkEpsBC}_{\mathit{ri}_2} & \text{otherwise.}
  \end{cases}
\end{aligned}
\end{equation}

%

\paragraph{In Rust.}
Figure~\ref{fig:mkepsbc-rust} mirrors \texttt{mk\_eps}
(Figure~\ref{fig:mkeps-rust}), replacing \texttt{ParseTree} construction
with bit-list concatenation. 
The \texttt{Star} case does not recurse because the empty parse of a star
uses zero iterations, it only appends the closing \texttt{true}. The child
expression is therefore never examined, as \texttt{true} records the
decision to stop the iteration immediately.
\begin{figure}[H]
\small
\begin{verbatim}
pub fn mk_eps_bc(ri: &ARegex) -> Vec<bool> {
    match ri {
        // Phi, Lit: unreachable, mk_eps_bc is called only once
        // nullable_bc(&ri) holds, and neither is ever nullable
        ARegex::Eps(bs) => bs.clone(),
        ARegex::Alt(bs, r1, r2) => {
            let mut result = bs.clone();
            if nullable_bc(r1) {
                result.extend(mk_eps_bc(r1));
            } else {
                result.extend(mk_eps_bc(r2));
            }
            result
        }
        ARegex::Seq(bs, r1, r2) => {
            let mut result = bs.clone();
            result.extend(mk_eps_bc(r1));
            result.extend(mk_eps_bc(r2));
            result
        }
        ARegex::Star(bs, _) => {
            let mut result = bs.clone();
            result.push(true);
            result
        }
    }
}
\end{verbatim}

~\eqref{eq:mkepsbc}.}
\label{fig:mkepsbc-rust}
\end{figure}

\subsection{Annotated Derivatives}
\label{sec:deriv-bc-theory}

$\mathit{ri}\backslash_b l$ has the same case structure of
~\eqref{eq:derivative}, with bits threaded through instead of
discarded:
\begin{equation}\label{eq:bderiv}
\begin{aligned}
(bs@\mathit{ri}_1 \oplus \mathit{ri}_2) \backslash_b l &=
  (bs@(\mathit{ri}_1 \backslash_b l) \oplus (\mathit{ri}_2 \backslash_b l))
  &&(\mathsf{B}_{+}) \\
(bs@\mathit{ri}_1\,\mathit{ri}_2) \backslash_b l &=
  (bs@(\mathit{ri}_1 \backslash_b l)\,\mathit{ri}_2)
  &&(\mathsf{B}_{\mathrm{seq}}),\ \varepsilon \notin L(\mathit{ri}_1) \\
(bs@\mathit{ri}_1\,\mathit{ri}_2) \backslash_b l &=
  (bs@(\mathit{ri}_1 \backslash_b l)\,\mathit{ri}_2)
  \oplus
  \mathit{fuse}(\mathit{mkEpsBC}_{\mathit{ri}_1},
                 \mathit{ri}_2 \backslash_b l)
  &&(\mathsf{B}_{\mathrm{seq}}^{\,n}),\ \varepsilon \in L(\mathit{ri}_1) \\
(bs@\mathit{ri}^{*}) \backslash_b l &=
  (bs@\mathit{fuse}([0],\mathit{ri} \backslash_b l)\,
  ([\,]@\mathit{ri}^{*}))
  &&(\mathsf{B}_{*}).
\end{aligned}
\end{equation}

The $\mathsf{B}_{\mathrm{seq}}^{\,n}$ branch proceeds directly into
$\mathit{ri}_2$, so the bits produced by the empty match of
$\mathit{ri}_1$ are fused into the derivative of $\mathit{ri}_2$. This
performs during the forward pass the reconstruction step that
$\mathsf{I}_{\mathrm{seq}}^{R}$ would otherwise perform during
$\mathit{inj}$.

%

\paragraph{In Rust.}
\label{sec:deriv-bc-impl}

Figure~\ref{fig:derivbc-rust} implements the rules in~\eqref{eq:bderiv},
following the case structure of plain \texttt{deriv} with annotations
threaded through the constructors. The nullable \texttt{Seq} and
\texttt{Star} cases additionally use \texttt{mk\_eps\_bc} and
\texttt{fuse} to preserve reconstruction information.
\begin{figure}[H]
\small
\begin{verbatim}
pub fn deriv_bc(ri: ARegex, l: char) -> ARegex {
    match ri {
        // Phi, Eps, Lit: unchanged from plain deriv 
        ARegex::Alt(bs, r1, r2) => {
            let d1 = deriv_bc(*r1, l);
            let d2 = deriv_bc(*r2, l);
            ARegex::Alt(bs, Box::new(d1), Box::new(d2))
        }
        ARegex::Seq(bs, r1, r2) => {
            if nullable_bc(&r1) {
                let eps_bits = mk_eps_bc(&r1);
                let d1 = deriv_bc(*r1, l);
                let d2 = deriv_bc(*r2.clone(), l);
                let left_branch = ARegex::Seq(vec![], Box::new(d1), r2);
                let right_branch = fuse(&eps_bits, d2);
                ARegex::Alt(bs, Box::new(left_branch), Box::new(right_branch))
            } else {
                let d1 = deriv_bc(*r1, l);
                ARegex::Seq(bs, Box::new(d1), r2)
            }
        }
        ARegex::Star(bs, r) => {
            let d = deriv_bc(*r.clone(), l);
            let fused = fuse(&[false], d);
            let new_star = ARegex::Star(vec![], r);
            ARegex::Seq(bs, Box::new(fused), Box::new(new_star))
        }
    }
}
\end{verbatim}
\caption{\texttt{deriv\_bc} (excerpt): the \texttt{Alt}, \texttt{Seq}, and
\texttt{Star} arms implementing $\mathsf{B}_{+}$,
$\mathsf{B}_{\mathrm{seq}}/\mathsf{B}_{\mathrm{seq}}^{\,n}$, and
$\mathsf{B}_{*}$; the \texttt{Phi}/\texttt{Eps}/\texttt{Lit} base cases,
unchanged from plain \texttt{deriv}, are omitted.}
\label{fig:derivbc-rust}
\end{figure}

The \texttt{Alt} arm derives both operands and
preserves the outer \texttt{bs}, since deriving does not change the
choice already recorded for that alternation.

The \texttt{Seq} arm reflects $\mathsf{B}_{\mathrm{seq}}$ and
$\mathsf{B}_{\mathrm{seq}}^{\,n}$. In the non-nullable case, \texttt{r2}
is moved directly into the rebuilt sequence. In the nullable case,
\texttt{r2} is needed both unchanged in \texttt{left\_branch} and for its
derivative, so \texttt{r2.clone()} provides the second copy. Similarly,
\texttt{r1} is borrowed by \texttt{nullable\_bc} before being consumed.

The \texttt{Star} arm follows the same pattern. Its body is needed both for
the derivative and the reconstructed star, so \texttt{r.clone()} provides
the second copy. So both clones correspond to duplicated subexpressions
in the corresponding derivative rules.

\subsection{Internalizing Expressions}
\label{sec:internalize}

$\mathit{internalize}$ recursively converts a plain expression $r$ into an
annotated expression $\mathit{ri}$. All nodes receive an empty bit-list
except the two branches of an alternation, which are tagged with
$0{=}\mathit{Left}$ and $1{=}\mathit{Right}$:
\begin{equation}\label{eq:internalize}
\begin{aligned}
\mathit{internalize}(\emptyset) &= \emptyset \\
\mathit{internalize}(\varepsilon) &= [\,]@\varepsilon \\
\mathit{internalize}(x) &= [\,]@x \\
\mathit{internalize}(r_1+r_2) &=
  [\,]@\big(\mathit{fuse}([0],\mathit{internalize}(r_1))
  \oplus \mathit{fuse}([1],\mathit{internalize}(r_2))\big) \\
\mathit{internalize}(r_1\,r_2) &=
  [\,]@\big(\mathit{internalize}(r_1)\,\mathit{internalize}(r_2)\big) \\
\mathit{internalize}(r^{*}) &= [\,]@\mathit{internalize}(r)^{*}.
\end{aligned}
\end{equation}

The $[0]$/$[1]$ tags on the two sides of $r_1+r_2$ follow the
$0{=}\mathit{Left}/1{=}\mathit{Right}$ convention. Every other case
introduces no new bit and uses only the empty list $[\,]$. The two
calls to $\mathit{fuse}$ in ~\eqref{eq:internalize} are the only
points in the construction where new bits are introduced.

%

\paragraph{In Rust.}
\label{sec:internalize-impl}

Figure~\ref{fig:internalize-rust} directly maps the constructors of
\texttt{Regex} to their annotated counterparts.
Each recursive call applies \texttt{internalize} to the corresponding
subexpression, preserving the structure of the original expression in
the annotated representation.

\begin{figure}[H]
\small
\begin{verbatim}
pub fn internalize(r: &Regex) -> ARegex {
    match r {
        Regex::Phi => ARegex::Phi,
        Regex::Eps => ARegex::Eps(vec![]),
        Regex::Lit(c) => ARegex::Lit(vec![], *c),
        Regex::Alt(r1, r2) => {
            let ri1 = fuse(&[false], internalize(r1));
            let ri2 = fuse(&[true], internalize(r2));
            ARegex::Alt(vec![], Box::new(ri1), Box::new(ri2))
        }
        Regex::Seq(r1, r2) => ARegex::Seq(vec![],
            Box::new(internalize(r1)), Box::new(internalize(r2))),
        Regex::Star(r1) => ARegex::Star(vec![], Box::new(internalize(r1))),
    }
}
\end{verbatim}
\caption{\texttt{internalize}: convert a \texttt{Regex} into an
\texttt{ARegex}.}
\label{fig:internalize-rust}
\end{figure}

The \texttt{Alt} case calls \texttt{fuse} with a non-empty bit-list,
tagging the left operand with \texttt{[false]} and the right with
\texttt{[true]} before wrapping them in a fresh \texttt{Alt} with an empty
outer bit-list. These are the only points where new bits are introduced.
All later bits originate from these two tags and are propagated during
derivation.

The \texttt{Phi}, \texttt{Eps}, \texttt{Lit}, \texttt{Seq}, and
\texttt{Star} cases use an empty bit-list, since they introduce no
disambiguation choice at this stage. Star iteration choices are instead
determined during derivative computation by $\mathsf{B}_{*}$.

\subsection{Decoding Bits}
\label{sec:decode}

$\mathit{decode}_r$ reconstructs a \texttt{ParseTree} from the bit-string
produced by $\mathit{mkEpsBC}$, by calling a recursive worker
$\mathit{decodeInner}$ that traverses the original, unannotated $r$ (since
the annotated expression has by now been reduced to bits) and threads the
remaining bit-list through its structure:
\begin{equation}\label{eq:decode}
\begin{aligned}
\mathit{decode}_r(bs) &= v \\
  &\text{if } \mathit{decodeInner}_r(bs)=(v,[\,]) \\[0.8em]
\mathit{decodeInner}_{\varepsilon}(bs)
  &= (\mathit{Empty},bs) \\
\mathit{decodeInner}_{x}(bs)
  &= (\mathit{Char}(x),bs) \\
\mathit{decodeInner}_{r_1+r_2}(0{:}bs)
  &= \bigl(\mathit{Left}(v),bs_1\bigr) \\
  &\text{if } \mathit{decodeInner}_{r_1}(bs)=(v,bs_1) \\
\mathit{decodeInner}_{r_1+r_2}(1{:}bs)
  &= \bigl(\mathit{Right}(v),bs_1\bigr) \\
  &\text{if } \mathit{decodeInner}_{r_2}(bs)=(v,bs_1) \\
\mathit{decodeInner}_{r_1r_2}(bs)
  &= \bigl(\mathit{Pair}(v_1,v_2),bs_2\bigr) \\
  &\text{if } \mathit{decodeInner}_{r_1}(bs)=(v_1,bs_1),\;
     \mathit{decodeInner}_{r_2}(bs_1)=(v_2,bs_2) \\
\mathit{decodeInner}_{r^{*}}(1{:}bs)
  &= (\mathit{Star}([\,]),bs) \\
\mathit{decodeInner}_{r^{*}}(0{:}bs)
  &= \bigl(\mathit{Star}(v{:}vs),bs_2\bigr) \\
  &\text{if } \mathit{decodeInner}_{r}(bs)=(v,bs_1),\;
     \mathit{decodeInner}_{r^{*}}(bs_1)=(\mathit{Star}(vs),bs_2)
\end{aligned}
\end{equation}

$\mathit{decode}_r$ is undefined if bits remain once $\mathit{decodeInner}$
returns. The $\mathit{Alt}$ case reads the $0{=}\mathit{Left}/1{=}\mathit{Right}$
tags introduced by $\mathit{internalize}$. The $\mathit{Star}$ case consumes
one $0$ per iteration until the trailing $1$ inserted by
$\mathit{mkEpsBC}$ terminates the sequence.

%

\paragraph{In Rust.}

Figure~\ref{fig:decode-rust} is \texttt{decode} and the \texttt{Alt} arm
of its recursive worker \texttt{decode\_inner}, which returns
\texttt{(ParseTree, \&[bool])}, the tree for the current subexpression
together with whatever bits remain; Rust's slice patterns make the
leading-bit test direct, \texttt{[false, rest @ ..]}/\texttt{[true, rest
@ ..]} both checking the bit and naming the remainder in one pattern.
\texttt{Seq} and \texttt{Star} thread bits the same way, omitted here:
\texttt{Seq} recurses once per factor, \texttt{Star} loops since its
iteration count isn't known until the bits say so, both reusing the
identical slice-pattern test the \texttt{Alt} arm shows below.
\texttt{decode}'s \texttt{assert!} enforces Equation~\eqref{eq:decode}'s
side condition, that no bits remain once decoding finishes.

\begin{figure}[H]
\small
\begin{verbatim}
pub fn decode(r: &Regex, bs: &[bool]) -> ParseTree {
    let (v, rest) = decode_inner(r, bs);
    assert!(rest.is_empty(),
        "decode: {} leftover bit(s) after decoding {:?}", rest.len(), r);
    v
}

fn decode_inner<'a>(r: &Regex, bs: &'a [bool]) -> (ParseTree, &'a [bool]) {
    match r {
        // Eps, Lit, Seq, Star: one direct recursive case each,
        // threading the remaining bits the same way; omitted here.
        Regex::Alt(r1, r2) => match bs {
            [false, rest @ ..] => {
                let (v, remaining) = decode_inner(r1, rest);
                (ParseTree::Left(Box::new(v)), remaining)
            }
            [true, rest @ ..] => {
                let (v, remaining) = decode_inner(r2, rest);
                (ParseTree::Right(Box::new(v)), remaining)
            }
            [] => panic!("decode: unexpected end of bits at Alt"),
        },
        // Phi: unreachable, decode never runs against a failed match
    }
}
\end{verbatim}

the other arms are one direct recursive case apiece, described in the

\end{figure}

\subsection{Simplification}
\label{sec:simplification-rules-theory}

Unlike the direct construction the
bit-coded method must simplify: Sulzmann and Lu show that $a^{*}$ doubles
in size at every derivative step without simplification. Simplification is
safe here because the information required for reconstruction is encoded in
the bits rather than in the unsimplified expression. The function
$\mathit{simp}$ is applied after every derivative step.

\paragraph{Sequence and star.}
The local simplification rules handle sequences and stars. A sequence
propagates $\emptyset$, eliminates a leading $\varepsilon$ while preserving
its bits with $\mathit{fuse}$, and otherwise retains its structure. A star
simplifies only its body:


{\small
\begin{equation}\label{eq:simp}
\begin{aligned}
\mathit{simp}(\emptyset) &= \emptyset \\
\mathit{simp}((bs@\varepsilon)) &= (bs@\varepsilon) \\
\mathit{simp}((bs@x)) &= (bs@x) \\[2pt]
\mathit{simp}((bs@\mathit{ri}_1\,\mathit{ri}_2)) &=
  \begin{cases}
    \emptyset
      & \mathit{isPhi}(\mathit{simp}(\mathit{ri}_1)) \lor \mathit{isPhi}(\mathit{simp}(\mathit{ri}_2)) \\
    \mathit{fuse}(bs\mathbin{+\!\!+} bs_1,\mathit{simp}(\mathit{ri}_2))
      & \mathit{simp}(\mathit{ri}_1) = (bs_1@\varepsilon) \\
    (bs@\mathit{simp}(\mathit{ri}_1)\,\mathit{simp}(\mathit{ri}_2)) & \text{otherwise}
  \end{cases}\\[4pt]
\mathit{simp}((bs@\mathit{ri}_1\oplus\mathit{ri}_2)) &=
  \mathit{fuse}(bs,\ \mathit{prune}(\mathit{flatten}(\mathit{ri}_1,\mathit{ri}_2)))\\[2pt]
\mathit{simp}((bs@\mathit{ri}^{*})) &= (bs@\mathit{simp}(\mathit{ri})^{*})
\end{aligned}
\end{equation}
}

The first case propagates the empty language through a sequence, while the
second removes a leading $\varepsilon$ and transfers its bits to the
remaining expression. The $\mathit{isPhi}$ test also recognizes expressions
equivalent to $\emptyset$ beyond the literal $\emptyset$.

\paragraph{Alternation.}
Alternation requires additional restructuring. $\mathit{flatten}$ collects
nested alternatives that carry no bit-tag of their own into a single branch
list. When descending through a tagged alternative, it first fuses its bits
into both branches so that no recorded choice is lost. $\mathit{prune}$
then simplifies each branch, removes branches equivalent to $\emptyset$,
and removes duplicate annotated expressions while retaining the first
occurrence. Finally, $\mathit{collapse}$ rebuilds the remaining branches
and applies the outer $bs$ once:

\begin{equation}\label{eq:simp-alt}
\mathit{simp}(bs@(r_1\oplus r_2))
  =
  \mathit{fuse}\bigl(bs,\,
    \mathit{prune}(\mathit{flatten}(r_1,r_2))\bigr).
\end{equation}

The pruning step compares complete annotated expressions, including
their bit-lists, so branches with identical underlying expressions but
different annotations remain distinct, since they represent different
reconstruction choices; simplification therefore does not merge on
shape alone, and does not guarantee bounded expression growth in every
case. If no branch survives, $\mathit{collapse}$ produces $\emptyset$;
with one survivor it returns that expression, otherwise it rebuilds an
alternation.

\subsection{Parser}
\label{sec:deriv-bc-driver}

Figure~\ref{fig:deriv-bc-loop-rust} implements the bit-coded driver.
It internalizes $r$, applies \texttt{deriv\_bc} and \texttt{simp} to each
input character, checks nullability and, if successful, calls
\texttt{mk\_eps\_bc} and \texttt{decode}.

\begin{figure}[H]
\small
\begin{verbatim}
pub fn parse_bitcoded_loop(input: &str, r: &Regex) -> Option<ParseTree> {
    let mut ri = internalize(r);
    for l in input.chars() { ri = simp(deriv_bc(ri, l)); }
    if !nullable_bc(&ri) { return None; }
    Some(decode(r, &mk_eps_bc(&ri)))
}
\end{verbatim}
\caption{\texttt{parse\_bitcoded\_loop}: the bit-coded parser implementation.}
\label{fig:deriv-bc-loop-rust}
\end{figure}

Unlike the direct implementation, which has a growing
\texttt{Vec<Regex>} for backward reconstruction, the bit-coded implementation
needs only the current \texttt{ri}. The recursive entry point has the same
three-step computation but differs only in how intermediate expressions
are stored.

\subsection{Worked Example: Ambigious Expression}
\label{sec:deriv-bc-worked}

Consider the same input $\texttt{ab}$ and regular expression $r_0=(a\mid ab)(b\mid\varepsilon)$.

%

\paragraph{Internalize.}
Before consuming input, $\mathit{internalize}$ tags each alternative with $[0]$ for the left 
branch and $[1]$ for the right branch:

\begin{equation}\label{eq:dpbc-internalize}
\mathit{internalize}(r_0) = \mathit{ri}_0 =
[\,]@\big(
  [\,]@([0]@a \oplus [1]@(a\,b))
  \cdot
  [\,]@([0]@b \oplus [1]@\varepsilon)
\big).
\end{equation}

%

\paragraph{Forward pass.}
The two input symbols are consumed by successive bit-threaded derivatives with $\mathit{simp}$ 
applied after each step. The first derivative uses $\mathsf{B}_{\mathrm{seq}}$. After consuming $\mathtt{a}$, 
the first factor becomes nullable, so the second derivative uses $\mathsf{B}_{\mathrm{seq}}^{\,n}$, 
which propagates bits from the empty match of the first factor into the derivative of the second:

\begin{equation}\label{eq:dpbc-forward}
\begin{aligned}
\mathit{ri}_0
  &\xrightarrow[\mathsf{B}_{\mathrm{seq}}]{\ a\ }
  \mathit{ri}_1 =
  [\,]@\big(
    [\,]@([0]@\varepsilon \oplus [1]@b)
    \cdot
    [\,]@([0]@b \oplus [1]@\varepsilon)
  \big) \\
\mathit{ri}_1
  &\xrightarrow[\mathsf{B}_{\mathrm{seq}}^{\,n}]{\ b\ }
  \mathit{ri}_2 =
  [\,]@\big(
    [1]@([0]@b \oplus [1]@\varepsilon)
    \oplus
    [0,0]@\varepsilon
  \big).
\end{aligned}
\end{equation}

The $[1]$ records the right alternative $ab$ of the first factor. The $[0,0]$ on the second 
branch results from fusing bits during the derivative. Unlike the direct construction, where 
$\mathit{inj}$ recovers this information later, the bit-coded method propagates it during 
the forward pass.

%

\paragraph{Extracting and decoding the bits.}
Both disjuncts of $\mathit{ri}_2$ are nullable, so $\mathit{mkEpsBC}$ applies the left-preference 
rule and selects the left disjunct. Inside, $b$ is not nullable while $\varepsilon$ is, so 
$\mathsf{EB}_{+}^{R}$ contributes its $[1]$ tag:

\begin{equation}\label{eq:dpbc-mkepsbc}
\mathit{mkEpsBC}(\mathit{ri}_2)
  \xrightarrow{\mathsf{EB}_{+}^{L}}
  \mathit{mkEpsBC}\big(
    [1]@([0]@b \oplus [1]@\varepsilon)
  \big)
  \xrightarrow{\mathsf{EB}_{+}^{R}}
  [1,1].
\end{equation}

Unlike $\mathit{mkEps}$, which constructs a partial parse tree, $\mathit{mkEpsBC}$ extracts 
only the committed choices as a bit-string. The decoder then interprets $[1,1]$ against the 
original $r_0$: the first bit selects the right branch of $a+ab$ (producing $ab$), and the 
second selects the right branch of $b+\varepsilon$:

\begin{equation}\label{eq:dpbc-decode}
\mathit{decode}_{r_0}([1,1])
  = \big(
      \mathit{Right}(a,b),
      \mathit{Right}(\,)
    \big)
  = v_0.
\end{equation}

Flattening validates the result:
\begin{equation}\label{eq:dpbc-flatten}
\mathit{flatten}(v_0) = a \cdot b \cdot \varepsilon = \mathtt{ab}.
\end{equation}

The bit-coded construction produces the same parse tree as the direct construction but stores 
only the final annotated expression $\mathit{ri}_2$, not the intermediate expressions $r_0$ 
and $r_1$.
