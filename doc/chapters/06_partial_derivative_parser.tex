\chapter{Partial-Derivative-Based Parser}
\label{sec:partial-derivative-parser}

Chapter~\ref{sec:derivative-parser} built two parsers on Brzozowski's
derivative $r\backslash x$, which names one expression: parsing there
follows a single thread, one expression after another, deterministic
the way a DFA is. This chapter builds the same two kinds of parser
again, using Antimirov's partial derivative $pd(r,x)$ from
Section~\ref{sec:antimirov-partial-derivatives} in place of
$r\backslash x$. $pd(r,x)$ does not return one expression; it returns
the \emph{set} of states of the implicit NFA for $r$ that a transition
on $x$ reaches. Stepping $pd$ across a whole input therefore does not
follow a single thread: it tracks a whole set of live NFA states at
once, one character at a time, the same subset-simulation idea a
textbook NFA-to-DFA construction uses to decide membership, except
nothing is precomputed into a DFA table here; the set is recomputed
directly at every character.

The substitution is not free for parsing specifically. $r\backslash
x$'s single expression lets a rule prefer its left branch when
reconstructing a value; $pd(r,x)$'s set has no distinguished branch to
prefer, so the POSIX choice $\mathit{mkEps}$ and $\mathit{mkEpsBC}$
made in Chapter~\ref{sec:derivative-parser} has no obvious site to
attach to in the set representation. Both parsers built here instead
keep every live state around in parallel, each carrying whatever
reconstruction information it individually needs, and resolve the
choice only once, by list order, once the input runs out.

\section{The Standard Partial-Derivative-Based Parser}
\label{sec:pderiv-std-theory-rust}

Knowing which NFA states are alive is enough to decide whether $w\in
L(r)$ (Section~\ref{sec:antimirov-partial-derivatives}), but parsing
needs more: once the input ends, whichever surviving state is
nullable must be turned back into a parse tree for the
\emph{original} expression $r$, not just for its own local residual.
In Chapter~\ref{sec:derivative-parser}'s single-threaded setting this
was $\mathit{inj}$'s job, walking the one stored sequence of
expressions backward, from the final residual to $r$. There is no
single sequence to walk here: many states are alive at once, each
reached by a different path through $r$'s alternations and sequences,
and a state that died two steps ago is simply gone from the set that
replaced it, with no stored history to walk back through. Each
surviving state must therefore carry its own reconstruction recipe
with it as it goes, rather than relying on a shared trail left behind
it.

This construction attaches exactly that recipe to every state, as a
function called an \emph{injection closure}: given the parse tree for
the state's own residual, it returns the parse tree for the whole
original $r$. The construction starts with one state, $r$ itself,
carrying the identity closure, since at that point the state's
residual \emph{is} $r$ and nothing needs reconstructing yet. Each
character replaces the whole state set with $pd$ applied to every
member, and every successor's closure is built by composing that
step's own local reconstruction step inside the closure it inherited
from its parent, so the composition grows by one layer per character
without ever being evaluated. Once the input is exhausted, the first
state with a nullable residual, in list order, is selected, and its
closure, applied to $\mathit{mkEps}$ of that residual, is the parse
tree.

\paragraph{Terminology.} This section calls an element of $pd(r,x)$ a
\emph{state} and the working collection of them the \emph{state set},
following the automata reading above rather than any
expression-specific vocabulary. The implementation's own names for
this collection, \texttt{frontier} and \texttt{step\_frontier}
(Section~\ref{sec:pderiv-std-driver}), refer to the identical thing;
this chapter says state set throughout, but the two names are
interchangeable.

Consider the unambiguous example from Section~\ref{par:unambigious-example}:
$r = a\cdot b$ with input $w=\mathtt{ab}$, checked against
\texttt{--parser pderiv\_std --diag 3}. A single state survives at every
step, so the forward pass is visible without any competition between
states:
\begin{equation}\label{eq:pderiv-std-overview-example}
\{(a\cdot b,\ \mathrm{id})\}
\ \xrightarrow{\ a\ }\
\{(\varepsilon\cdot b,\ \kappa_1)\}
\ \xrightarrow{\ b\ }\
\{(\varepsilon,\ \kappa_2)\},
\end{equation}
shown in Figure~\ref{fig:pderiv-std-single-pass}. A mismatched literal
under Brzozowski's derivative keeps $\phi$ as a residual, so the matcher
discovers failure only once it reaches the end; a mismatched literal
under $pd$ contributes no successor at all, so a dead state simply
disappears from the set rather than surviving as $\phi$.

\paragraph{Single pass, not two.} Both closures are fully determined as
soon as they are built: $\kappa_1$ already carries the tree for the
\texttt{a} it just matched, and $\kappa_2$ extends that with the tree for
\texttt{b}. Nothing is deferred, so there is no separate backward walk:
the construction ends by evaluating $\kappa_2$ once, on
$\mathit{mkEps}(\varepsilon)=()$, giving $\kappa_2(()) = (a,b)$, matching
the trace above. Section~\ref{sec:pderiv-std-worked} repeats this on the
ambiguous $r_0=(a+ab)(b+\varepsilon)$ from
Section~\ref{par:ambigious-example}, where more than one state survives a
step and list order, not the closure, does the choosing.

No rule anywhere prefers one state over another during this process:
a parse tree is complete only once the whole input has been read, so
there is nothing to compare while stepping. Two states can both be
nullable at the end; only the first, in the order this section's
rules produce, is ever inspected.

\emph{No published construction corresponds to this one.} Sulzmann's
teaching-page Haskell transcript \citep{sulzmann_slides} defines a
bit-coded partial-derivative parser directly (Section~\ref{sec:pderiv-bc-theory}
follows it literally), but not a tree-building one; this
injection-closure construction is this project's own extension of
$pd$, built to give the bit-coded parser below a matched,
independently-implemented counterpart the way \texttt{deriv\_std} is
to \texttt{deriv\_bc} in Chapter~\ref{sec:derivative-parser}. Every
rule and every Rust listing in this section was checked directly
against \texttt{src/parsers/pderiv\_std/} and against a live
\texttt{--diag 3} trace before being written here, since no reference
implementation exists to check it against instead.

\subsection{Injection Closures}
\label{sec:pderiv-std-strand-theory}

A state's closure accumulates the same way $\mathit{inj}$'s effect
does in Chapter~\ref{sec:derivative-parser}, one layer per character,
except that nothing is applied until the very end: where
\texttt{deriv\_std} runs an explicit backward pass, calling
\texttt{inject} once per character after the input is exhausted, this
construction builds the composition forward, one layer per step, and
applies the finished composition exactly once. In that sense it is as
single-pass as \texttt{deriv\_bc}: the closure chain plays the role
the bit-string plays there.

\paragraph{In Rust.}
\label{sec:inj-type-impl}

Figure~\ref{fig:inj-type-rust} is the closure's type, the identity
closure the construction starts with, and its deduplication helper.

\begin{figure}[H]
\small
\begin{verbatim}
pub(crate) type Inj = Rc<dyn Fn(ParseTree) -> ParseTree>;

pub(crate) fn identity_inj() -> Inj {
    Rc::new(|v| v)
}

pub(crate) fn nub_tree(strands: Vec<(Regex, Inj)>) -> Vec<(Regex, Inj)> {
    let mut seen: HashSet<Regex> = HashSet::with_capacity(strands.len());
    let mut out = Vec::with_capacity(strands.len());
    for (r, inj) in strands {
        if seen.insert(r.clone()) {
            out.push((r, inj));
        }
    }
    out
}
\end{verbatim}
\caption{\texttt{Inj}, its identity value, and \texttt{nub\_tree}:
stable deduplication on the residual alone, keeping the first
occurrence.}
\label{fig:inj-type-rust}
\end{figure}

\texttt{Rc<dyn Fn(ParseTree) -> ParseTree>} is a reference-counted,
heap-allocated closure: a single step can expand one state into
several, and every successor needs the same parent closure, so the
parent has to be shared rather than cloned or moved. Cloning an
\texttt{Rc} bumps a reference count; it does not copy whatever state
the closure captured.

\subsection{The Partial Derivative with Injection}
\label{sec:pderiv-tree-theory}

Writing $D^{T}_r$ for this construction's step at a fixed character
$x$, its case structure matches $pd$'s own
(Section~\ref{sec:antimirov-partial-derivatives}) with a closure
attached to every surviving element instead of nothing:
\begin{equation}\label{eq:pd-tree}
\begin{aligned}
D^{T}_{\varepsilon} &= \{\} \qquad D^{T}_{\emptyset} = \{\} \\
D^{T}_{y} &= \begin{cases}
  \{(\varepsilon,\ \_\mapsto \mathit{Char}(y))\} & x = y \\
  \{\} & x \neq y
\end{cases} \\
D^{T}_{r+s} &= \mathit{nub}_T\big(
  \{(r',\ v\mapsto\mathit{Left}(f(v))) \mid (r',f)\in D^{T}_r\} \\
  &\qquad\qquad \cup\ \{(s',\ v\mapsto\mathit{Right}(g(v))) \mid (s',g)\in D^{T}_s\}\big) \\
D^{T}_{r^{*}} &= \mathit{nub}_T\big(
  \{(r'\,r^{*},\ (v,vs)\mapsto \mathit{Star}(f(v){:}vs)) \mid (r',f)\in D^{T}_r\}\big)
\end{aligned}
\end{equation}
and the sequence case again splits on the nullability of the left
factor:
\begin{equation}\label{eq:pd-tree-seq}
\begin{aligned}
D^{T}_{rs} &= \{(r's,\ (v_1,v_2)\mapsto(f(v_1),v_2)) \mid (r',f)\in D^{T}_r\}
  && n(r) = \mathrm{false} \\
D^{T}_{rs} &= \mathit{nub}_T\big(
  \{(r's,\ (v_1,v_2)\mapsto(f(v_1),v_2)) \mid (r',f)\in D^{T}_r\} \\
  &\qquad\quad \cup\ \{(s',\ v_2\mapsto(\mathit{mkEps}_r,\,g(v_2))) \mid (s',g)\in D^{T}_s\}\big)
  && n(r) = \mathrm{true}
\end{aligned}
\end{equation}

Each case answers the same question $pd$'s own cases answer, which
successor states exist, and additionally says how to rebuild a value
for $r$ from a value for that successor. $D^{T}_y$ is where a value
first appears: on a match, the one successor state $\varepsilon$
carries a closure that ignores whatever it is eventually given and
returns $\mathit{Char}(y)$ directly, since there is nothing left to
reconstruct below a matched literal. $D^{T}_{r+s}$ keeps both
operands' states alive side by side, wrapping each one's closure in
an outer $\mathit{Left}$ or $\mathit{Right}$ tag: the tag is written
into the closure the moment the state is created, not decided later,
so by the time a state is selected its path through the alternation
is already fixed. $D^{T}_{r^{*}}$ takes every successor of the star's
body and prepends the reconstructed iteration onto whatever
iterations the rest of the star eventually produces, which is exactly
what running the body once more inside the same star means.

The sequence case is where a state can come from either operand.
When $r$ is not nullable, only $r$ can currently be mid-match, so
every successor is $r$'s own, each rewrapped into a sequence with $s$
untouched. When $r$ is nullable, a second possibility opens: the
character just read may belong to $s$ instead, immediately after $r$
matched the empty word. The nullable case's union reflects exactly
this: one strand continues into $r$ as before, and a second strand
jumps straight into $s$'s own successors. A state on the jump strand
never has a closure for $r$'s half of the pair, since no future step
will visit $r$ again to produce one, so its closure supplies
$\mathit{mkEps}_r$ for that half directly, the same role
$\mathit{mkEps}$ plays for the skipped operand in
Chapter~\ref{sec:derivative-parser}'s own $\mathsf{I}_{\mathrm{seq}}^R$
rule.

The $r^{*}$ and $rs,\ n(r){=}\mathrm{false}$ cases both build their
residual with a plain sequence, $r'\,r^{*}$ or $r's$, never the smart
constructor $\mathit{smartC}$
(Section~\ref{sec:antimirov-partial-derivatives}) that collapses
$\varepsilon\cdot s$ to $s$. This is not an oversight: selection ends
by calling $f(\mathit{mkEps}(r))$ on the winning state, so every
closure is applied to a tree whose \emph{shape is fixed by its own
residual}. A closure built for a sequence residual pattern-matches on
a pair, exactly what $\mathit{mkEps}$ produces for a sequence;
collapsing $\varepsilon\cdot s$ to $s$ would make $\mathit{mkEps}$
produce $s$'s own shape instead, and the closure expecting a pair
would receive something else. Substituting the smart constructor here
makes the test suite fail immediately, on the simplest sequence
pattern, with exactly that mismatch.

\paragraph{In Rust.}
\label{sec:pderiv-tree-impl}

Figure~\ref{fig:pderiv-tree-rust} is the \texttt{Alt} and \texttt{Seq}
arms of \texttt{pderiv\_tree}; \texttt{Star} follows the same shape as
\texttt{Seq}'s continue branch, prepending its injected value onto the
existing \texttt{Star} list instead of pairing it, and is omitted.

\begin{figure}[H]
\small
\begin{verbatim}
Regex::Alt(r1, r2) => {
    let mut out: Vec<(Regex, Inj)> = pderiv_tree(r1, x)
        .into_iter()
        .map(|(r1_, inj1)| {
            let f: Inj = Rc::new(move |v| ParseTree::Left(Box::new(inj1(v))));
            (r1_, f)
        })
        .collect();
    out.extend(pderiv_tree(r2, x).into_iter().map(|(r2_, inj2)| {
        let f: Inj = Rc::new(move |v| ParseTree::Right(Box::new(inj2(v))));
        (r2_, f)
    }));
    nub_tree(out)
}

Regex::Seq(r1, r2) => {
    if nullable(r1) {
        let mut out: Vec<(Regex, Inj)> = pderiv_tree(r1, x)
            .into_iter()
            .map(|(r1_, inj1)| {
                let r2c = (**r2).clone();
                let f: Inj = Rc::new(move |v: ParseTree| match v {
                    ParseTree::Pair(v1, v2) =>
                        ParseTree::Pair(Box::new(inj1(*v1)), v2),
                    other => panic!("expected Pair, got {:?}", other),
                });
                (Regex::seq(r1_, r2c), f)
            })
            .collect();
        let v1_eps = mk_eps(r1);
        out.extend(pderiv_tree(r2, x).into_iter().map(|(r2_, inj2)| {
            let v1c = v1_eps.clone();
            let f: Inj = Rc::new(move |v2: ParseTree| {
                ParseTree::Pair(Box::new(v1c.clone()), Box::new(inj2(v2)))
            });
            (r2_, f)
        }));
        nub_tree(out)
    } else {
        pderiv_tree(r1, x)
            .into_iter()
            .map(|(r1_, inj1)| {
                let r2c = (**r2).clone();
                let f: Inj = Rc::new(move |v: ParseTree| match v {
                    ParseTree::Pair(v1, v2) =>
                        ParseTree::Pair(Box::new(inj1(*v1)), v2),
                    other => panic!("expected Pair, got {:?}", other),
                });
                (Regex::seq(r1_, r2c), f)
            })
            .collect()
    }
}
\end{verbatim}
\caption{The alternation and sequence arms of \texttt{pderiv\_tree},
transcribing Equations~\eqref{eq:pd-tree} and~\eqref{eq:pd-tree-seq}.}
\label{fig:pderiv-tree-rust}
\end{figure}

Both \texttt{Seq} branches build the same "continue into \texttt{r1}"
closure shape; the nullable branch additionally unions in the
"jump to \texttt{r2}" strands, each carrying a fresh
\texttt{mk\_eps(r1)} for the half the derivative skipped, the same
role $\mathit{mkEps}_r$ plays in Equation~\eqref{eq:pd-tree-seq}. Both
\texttt{mk\_eps} and \texttt{nullable} here are the exact functions
Chapter~\ref{sec:derivative-parser} defined
(Figure~\ref{fig:mkeps-rust}), imported and reused, not reimplemented.

\subsection{Parser}
\label{sec:pderiv-std-driver}

Figure~\ref{fig:pderiv-std-driver-rust} is the driver: start with one
state carrying the identity closure, replace the whole state set
(the code's own \texttt{frontier}) with \texttt{pderiv\_tree}'s union
at each character, and select the first nullable residual's closure
applied to \texttt{mk\_eps} of that residual once the input ends.

\begin{figure}[H]
\small
\begin{verbatim}
pub(super) fn step_frontier(frontier: Vec<(Regex, Inj)>, x: char)
    -> Vec<(Regex, Inj)>
{
    let mut out = Vec::new();
    for (r, inj_parent) in frontier {
        for (r_next, inj_step) in pderiv_tree(&r, x) {
            let parent = inj_parent.clone();
            let combined: Inj = Rc::new(move |v| parent(inj_step(v)));
            out.push((r_next, combined));
        }
    }
    out
}

pub(super) fn select(frontier: &[(Regex, Inj)]) -> Option<ParseTree> {
    for (r, inj) in frontier {
        if nullable(r) {
            return Some(inj(mk_eps(r)));
        }
    }
    None
}

pub fn parse_pderiv_std(input: &str, r: &Regex) -> Option<ParseTree> {
    let mut frontier: Vec<(Regex, Inj)> = vec![(r.clone(), identity_inj())];
    for c in input.chars() {
        frontier = step_frontier(frontier, c);
        if frontier.is_empty() { return None; }
    }
    select(&frontier)
}
\end{verbatim}
\caption{\texttt{parse\_pderiv\_std}: build the closure chain forward,
one character at a time, and apply it once, at the end.}
\label{fig:pderiv-std-driver-rust}
\end{figure}

\texttt{combined} composes \texttt{inj\_step} \emph{inside}
\texttt{parent}, \texttt{parent(inj\_step(v))}: the most recent step's
closure runs first, on the raw tree \texttt{mk\_eps} produces for the
current residual, and each earlier step's closure wraps that result
one layer further out, exactly the right-to-left order
Chapter~\ref{sec:derivative-parser}'s $\mathit{inj}$ applies during
its own backward pass, just built forward here instead of walked
backward.

\texttt{select} scans the state set in the fixed order
\texttt{step\_frontier} built it in and returns the first nullable
state it finds, the same list-order priority a hand-written
alternative-by-alternative matcher applies when more than one
alternative would otherwise match: earlier states come from earlier
alternatives or earlier iterations, so \emph{first nullable, in list
order} and \emph{leftmost alternative preferred} pick out the same
state. Nothing resembling a POSIX longest-match comparison happens
here, since \texttt{select} stops at the first match it finds and
never looks at the states after it.

\subsection{Worked Example: Ambigious Expression}
\label{sec:pderiv-std-worked}

Recall the ambigious example from Section~\ref{par:ambigious-example}
with regular expression $r_0=(a+ab)(b+\varepsilon)$ against input
$\mathtt{ab}$, checked against \texttt{--parser pderiv\_std --diag 3}.

\paragraph{Step 1.} $a+ab$ is not nullable, so the outer sequence
takes its non-nullable case: every state below comes from stepping
$a+ab$ alone, each wrapped back into a sequence with $b+\varepsilon$
untouched:
\begin{equation}\label{eq:pt-step1}
\{(r_0,\ \mathrm{id})\}
\ \xrightarrow{\ a\ }\
\big\{
  \big(\varepsilon\,(b+\varepsilon),\ f_0\big),\ \
  \big((\varepsilon\, b)\,(b+\varepsilon),\ f_1\big)
\big\}
\end{equation}
Both states survive $\mathit{nub}_T$, since $\varepsilon(b+\varepsilon)$
and $(\varepsilon b)(b+\varepsilon)$ are syntactically distinct
residuals; the tool's own trace lists exactly these two, printed as
\texttt{Seq(Eps, Alt(Lit('b'), Eps))} and
\texttt{Seq(Seq(Eps, Lit('b')), Alt(Lit('b'), Eps))}.

\paragraph{Step 2.} The two states are stepped independently, and
different rules fire on each. The first state's left factor
$\varepsilon$ is nullable, so it takes the nullable sequence case;
its own left factor contributes no successor ($\varepsilon$ has none),
so only the jump into $b+\varepsilon$ survives. The second state's
left factor $\varepsilon\,b$ is not nullable, so it takes the plain
case again:
\begin{equation}\label{eq:pt-step2}
\big\{
  \big(\varepsilon(b+\varepsilon),\ f_0\big),\ \big((\varepsilon b)(b+\varepsilon),\ f_1\big)
\big\}
\ \xrightarrow{\ b\ }\
\big\{
  (\varepsilon,\ g_0),\ \ \big(\varepsilon(b+\varepsilon),\ g_1\big)
\big\}
\end{equation}
matching the tool's \texttt{Eps} and
\texttt{Seq(Eps, Alt(Lit('b'), Eps))}.

\paragraph{Selection and result.} Both residuals are nullable;
$\varepsilon$, first in list order, is selected. Its closure applied
to $\mathit{mkEps}(\varepsilon) = ()$ threads back through every layer
built above it:
\begin{equation}\label{eq:pt-result}
g_0(()) = \big(\mathit{Left}\ a,\ \mathit{Left}\ b\big) = v_0,
\qquad \lvert v_0\rvert = \mathtt{ab}.
\end{equation}
This is a different tree from the POSIX one
Section~\ref{sec:worked-example} builds for the identical
$r_0$ and $\mathtt{ab}$, $\big(\mathit{Right}(a,b),\mathit{Right}(\,)\big)$:
here the leftmost alternative of $a+ab$ is committed to as soon as it
is available, rather than the longest one being preferred once the
whole match is known. Both are valid parse trees for the same
expression and word (Section~\ref{sec:parse-trees-as-evidence}); which
one a parser returns depends on which of the two constructions built
it.

\section{The Bit-Coded Partial-Derivative-Based Parser}
\label{sec:pderiv-bc-theory}

Sulzmann's teaching-page Haskell transcript gives a bit-coded
partial-derivative construction, \texttt{pDerivBC}
\citep{sulzmann_slides}, that this project's \texttt{pderiv\_bc}
follows directly. It extends $pd$ with per-state bits the same way
Chapter~\ref{sec:derivative-parser}'s $\backslash_b$ extends the
Brzozowski derivative, with one visible difference: the bits stay
\emph{external} to the expression, a plain list carried alongside a
plain, un-annotated $r$, rather than folded into an
\texttt{ARegex}-shaped tree. This construction's correctness
criterion is literal agreement with \texttt{pDerivBC}, not an
independently derived ideal form, so where the reference keeps an
asymmetry, this section keeps it too rather than smoothing it away.

Figure~\ref{fig:pderiv-bc-single-pass} shows this on the same
unambiguous example Section~\ref{sec:pderiv-std-theory-rust}'s own
overview used, $r=a\cdot b$ against \texttt{"ab"}, checked against
\texttt{--parser pderiv\_bc --diag 3}. $a\cdot b$ is unambiguous, so no
$\mathsf{PB}_{+}$ or $\mathsf{PB}_{*}$ rule ever fires and the bit list
carried alongside the state stays empty throughout; what changes at
each step is the state itself, as $\mathit{smartC}$ strips the factor
just matched away.

\subsection{The Bit-Coded Partial Derivative}
\label{sec:pderivbc-rules-theory}

Writing $D_r$ for $\mathit{pDerivBC}(x,r)$, the base and non-sequence
cases are
\begin{equation}\label{eq:pderivbc}
\begin{aligned}
D_{\varepsilon} &= \{\} \qquad D_{\emptyset} = \{\} \\
D_{y} &= \begin{cases} \{(\varepsilon, [\,])\} & x = y \\
                       \{\} & x \neq y \end{cases} \\
D_{r+s} &= \mathit{nub2}\big(
  \{(r', 0{:}bs) \mid (r',bs) \in D_r\}
  \cup \{(s', 1{:}bs) \mid (s',bs) \in D_s\}\big) \\
D_{r^{*}} &= \mathit{nub2}\big(
  \{(\mathit{smartC}(r', r^{*}),\, 0{:}bs) \mid (r',bs) \in D_r\}\big)
\end{aligned}
\end{equation}
and the sequence case splits on the nullability of the left factor,
exactly as in Chapter~\ref{sec:derivative-parser}:
\begin{equation}\label{eq:pderivbc-seq}
\begin{aligned}
D_{rs} &= \{(\mathit{smartC}(r',s),\, bs) \mid (r',bs) \in D_r\}
  && n(r) = \mathrm{false} \\
D_{rs} &= \mathit{nub2}\big(
  \{(r's,\ bs) \mid (r',bs) \in D_r\} \\
  &\quad \cup\ \{(s',\ \mathit{mkEpsBC}_r \mathbin{+\!\!+} bs) \mid (s',bs) \in D_s\}\big)
  && n(r) = \mathrm{true}
\end{aligned}
\end{equation}
Here $\mathit{mkEpsBC}_r$ is the plain-$r$ analogue of
Chapter~\ref{sec:derivative-parser}'s $\mathit{mkEpsBC}$, identical in
structure but walking an un-annotated tree; $\mathit{smartC}$ is the
smart sequence constructor collapsing $\varepsilon\cdot s$ to $s$; and
$\mathit{nub2}$ deduplicates a list of \texttt{(residual, bits)} pairs
by the residual alone, keeping the first occurrence.

Every case here has the same job as its $\mathsf{B}$-rule counterpart
in Chapter~\ref{sec:derivative-parser}
(Equation~\eqref{eq:bderiv}), just distributed over a state set
instead of folded into one annotated tree: $\mathsf{PB}_{+}$ tags each
operand's states with $0$ or $1$ the way $\mathsf{B}_{+}$ tags each
branch; $\mathsf{PB}_{\mathrm{seq}}$ and $\mathsf{PB}_{\mathrm{seq}}^{\,n}$
split on nullability the same way $\mathsf{B}_{\mathrm{seq}}$ and
$\mathsf{B}_{\mathrm{seq}}^{\,n}$ do, with the nullable case again
producing two strands; and $\mathsf{PB}_{*}$ tags one more iteration
with a leading $0$ the same way $\mathsf{B}_{*}$ does. The state and
state set terminology from Section~\ref{sec:pderiv-std-theory-rust}
carries over unchanged: an element of $D_r$ is a state, $D_r$ itself
is the next state set, and \texttt{frontier} in this section's own
code (Section~\ref{sec:pderiv-bc-driver}) names the same thing again.

Unlike Section~\ref{sec:pderiv-tree-theory}'s construction, the two
sequence cases here build their residuals differently on purpose:
$n(r){=}\mathrm{false}$ uses $\mathit{smartC}$, while
$n(r){=}\mathrm{true}$'s first branch uses a plain $r's$. That
asymmetry is present in the reference itself; since this
construction's own correctness bar is literal agreement with
\texttt{pDerivBC}, it is kept rather than corrected.

\paragraph{In Rust.}
\label{sec:pderiv-bc-impl}

Each $D_r$ becomes a \texttt{Vec<(Regex, Vec<bool>)>}, not a set,
since order is what encodes priority and a \texttt{HashSet} would
discard exactly that. Figure~\ref{fig:pderivbc-rust} is the
\texttt{Seq} arm, where the asymmetry above is visible directly in
code; \texttt{Alt} and \texttt{Star} tag their one or two successors
with a leading \texttt{false}/\texttt{true} and deduplicate with
\texttt{nub2} (Figure~\ref{fig:nub2-rust}), omitted here.

\begin{figure}[H]
\small
\begin{verbatim}
fn nub2(pairs: Vec<(Regex, Vec<bool>)>) -> Vec<(Regex, Vec<bool>)> {
    let mut seen: HashSet<Regex> = HashSet::with_capacity(pairs.len());
    let mut out = Vec::with_capacity(pairs.len());
    for (r, bs) in pairs {
        if seen.insert(r.clone()) { out.push((r, bs)); }
    }
    out
}
\end{verbatim}
\caption{\texttt{nub2}: stable deduplication on the residual alone.
The one place \texttt{Regex}'s derived \texttt{Hash} is load-bearing
in the codebase, keeping this linear rather than quadratic in the
number of states.}
\label{fig:nub2-rust}
\end{figure}

\begin{figure}[H]
\small
\begin{verbatim}
Regex::Seq(r1, r2) => {
    if nullable(r1) {
        let mut out: Vec<(Regex, Vec<bool>)> = pderiv_bc(r1, x)
            .into_iter()
            .map(|(r1_, bs)| (Regex::seq(r1_, *r2.clone()), bs))
            .collect();
        let eps_bits = mk_eps_bits(r1);
        out.extend(pderiv_bc(r2, x).into_iter().map(|(r2_, bs)| {
            let mut b = eps_bits.clone();
            b.extend(bs);
            (r2_, b)
        }));
        nub2(out)
    } else {
        pderiv_bc(r1, x)
            .into_iter()
            .map(|(r1_, bs)| (smart_seq(r1_, r2), bs))
            .collect()
    }
}
\end{verbatim}

the nullable branch's first strand uses plain \texttt{Regex::seq},

\subsection{Parser}
\label{sec:pderiv-bc-driver}

Figure~\ref{fig:pderivbc-driver-rust} is the driver, the same loop as
Section~\ref{sec:pderiv-std-driver}'s, with a \texttt{Vec<bool>}
accumulated per state instead of a closure, and
\texttt{decode} (Chapter~\ref{sec:derivative-parser},
Section~\ref{sec:decode}) reading the winning bit-string against the
\emph{original} \texttt{Regex} at the very end.

\begin{figure}[H]
\small
\begin{verbatim}
pub(super) fn step_frontier(frontier: &[(Regex, Vec<bool>)], x: char)
    -> Vec<(Regex, Vec<bool>)>
{
    let mut out = Vec::new();
    for (r, bits) in frontier {
        for (r_next, extra) in pderiv_bc(r, x) {
            let mut combined = bits.clone();
            combined.extend(extra);
            out.push((r_next, combined));
        }
    }
    out
}

pub(super) fn select_bits(frontier: &[(Regex, Vec<bool>)]) -> Option<Vec<bool>> {
    for (r, bits) in frontier {
        if nullable(r) {
            let mut result = bits.clone();
            result.extend(mk_eps_bits(r));
            return Some(result);
        }
    }
    None
}

pub fn parse_pderiv_bc(input: &str, r: &Regex) -> Option<ParseTree> {
    let mut frontier = vec![(r.clone(), Vec::new())];
    for c in input.chars() {
        frontier = step_frontier(&frontier, c);
        if frontier.is_empty() { return None; }
    }
    let bits = select_bits(&frontier)?;
    Some(decode(r, &bits))
}
\end{verbatim}
\caption{\texttt{parse\_pderiv\_bc}: accumulate bits per state instead
of composing closures; decode once, at the end, against the original
\texttt{Regex}.}
\label{fig:pderivbc-driver-rust}
\end{figure}

\subsection{Worked Example: Ambigious Expression}
\label{sec:pderiv-bc-worked}

The same $r_0=(a+ab)(b+\varepsilon)$ against $\mathtt{ab}$, checked
against \texttt{--parser pderiv\_bc --diag 3}.

\paragraph{Step 1.} $a+ab$ is not nullable, so $\mathsf{PB}_{\mathrm{seq}}$
applies with $\mathit{smartC}$ collapsing every $\varepsilon\cdot s$
residual it produces along the way:
\begin{equation}\label{eq:pdbc-step1}
\{(r_0,[\,])\}
\ \xrightarrow{\ a\ }\
\big\{\,(b+\varepsilon,\ [0]),\ \ (b\,(b+\varepsilon),\ [1])\,\big\}
\end{equation}
The $0$ and $1$ come from $\mathsf{PB}_{+}$ tagging $a+ab$'s two
alternatives one level down; $\mathit{smartC}$ collapses the first
state's $\varepsilon\cdot(b+\varepsilon)$ to $b+\varepsilon$ outright,
which is why this residual is shorter than
Section~\ref{sec:pderiv-std-worked}'s equivalent state at the same
step.

\paragraph{Step 2.} $b+\varepsilon$ takes $\mathsf{PB}_{+}$, matching
$b$ and contributing nothing for $\varepsilon$
($\mathsf{PB}_{\varepsilon}$ is empty); $b(b+\varepsilon)$'s left
factor $b$ is not nullable, so it takes $\mathsf{PB}_{\mathrm{seq}}$
again:
\begin{equation}\label{eq:pdbc-step2}
\big\{(b+\varepsilon,[0]),\ (b(b+\varepsilon),[1])\big\}
\ \xrightarrow{\ b\ }\
\big\{(\varepsilon,\ [0,0]),\ \ (b+\varepsilon,\ [1])\big\}
\end{equation}

\paragraph{Selection and result.} Both states are nullable;
$(\varepsilon,[0,0])$, first in list order, is selected, and
$\mathit{mkEpsBC}(\varepsilon)=[\,]$ contributes nothing further:
\begin{equation}\label{eq:pdbc-result}
[0,0] \mathbin{+\!\!+} [\,] = [0,0],
\qquad
\mathit{decode}_{r_0}([0,0]) = \big(\mathit{Left}\ a,\ \mathit{Left}\ b\big) = v_0,
\qquad \lvert v_0\rvert = \mathtt{ab}.
\end{equation}
This is the identical tree Section~\ref{sec:pderiv-std-worked} reached
by composing injection closures, reached here instead by reading bits
off the winning state at the very end.
