\chapter{Partial-Derivative-Based Parser}
\label{sec:partial-derivative-parser}

This chapter presents the partial-derivative approach to parse-tree construction, 
following \citep{sulzmannlu2012}. 
Unlike ordinary derivatives, partial derivatives produce a set of residual states,
each pairing an expression with the reconstruction information 
for one path through the original expression. 
The parser maintains this set as an NFA state set 
and selects the first accepting state in generation order. 

Since partial derivatives lose the original expression's structure, 
this favours leftmost alternatives over the longest match, 
resulting in non-POSIX parse trees.
As in Chapter~\ref{sec:derivative-parser}, two variants are considered. 
The standard parser attaches an injection closure to each state, 
while the bit-coded parser replaces these closures with bit sequences. 
Both produce the same parse tree.

\section{The Standard Partial-Derivative Parser}
\label{sec:pderiv-std}

Consider again $r_0 = (a + ab)(b + \varepsilon)$ with input $w = \mathtt{ab}$. 
Whereas $\mathit{deriv}$ produces a single residual at each step, 
$\mathit{pderiv}$ produces a \emph{set} of states, 
one per way the next character can be consumed.
Each state pairs a residual with an injection 
that reconstructs a parse tree of $r_0$ from one of that residual. 
Unlike $\mathit{inj}$, this injection is attached 
when the state is created rather than recovered from a stored sequence.
Figure~\ref{fig:pderiv-std-overview} shows the process.

\clearpage

Deriving $r_0$ by $\mathtt{a}$ produces the two states of $S_1$, 
one for each way $\mathtt{a}$ can be consumed:
\begin{equation}\label{eq:pderiv-std-example}
\begin{aligned}
\mathit{pderiv}(r_0, \mathtt{a}) =
  \bigl\{
    &(\;\varepsilon \cdot (b + \varepsilon),\;
       \lambda(\_, v_2).\; (\mathit{Left}\,a,\, v_2)\;), \\[2pt]
    &(\;(\varepsilon \cdot b)\,(b + \varepsilon),\;
       \lambda((v_1, v_2), v_2').\; (\mathit{Right}(a, v_2),\, v_2')\;)
  \bigr\}.
\end{aligned}
\end{equation}

A state is a pair of a residual expression describing what is left to match,
and an injection that reconstructs the original parse tree 
from a parse tree of the residual.
The two states of $S_1$ correspond to the two branches 
of $a + ab$ in the first factor. 
The second factor $b + \varepsilon$ is untouched in both 
and appears as the trailing component of each residual: $r' \cdot (b + \varepsilon)$.
The leading $\varepsilon$ in each $r'$ records  
that the consumed character matched a leading literal.

The first state's residual $\varepsilon \cdot (b + \varepsilon)$ is a sequence, 
so its tree is a pair $(v_1, v_2)$: 
$v_1$ is the tree of the leading $\varepsilon$, 
which is necessarily $\mathit{Empty}$, 
and $v_2$ is the tree of the untouched second factor $b + \varepsilon$. 
The closure returns $(\mathit{Left}(a), v_2)$. 
It discards $v_1$ because the tree of $\varepsilon$ carries no information, 
and replaces the first position with $\mathit{Left}(a)$ 
to record that the left branch of $a + ab$ was taken. 
The second factor's tree $v_2$ is passed through unchanged.

The second state's residual $(\varepsilon \cdot b)\,(b + \varepsilon)$
is a sequence whose first component is itself a sequence, 
so its tree is a pair $((v_1, v_2), v_2')$. 
The inner pair $(v_1, v_2)$ is the tree of $\varepsilon \cdot b$, 
with $v_1$ the tree of the leading $\varepsilon$ 
and $v_2$ the tree of the trailing $b$. 
The outer $v_2'$ is the tree of the untouched second factor. 
The closure returns $(\mathit{Right}(a, v_2), v_2')$. 
It rebuilds the consumed $a$ (which the leading $\varepsilon$ records) 
and the still-owed $b$ (which $v_2$ records) as the pair $(a, v_2)$.
It places that pair inside a right injection to record 
that the right branch $ab$ of the alternation was taken, 
and passes the second factor's tree $v_2'$ through unchanged. 
The binder $v_1$ is bound but not used in the body, 
as again the tree of $\varepsilon$ carries no information.

%

Transitioning both states on the second character $\mathtt{b}$ gives a new
state set:
\begin{equation}\label{eq:pderiv-std-step2}
\begin{aligned}
\mathit{pderiv}(r_0, \mathtt{a}, \mathtt{b}) =
  \bigl\{
    &(\;\varepsilon,\;
       \lambda \_.\; (\mathit{Left}\,a,\, \mathit{Left}\,b)\;), \\[2pt]
    &(\;\varepsilon \cdot (b + \varepsilon),\;
       \lambda(\_, v_2).\; (\mathit{Right}(a,b),\, v_2)\;)
  \bigr\}.
\end{aligned}
\end{equation}

The first state now has residual $\varepsilon$, 
meaning every input character has been consumed, and is accepting. 
The second has the residual $\varepsilon \cdot (b + \varepsilon)$, 
corresponding to the $ab$ branch of the first factor.
That branch consumed both characters, leaving $\varepsilon$, 
and the second factor $b + \varepsilon$ is untouched. 
So the remaining language still acceptable is $L(b + \varepsilon) = \{\varepsilon, b\}$.
The state is accepting as well, 
since $\varepsilon$ completes $\mathtt{ab}$ to a full match, 
Selection walks the whole state set in generation order 
and returns the first accepting state. 
Applying its injection to $\mathit{mkEps}_\varepsilon = ()$ 
gives $(\mathit{Left}\,a, \mathit{Left}\,b)$, 
the leftmost alternative at every choice.

Two properties of the state set determine which tree is selected. 
First, the order of states encodes the preference.
When a state produces several successors, 
they are appended in the order the rules generate them, 
with the left alternative first, 
so the leftmost path appears earliest.
Second, when two states share a residual, 
only the first is kept and the later one is discarded together with its injection, 
so the earlier path wins ties (Definition~8 of~\citealp{sulzmannlu2012}). 
Both mechanisms favour the leftmost alternative at every choice over the longest one,
which is what distinguishes the tree this parser returns 
from the POSIX tree of Chapter~\ref{sec:derivative-parser}.

\subsection{Partial Derivatives with Injections}
\label{sec:pderiv-tree-theory}

A partial derivative of $r$ with respect to a character $x$ 
produces a set of pairs rather than a single expression. 
The first component of each pair, the residual, 
is exactly $pd$ from Section~\ref{sec:antimirov-partial-derivatives}~\citep{antimirov1996},
so $\mathit{pderiv}$ reuses $pd$'s rules (Equation~\eqref{eq:pd}). 
The second component is the injection $\iota$, 
which rebuilds a parse tree of $r$ from a parse tree of the residual. 
This injection is $\mathit{inj}$ from Equation~\eqref{eq:inj},
already used by the standard derivative parser (Chapter~\ref{sec:derivative-parser})
to wrap alternatives and build concatenation and star trees.
Unlike for the standard derivative parser, 
the pattern partial derivatives of \citet{sulzmannlu2012}
provide no corresponding rules for constructing injections.

The pattern partial derivatives of \citet[Fig.~11]{sulzmannlu2012}
pair a residual with a variable-binding environment for submatching, not full parsing.
It records which substring each pattern variable matched,
not the derivation structure a parse tree records,
so those cannot be reused directly for parse-tree construction.
$\mathit{pderiv}$ instead threads $\mathit{inj}$ through $pd$'s rules,
pairing each residual with the injection that rebuilds its tree.
\begin{equation}\label{eq:pderiv-tree}
\begin{aligned}
\mathit{pderiv}(\emptyset, x) &= \{\} &&(\mathsf{P}_{\emptyset}) \\
\mathit{pderiv}(\varepsilon, x) &= \{\} &&(\mathsf{P}_{\varepsilon}) \\
\mathit{pderiv}(y, x) &=
  \begin{cases}
    \{(\varepsilon,\ \lambda\_.\, y)\} & x = y \\
    \{\} & x \neq y
  \end{cases}
  &&(\mathsf{P}_{\mathrm{lit}}) \\
\mathit{pderiv}(r + s, x) &=
  \begin{aligned}[t]
    &\{\,(r',\, \lambda v.\, \mathit{Left}\,(\iota\,v))
      \mid (r', \iota) \in \mathit{pderiv}(r, x)\,\} \;\cup \\
    &\{\,(s',\, \lambda v.\, \mathit{Right}\,(\iota\,v))
      \mid (s', \iota) \in \mathit{pderiv}(s, x)\,\}
  \end{aligned}
  &&(\mathsf{P}_{+}) \\
\mathit{pderiv}(r^{*}, x) &=
  \{(r'\,r^{*},
     \lambda(v, \mathit{Star}(vs)).
     \mathit{Star}([\iota\,v] \mathbin{+\!\!+} vs))
    \mid (r', \iota) \in \mathit{pderiv}(r, x)\}
  &&(\mathsf{P}_{*}) \\
\mathit{pderiv}(r \cdot s, x) &=
  \begin{cases}
    \begin{aligned}
    \{&(r'\,s,\lambda(v_1, v_2).\, (\iota\,v_1,\, v_2))
      \mid (r', \iota) \in \mathit{pderiv}(r, x)\} \;\cup \\
    &\{(s',\lambda v.\, (\mathit{mkEps}_{r},\, \iota\,v))
      \mid (s', \iota) \in \mathit{pderiv}(s, x)\}
    \end{aligned}
      & n(r) \\
    \{(r'\,s,\lambda(v_1, v_2).\, (\iota\,v_1,\, v_2))
      \mid (r', \iota) \in \mathit{pderiv}(r, x)\}
      & \neg\, n(r)
  \end{cases}
  &&\begin{array}{l} (\mathsf{P}_{\mathrm{seq}}^{\,n}) \\[1.2em] (\mathsf{P}_{\mathrm{seq}}) \end{array}
\end{aligned}
\end{equation}

Unlike the derivative of $r+s$, which keeps a single alternation,
the partial derivative produces separate states per branch.
$\mathsf{P}_{+}$ tags each with $\mathit{Left}$ or $\mathit{Right}$,
and $\mathsf{P}_{*}$ prepends each injected result to the iteration list.
Concatenation branches on $n(r)$.
$\mathsf{P}_{\mathrm{seq}}$ passes the outer pair through,
applying the recursive injection only to its first component.
When $r$ is nullable, $\mathsf{P}_{\mathrm{seq}}^{\,n}$
also includes states that skip $r$,
using $\mathit{mkEps}_r$ to construct its empty parse tree.
The skip-strand's injection pairs that empty tree with the tree for $s$,
keeping the concatenation shape even though the consumed character never entered $r$.
Each rule deduplicates its result by residual, keeping the first occurrence,
except $\mathsf{P}_{\mathrm{seq}}$, whose single source of states needs none.

Equation~\eqref{eq:pderiv-tree} keeps $\varepsilon \cdot s$ unsimplified,
unlike $pd$ (Equation~\eqref{eq:pd}), which uses $\mathit{smartC}$.
This is necessary because injection rule $\mathsf{I}_{\mathrm{seq}}$
from Equation~\eqref{eq:inj} destructures a $\mathit{Pair}$ 
from the residual's tree. 
If $\mathit{smartC}$ simplified $\varepsilon \cdot s$ to $s$, 
injection would no longer find the required $\mathit{Pair}$. 
Equation~\eqref{eq:mkeps-simp} shows a similar loss of structure 
in the standard derivative parser.
However, simplification can still be used, when the injection for the
simplified shape is rebuilt, similarly to the bit-coded parser that
rebuilds its bits onto the surviving node with fuse, 
as shown in Section~\ref{sec:fuse}.

%

\paragraph{In Rust.}
\label{sec:pderiv-tree-impl}

\texttt{pderiv\_tree} implements Equation~\eqref{eq:pderiv-tree}.
It returns a list of $(\text{residual}, \iota)$ pairs,
where each $\iota$ is a closure of type \texttt{InjStep}
taking a tree for the residual and returning a tree for the original expression.
The implementation simplifies $\varepsilon \cdot s$ to $s$ 
through \texttt{smart\_seq} (Equation~\eqref{eq:smartc}), 
as the bit-coded parser does (Section~\ref{sec:simp}).
In this parser, the reconstruction information
is preserved by rebuilding the injection for the simplified shape.

After derivation, the states are deduplicated by \texttt{nub\_tree}, 
which implements the $\mathit{nub}$ of Equation~\eqref{eq:simp-theory}.
This keeps the first state of each residual and discards the rest, 
comparing residuals by structural equality and ignoring injections. 
Without the collapse, 
$\varepsilon \cdot s$ and $s$ are structurally distinct, 
so \texttt{nub\_tree} would not recognize them as duplicates and neither is removed. 
The state set could then exceed the finite bound on distinct residuals.

Simplifying only the residual without rebuilding the injection
would leave the injection expecting a $\mathit{Pair}$ that is no longer there.
\texttt{pderiv\_tree}
avoids this by branching on whether the residual collapsed to \texttt{Regex::Eps}
(Figure~\ref{fig:pderiv-tree-seqstar-rust}):
in \texttt{Seq}, the closure then returns
$\mathit{Pair}(\mathit{inj}_1(\mathit{Empty}), v)$
or destructures $\mathit{Pair}(v_1, v_2)$ into $\mathit{Pair}(\mathit{inj}_1(v_1), v_2)$,
as Equation~\eqref{eq:pderiv-tree} specifies;
in \texttt{Star}, which extends a $\mathit{Star}$ list,
it pushes $\mathit{inj}_1(\mathit{Empty})$ directly
or destructures the wrapping $\mathit{Pair}$ first;
in \texttt{Alt}, since the $\mathsf{P}_{+}$ rule only derives two alternatives
and not a longer chain,
\texttt{pderiv\_tree} instead flattens a chain $r_1 + \cdots + r_p$
into its leaves before deriving them.
This preserves left-to-right order just as deriving one $+$ at a time would.
All three arms then call \texttt{nub\_tree} directly on their own output.

\begin{figure}[H]
\small
\begin{verbatim}
pub(crate) type InjStep = Rc<dyn Fn(ParseTree) -> ParseTree>;

pub(crate) fn pderiv_tree(r: &Regex, x: char) -> Vec<(Regex, InjStep)> {
    match r {
        // ...
        Regex::Seq(r1, r2) => {
            let mut out: Vec<(Regex, InjStep)> = pderiv_tree(r1, x).into_iter()
                .map(|(r1_, inj1)| {
                    let r2c = (**r2).clone();
                    if r1_ == Regex::Eps {
                        (r2c, Rc::new(move |v2| ParseTree::Pair(
                            Box::new(inj1(ParseTree::Empty)),
                            Box::new(v2))) as InjStep)
                    } else {
                        (smart_seq(r1_, &r2c), Rc::new(move |v| match v {
                            ParseTree::Pair(v1, v2) =>
                                ParseTree::Pair(Box::new(inj1(*v1)), v2),
                            _ => panic!("pderiv_tree/Seq: want Pair"),
                        }) as InjStep)
                    }
                }).collect();
            if nullable(r1) {
                let v1 = mk_eps(r1);
                out.extend(pderiv_tree(r2, x).into_iter().map(|(r2_, inj2)| (
                    r2_,
                    Rc::new(move |v2| ParseTree::Pair(
                        Box::new(v1.clone()),
                        Box::new(inj2(v2)))) as InjStep
                )));
                nub_tree(out)
            } else { out }
        }

        Regex::Star(r1) => nub_tree(
            pderiv_tree(r1, x).into_iter().map(|(r1_, inj1)| {
                if r1_ == Regex::Eps {
                    (Regex::star((**r1).clone()),
                     Rc::new(move |vs| match vs {
                        ParseTree::Star(mut it) => {
                            it.push(inj1(ParseTree::Empty));
                            ParseTree::Star(it)
                        }
                        _ => panic!("pderiv_tree/Star: want Star"),
                    }) as InjStep)
                } else {
                    (smart_seq(r1_, &Regex::star((**r1).clone())),
                     Rc::new(move |v| match v {
                        ParseTree::Pair(v1, vs) => match *vs {
                            ParseTree::Star(mut it) => {
                                it.push(inj1(*v1));
                                ParseTree::Star(it)
                            }
                            _ => panic!("pderiv_tree/Star: want Star"),
                        },
                        _ => panic!("pderiv_tree/Star: want Pair"),
                    }) as InjStep)
                }
            }).collect()
        ),}}
\end{verbatim}
\caption{\texttt{pderiv\_tree}: the \texttt{Seq} and \texttt{Star} arms of one
partial-derivative transition, producing a list of (residual,
injection-step) states via the \texttt{InjStep} closure type.}
\label{fig:pderiv-tree-seqstar-rust}
\end{figure}

\subsection{State Sets and Selection}
\label{sec:pderiv-state-set}

A \emph{state set} $S$ is a finite set of pairs $(r, \iota)$, 
where $r$ is a residual expression and $\iota$ an injection 
from parse trees of $r$ to parse trees of the original expression $r_0$. 
The parser maintains one state set per input prefix.
After $i$ characters, $S_i$ holds the pairs reachable from $r_0$ 
after those characters are consumed.
Each input character advances the whole set at once. 
Every pair produces its successors via \texttt{pderiv\_tree}, 
and the union replaces the old set. 
Unlike the standard derivative parser, no earlier state set is kept,
because each pair already carries its own reconstruction path.
When a transition produces a new residual, 
its step injection $\mathit{inj}_s$ 
maps the new residual's tree back to the old residual's tree, 
and the old pair's injection $\mathit{inj}_p$ 
maps that to the original. 
The new pair's injection is their composition,
$\lambda v.\, \mathit{inj}_p(\mathit{inj}_s(v))$.

%

\paragraph{In Rust.}
Representing that composition as nested closures 
would recurse one stack frame per character, 
both when applied and when destroyed. 
Therefore the implementation stores the steps 
as a cons-list and applies them iteratively instead (Figure~\ref{fig:inj-rust}).
\begin{figure}[H]
\small
\begin{verbatim}
enum InjNode { Identity, Step(InjStep, Rc<InjNode>) }
pub(crate) struct Inj(Rc<InjNode>);

impl Inj {
    pub(crate) fn then(&self, step: InjStep) -> Self {
        Inj(Rc::new(InjNode::Step(step, self.0.clone())))
    }
    pub(crate) fn apply(&self, v: ParseTree) -> ParseTree {
        let mut v = v;
        let mut cur = &self.0;
        loop {
            match &**cur {
                InjNode::Identity => return v,
                InjNode::Step(step, rest) => { v = step(v); cur = rest; }
            }
        }
    }
}
\end{verbatim}
\caption{\texttt{Inj}: a persistent cons-list of \texttt{InjStep}s.
\texttt{then} prepends one step in $O(1)$; \texttt{apply} walks the list
iteratively, so neither construction nor application recurses per step.}
\label{fig:inj-rust}
\end{figure}

%

The state set is a \texttt{Vec<(Regex, Inj)>}, 
advanced by \texttt{step\_frontier} (Figure~\ref{fig:step-frontier-rust}), 
which applies \texttt{pderiv\_tree} to every pair 
and composes each step onto the pair's \texttt{Inj}.
\begin{figure}[H]
\small
\begin{verbatim}
pub(super) fn step_frontier(frontier: Vec<(Regex, Inj)>, x: char) 
    -> Vec<(Regex, Inj)> {
    let mut out = Vec::new();
    for (r, inj_parent) in frontier {
        for (r_next, inj_step) in pderiv_tree(&r, x) {
            out.push((r_next, inj_parent.then(inj_step)));
        }
    }
    nub_tree(out)
}
\end{verbatim}
\caption{\texttt{step\_frontier}: one transition of the NFA state set on
a single character, replacing each pair by its successors. The final
\texttt{nub\_tree} deduplicates across parent pairs.}
\label{fig:step-frontier-rust}
\end{figure}

%

\clearpage
After the input is exhausted, 
\texttt{select} (Figure~\ref{fig:select-rust}) 
walks the state set in priority order 
and returns the tree for the first accepting pair.
\begin{figure}[H]
\small
\begin{verbatim}
pub(super) fn select(frontier: &[(Regex, Inj)]) -> Option<ParseTree> {
    for (r, inj) in frontier {
        if nullable(r) {
            return Some(reverse_stars(inj.apply(mk_eps(r))));
        }
    }
    None
}
\end{verbatim}
\caption{\texttt{select}: return the tree for the first accepting state.
\texttt{reverse\_stars} restores the iteration order of each
\texttt{Star}, which \texttt{pderiv\_tree} builds backwards.}
\label{fig:select-rust}
\end{figure}

The state set lists pairs in generation order, 
and \texttt{nub\_tree} keeps the first of each duplicate residual. 
Selection therefore favours whichever pair committed earliest, 
with no preference for the longest one, which gives a non-POSIX parse tree.

\subsection{Parser}
\label{sec:pderiv-std-parser}

The parser has a single pass.
Every input character advances the whole state set at once 
via $\mathit{step\_frontier}$, 
and the final state set is handed directly to $\mathit{select}$:
\begin{equation}\label{eq:pderiv-std-driver}
\begin{aligned}
S_0 &= \{(r, \mathit{id})\}, \\[10pt]
S_i &= \mathit{step\_frontier}(S_{i-1}, x_i)\ \ (1 \leq i \leq n), \\[10pt]
\mathit{result} &= \mathit{select}(S_n).
\end{aligned}
\end{equation}

Unlike the standard derivative parser's two-pass driver
(Equation~\eqref{eq:std-driver}),
no backward pass is needed here,
because each pair already carries the injection that reconstructs
its own tree rather than a bare residual.
Every injection in $S_i$ is already composed back to $r_0$
(Section~\ref{sec:pderiv-state-set}),
so $\mathit{select}$ applies only one injection,
to the first accepting state it finds in $S_n$,
instead of replaying $n$ derivative steps backward
the way $\mathit{inj}$ does for the standard parser.

%

\paragraph{In Rust.}
Figure~\ref{fig:pderiv-std-parser-rust} implements Equation~\eqref{eq:pderiv-std-driver}.
\begin{figure}[H]
\small
\begin{verbatim}
pub fn parse_pderiv_std(input: &str, r: &Regex) -> Option<ParseTree> {
    let mut frontier: Vec<(Regex, Inj)> =
        vec![(r.clone(), Inj::identity())];
    for c in input.chars() {
        frontier = step_frontier(frontier, c);
        if frontier.is_empty() {
            return None;
        }
    }
    select(&frontier)
}
\end{verbatim}
\caption{The standard partial-derivative parser.}
\label{fig:pderiv-std-parser-rust}
\end{figure}

The loop computes $S_0, \ldots, S_n$ in place, 
overwriting the state set each iteration 
rather than growing a \texttt{Vec} the way \texttt{parse\_deriv\_std\_loop} 
(Figure~\ref{fig:deriv-std-drivers-rust}) does. 
Nothing earlier survives once the next state set exists. 
An empty set early-returns, 
since $S_i = \{\}$ means no pair can consume the character and the input fails. 
Otherwise \texttt{select} returns the first accepting tree in $S_n$, or \texttt{None}.
Because the state set is overwritten rather than extended,
the parser's memory footprint is bounded by the size of one state set,
not by the input length, unlike a parser that keeps one derivative
per character consumed so far, such as the standard derivative
parser of Chapter~\ref{sec:derivative-parser}.

\subsection{Worked Example: Standard Partial-Derivative Parser}
\label{sec:pderiv-std-worked}

Recall the ambiguous example $r_0 = (a + ab)(b + \varepsilon)$ 
on input $\mathtt{ab}$.

%

\paragraph{Forward pass.}
The initial state set holds a single pair:
\[
S_0 = \bigl[(r_0,\ \mathit{id})\bigr].
\]

Transitioning with respect to $\mathtt{a}$:
\[
\begin{aligned}
\mathit{pderiv}(r_0, \mathtt{a})
  &= \mathit{pderiv}(a + ab,\ \mathtt{a})
     \cdot (b + \varepsilon).
\end{aligned}
\]
Inside the first factor:
\[
\begin{aligned}
\mathit{pderiv}(a, \mathtt{a})
  &= \bigl[(\varepsilon,\ \lambda\_.\, a)\bigr] \\
\mathit{pderiv}(ab, \mathtt{a})
  &= \bigl[(\mathit{Seq}(\varepsilon, b),\ \lambda(v_1, v_2).\, (a, v_2))\bigr].
\end{aligned}
\]
After the alternation rule wraps each state with $\mathit{Left}$ 
or $\mathit{Right}$:
\[
\begin{aligned}
\mathit{pderiv}(a + ab, \mathtt{a})
  = \bigl[
    &(\varepsilon,\ \lambda v.\, \mathit{Left}\,(\lambda\_.\, a)(v)), \\
    &(\mathit{Seq}(\varepsilon, b),\ \lambda(v_1, v_2).\,
       \mathit{Right}\,(a, v_2))\bigr].
\end{aligned}
\]
The outer sequence rule combines this with the untouched second factor:
\[
\begin{aligned}
S_1
  = \bigl[
    &(\mathit{Seq}(\varepsilon, b + \varepsilon),\,
       \lambda(v_1, v_2).\, (\mathit{Left}\,a,\, v_2)), \\
    &(\mathit{Seq}(\mathit{Seq}(\varepsilon, b), b + \varepsilon),\,
       \lambda((v_1, v_2), v_2').\, (\mathit{Right}(a, v_2),\, v_2'))\bigr].
\end{aligned}
\]

Transitioning with $\mathtt{b}$ steps both pairs. 
For the first, the left factor $\varepsilon$ is nullable, 
so the sequence rule produces the state that jumps directly into the second factor:
\[
\mathit{pderiv}(b + \varepsilon, \mathtt{b})
  = \bigl[(\varepsilon,\ \lambda v.\, \mathit{Left}\,b)\bigr].
\]
The second factor's injection inserts the character at the leftmost position
of the pair:
\[
\mathit{inj}_1(\mathit{Left}\,b) = (\mathit{Left}\,a,\, \mathit{Left}\,b).
\]
For the second pair, 
the leading $\mathit{Seq}(\varepsilon, b)$ is not nullable 
($\varepsilon$ is, but $b$ is not), 
so rule $(\mathsf{P}_{\mathrm{seq}})$ fires 
and the derivative continues inside $b$:
\[
\mathit{pderiv}(\mathit{Seq}(\varepsilon, b), \mathtt{b})
  = \bigl[(\varepsilon,\ \lambda\_.\, ((), b))\bigr],
\]
The outer sequence rule rebuilds the pair 
\emph{without} simplifying the leading $\varepsilon$ away, 
giving the second pair's residual 
$\varepsilon \cdot (b + \varepsilon)$, not $b + \varepsilon$. 
The two resulting state-set entries are:
\[
\begin{aligned}
S_2
  = \bigl[
    &(\varepsilon,\ \lambda\_.\, (\mathit{Left}\,a,\, \mathit{Left}\,b)), \\
    &(\varepsilon \cdot (b + \varepsilon),\ \lambda(\_, v_2).\,
       (\mathit{Right}(a, b),\, v_2))\bigr].
\end{aligned}
\]

%

\paragraph{Selection.}
The first residual $\varepsilon$ is nullable, 
so selection returns its injected parse tree:
\[
\begin{aligned}
\mathit{select}(S_2)
  &= (\lambda\_.\,(\mathit{Left}(a),\mathit{Left}(b)))
     (\mathit{mkEps}(\varepsilon)) \\
  &= (\mathit{Left}(a),\mathit{Left}(b))
  = v_0.
\end{aligned}
\]
Flattening confirms that $\mathtt{ab} \in L(r_0)$:
\[
\begin{aligned}
|v_0|
  &= |(\mathit{Left}(a),\mathit{Left}(b))| \\
  &= |\mathit{Left}(a)|\,|\mathit{Left}(b)| \\
  &= |a|\,|b| \\
  &= \mathtt{ab}.
\end{aligned}
\]
The second pair, $\varepsilon\cdot(b+\varepsilon)$, is also
nullable but is never inspected, since generation order favours
the first. Both partial-derivative parsers therefore return
the same non-POSIX tree. The POSIX parser of
Chapter~\ref{sec:derivative-parser} instead returns
$(\mathit{Right}(a,b),\mathit{Right}())$, selecting the longer
first alternative $ab$.

\section{The Bit-Coded Partial-Derivative Parser}
\label{sec:pderiv-bc}

The standard partial-derivative parser carries a closure per pair,
which accumulates the reconstruction path during the forward pass. 
The bit-coded variant replaces closures with bit-sequences: 
Each pair's annotation records the choices made so far, 
and decoding the final bit-sequence 
against the original expression gives the parse tree.

Unlike the bit-coded \emph{derivative} parser of Chapter~\ref{sec:derivative-parser}, 
this construction has no \texttt{internalize} step 
and builds no annotated \texttt{ARegex} type. 
A partial derivative already returns one residual per surviving strand, 
so each strand's bits thread 
alongside its plain \texttt{Regex} residual as a separate value 
(\texttt{AppendBits}, Section~\ref{sec:pderiv-bc-state-set}) 
rather than being embedded in the expression tree itself. 
There is no $\mathit{fuse}$ step either: 
$\mathit{fuse}$ exists to carry bits from a node 
a shared annotated tree is about to lose onto the
node that replaces it, and no such tree is ever built here.
Transitioning $w = \mathtt{ab}$ from $r_0 = (a + ab)(b + \varepsilon)$ gives:
\begin{equation}\label{eq:pderiv-bc-overview}
\begin{aligned}
S_0 &= \bigl[(r_0,\, [\,])\bigr] \\[2pt]
  &\xrightarrow{\ \mathtt{a}\ }
    S_1 = \bigl[
      (b + \varepsilon,\ [0]),\;
      (b\,(b + \varepsilon),\ [1])\bigr] \\[2pt]
  &\xrightarrow{\ \mathtt{b}\ }
    S_2 = \bigl[
      (\varepsilon,\ [0, 0]),\;
      (b + \varepsilon,\ [1])\bigr].
\end{aligned}
\end{equation}

The first pair of $S_1$ records that the character $\mathtt{a}$ 
was matched by the left branch of the first factor's alternation. 
The second pair records that it was matched by the right branch, 
leaving the residual $b$ to be consumed later. 
After the second character, both pairs are accepting, 
since both residuals $\varepsilon$ and $b + \varepsilon$ are nullable. 
Selection returns the first, 
whose bits $[0, 0]$ 
decode to $(\mathit{Left}\,a, \mathit{Left}\,b)$, 
the leftmost alternative at every choice.

\subsection{Bit-Coded Partial Derivatives}
\label{sec:pderiv-bc-theory}

The bit-coded partial derivative $\mathit{pderivBC}(r, x)$ 
returns a list of $(\text{residual}, \text{bit-sequence})$ pairs. 
It follows the same case structure as Equations~\eqref{eq:pderiv-tree}, 
with one difference:
where the standard version builds an injection closure, 
the bit-coded version prepends a fixed bit-sequence to the pair's existing bits.
The bit conventions are inherited from Chapter~\ref{sec:bitcoded-construction-formal}. 
Each alternation contributes a leading $0$ 
for the left branch or a leading $1$ for the right branch. 
Each star iteration contributes a leading $0$, 
and each star termination contributes a $1$. 
Concatenation contributes no bits of its own.
\begin{equation}\label{eq:pderiv-bc}
\begin{aligned}
\mathit{pderivBC}(\phi, x) &= \emptyset \\
\mathit{pderivBC}(\varepsilon, x) &= \emptyset \\
\mathit{pderivBC}(c, x) &=
  \begin{cases}
    \{(\varepsilon,\, [\,])\} & c = x \\
    \emptyset & \text{else}
  \end{cases} \\[4pt]
\mathit{pderivBC}(r_1 + r_2, x) &=
  \{\,(r_1',\, [0] \mathbin{+\!\!+} bs)
    \mid (r_1', bs) \in \mathit{pderivBC}(r_1, x)\,\} \\
  &\cup \{\,(r_2',\, [1] \mathbin{+\!\!+} bs)
    \mid (r_2', bs) \in \mathit{pderivBC}(r_2, x)\,\} \\[4pt]
\mathit{pderivBC}(r_1\,r_2, x) &=
  \{\,(\mathit{seq}(r_1', r_2),\, bs)
    \mid (r_1', bs) \in \mathit{pderivBC}(r_1, x)\,\} \\
  &\cup \begin{cases}
    \{\,(r_2',\, \mathit{mkEpsBC}_{r_1} \mathbin{+\!\!+} bs)
      \mid (r_2', bs) \in \mathit{pderivBC}(r_2, x)\,\} & n(r_1) \\
    \emptyset & \text{else}
  \end{cases} \\[4pt]
\mathit{pderivBC}(r^{*}, x) &=
  \{\,(\mathit{seq}(r', r^{*}),\, [0] \mathbin{+\!\!+} bs)
    \mid (r', bs) \in \mathit{pderivBC}(r, x)\,\}.
\end{aligned}
\end{equation}

As in the standard version, 
the result is deduplicated by residual, keeping the first occurrence.
The bit-coded sequence rule is the counterpart 
of the injection rule in the standard version. 
When the first factor is nullable, 
the bits recorded inside its empty match are extracted 
with $\mathit{mkEpsBC}_{r_1}$ and prepended to the second factor's bits, 
so the choice made inside the first factor survives in the surviving pair.

%

\paragraph{In Rust.}
\label{sec:pderiv-bc-impl}

Figure~\ref{fig:pderiv-bc-rust} implements Equation~\eqref{eq:pderiv-bc} directly.
The base cases mirror the standard version with bit-lists in place
of closures. Like \texttt{pderiv\_tree}'s \texttt{Alt} arm
(Section~\ref{sec:pderiv-tree-impl}), \texttt{pderiv\_bc}'s own
\texttt{Alt} arm flattens an $n$-ary $+$-chain into its leaves before
deriving them, rather than recursing through nested binary
\texttt{Alt} nodes and deduplicating at every level.
\texttt{flatten\_alt} (Figure~\ref{fig:pderiv-bc-flatten-rust}) walks
the chain once, giving each leaf the bit prefix its position assigns:
\texttt{false} for a left branch and \texttt{true} for a right,
accumulated down the spine in encounter order. This is the bit-list
counterpart of the $\mathit{Left}$/$\mathit{Right}$-wrapped closure
\texttt{pderiv\_tree}'s own flattening builds for the same leaf.
Deriving each leaf and extending its prefix with the result's own
bits, then calling \texttt{nub2} once on the combined list, gives the
same leftmost-priority result a per-level recursion would, for a
single dedup pass instead of $p - 1$.

The \texttt{Seq} arm's two branches are each written out in full,
rather than factoring out the shared recurse-into-$r_1$ step
the way \texttt{pderiv\_tree}'s \texttt{Seq} arm does;
this changes nothing about the result, since neither branch's computation
depends on which branch it is.
In the nullable branch, \texttt{eps\_bits} (that is, $\mathit{mkEpsBC}_{r_1}$)
is cloned and extended with each skip-strand's own bits,
giving $\mathit{mkEpsBC}_{r_1} \mathbin{+\!\!+} bs$ in that order,
exactly as Equation~\eqref{eq:pderiv-bc} specifies.
The star case prepends a leading $0$ marking that this
transition continues an iteration, the counterpart of the single
terminating $1$ that $\mathit{mkEpsBC}$'s star rule emits.

Both \texttt{Seq} and \texttt{Star} call \texttt{smart\_seq},
since $r_1$'s derivative can be $\varepsilon$
regardless of whether $r_1$ itself is nullable.
Unlike \texttt{pderiv\_tree} (Section~\ref{sec:pderiv-tree-impl}),
no companion adjustment is needed, since the bits ride alongside the
residual: collapsing $\varepsilon \cdot s$ to $s$ leaves \texttt{bs} untouched.

                    out: &mut Vec<(&'a Regex, Vec<bool>)>) {
    match r {
        Regex::Alt(r1, r2) => {
            prefix.push(false);
            flatten_alt(r1, prefix, out);
            prefix.pop();
            prefix.push(true);
            flatten_alt(r2, prefix, out);
            prefix.pop();
        }
        other => out.push((other, prefix.clone())),
    }
}

pub fn pderiv_bc(r: &Regex, x: char) -> Vec<(Regex, Vec<bool>)> {
    match r {
        Regex::Phi | Regex::Eps => vec![],

        Regex::Lit(y) => {
            if *y == x { vec![(Regex::Eps, vec![])] } else { vec![] }
        }

        Regex::Alt(_, _) => {
            let mut leaves: Vec<(&Regex, Vec<bool>)> = Vec::new();
            let mut prefix = Vec::new();
            flatten_alt(r, &mut prefix, &mut leaves);

            let mut out: Vec<(Regex, Vec<bool>)> = Vec::new();
            for (leaf, leaf_prefix) in leaves {
                for (r_, bs) in pderiv_bc(leaf, x) {
                    let mut b = leaf_prefix.clone();
                    b.extend(bs);
                    out.push((r_, b));
                }
            }
            nub2(out)
        }

        Regex::Seq(r1, r2) => {
            if nullable(r1) {
                let mut out: Vec<(Regex, Vec<bool>)> = pderiv_bc(r1, x)
                    .into_iter()
                    .map(|(r1_, bs)| (smart_seq(r1_, r2), bs))
                    .collect();

                let eps_bits = mk_eps_bits(r1);
                out.extend(pderiv_bc(r2, x).into_iter().map(|(r2_, bs)| {
                    let mut b = eps_bits.clone(); b.extend(bs);
                    (r2_, b)
                }));
                nub2(out)
            } else {
                pderiv_bc(r1, x)
                    .into_iter()
                    .map(|(r1_, bs)| (smart_seq(r1_, r2), bs))
                    .collect()
            }
        }

        Regex::Star(r1) => {
            let out: Vec<(Regex, Vec<bool>)> = pderiv_bc(r1, x)
                .into_iter()
                .map(|(r1_, mut bs)| {
                    let mut b = vec![false]; b.append(&mut bs);
                    (smart_seq(r1_, &Regex::star(*r1.clone())), b)
                })
                .collect();
            nub2(out)
        }
    }
}
\end{verbatim}
\caption{\texttt{pderiv\_bc}: one bit-coded partial-derivative transition.}

\end{figure}

\subsection{Extracting Bits}
\label{sec:pderiv-bc-mkeps}

When a pair's residual is nullable, its accumulated bits must be
extended with the bits of the residual's empty match. This is the role of
$\mathit{mkEpsBC}$, which mirrors $\mathit{mkEps}$ from
Chapter~\ref{sec:derivative-parser} but produces a bit-sequence instead of a
parse tree.
\begin{equation}\label{eq:pderiv-mkepsbc}
\begin{aligned}
\mathit{mkEpsBC}_{\varepsilon} &= [\,] \\
\mathit{mkEpsBC}_{r^{*}} &= [1] \\
\mathit{mkEpsBC}_{r_1 r_2} &=
  \mathit{mkEpsBC}_{r_1} \mathbin{+\!\!+} \mathit{mkEpsBC}_{r_2} \\
\mathit{mkEpsBC}_{r_1 + r_2} &=
  \begin{cases}
    [0] \mathbin{+\!\!+} \mathit{mkEpsBC}_{r_1} & n(r_1) \\
    [1] \mathbin{+\!\!+} \mathit{mkEpsBC}_{r_2} & \text{else.}
  \end{cases}
\end{aligned}
\end{equation}

The alternation rule reproduces the left preference of $\mathit{mkEps}$,
emitting $0$ when the left branch is nullable and $1$
otherwise. The star rule emits a single terminating $1$, since a
star matching the empty word uses zero iterations. Where $\mathit{mkEps}$ builds a parse-tree node per case
(Chapter~\ref{sec:derivative-parser}), $\mathit{mkEpsBC}$ only concatenates
bit-lists: $\mathit{Alt}$ and $r^{*}$ contribute the same leading bit their
$\mathit{pderivBC}$ counterparts do (Equation~\eqref{eq:pderiv-bc}), and
$r_1 r_2$ needs no case split, since $r_1 \cdot r_2$ is nullable only when
both $r_1, r_2$ are.

%

\paragraph{In Rust.}
\label{sec:mk-eps-bits-impl}

Figure~\ref{fig:mk-eps-bits-rust} implements~\eqref{eq:pderiv-mkepsbc} directly.

\begin{verbatim}
pub fn mk_eps_bits(r: &Regex) -> Vec<bool> {
    match r {
        Regex::Phi => panic!("mk_eps_bits called on Phi"),
        Regex::Lit(c) => panic!("mk_eps_bits called on Lit('{}')", c),
        Regex::Eps => Vec::new(),
        Regex::Alt(r1, r2) => {
            if nullable(r1) {
                let mut bits = vec![false];
                bits.extend(mk_eps_bits(r1));
                bits
            } else {
                let mut bits = vec![true];
                bits.extend(mk_eps_bits(r2));
                bits
            }
        }
        Regex::Seq(r1, r2) => {
            let mut bits = mk_eps_bits(r1);
            bits.extend(mk_eps_bits(r2));
            bits
        }
        Regex::Star(_) => vec![true],
    }
}

$\mathit{mkEpsBC}$ is invoked once per parse, by $\mathit{select\_bits}$
(Section~\ref{sec:pderiv-bc-state-set}), extending the accepting
pair's bits the same way the standard parser's $\mathit{select}$
applies $\mathit{mkEps}$ to its injection.

\subsection{State Sets and Selection}
\label{sec:pderiv-bc-state-set}

A state set here is a finite set of pairs $(r, bs)$ of a residual and
the bits accumulated for it so far, the bit-coded counterpart of
Section~\ref{sec:pderiv-state-set}'s $(r, \iota)$ pairs.
The parser maintains one state set per input prefix exactly as in
Section~\ref{sec:pderiv-state-set}: after $i$ characters, $S_i$ holds
every pair reachable from $r_0$ by consuming those characters, and each
character advances the whole set at once via \texttt{pderiv\_bc}, the
union replacing the old set.
The difference is what each pair carries forward.
Where $\iota$ composes a new closure onto the old one at every step,
$bs$ is simply extended: the step bits \texttt{pderiv\_bc} returns
alongside each residual are appended to the pair's existing bits, with
no composition or closure application ever needed.
A pair's bits already read left to right exactly as the forward pass
chose them, so nothing is assembled backwards the way injections are.

%

\paragraph{In Rust.}
\label{sec:pderiv-bc-state-set-impl}

\texttt{AppendBits} (Section~\ref{sec:aregex-type}) avoids the same
$O(n^2)$ clone-then-extend cost as \texttt{Bits} and \texttt{Inj} do
elsewhere, but faces the opposite access pattern: \texttt{Bits} only
ever prepends, while \texttt{step\_frontier} appends a short suffix onto
a potentially long accumulated history at every character.
\texttt{AppendBits} wraps a \texttt{Bits} chain holding the sequence in
reverse, so appending a suffix becomes prepending its reversed bits onto
that chain, an operation costing only the suffix's length regardless of
how much history already exists.
The full sequence is materialized, and reversed back into the right
order, only once, inside \texttt{decode}'s single call at the end of the
parse (Section~\ref{sec:pderiv-bc-parser}), never on an intermediate step.
Figure~\ref{fig:step-frontier-bc-rust} shows the resulting
\texttt{step\_frontier}.

\small
\begin{verbatim}
pub(super) fn step_frontier(frontier: &[(Regex, AppendBits)], x: char) 
    -> Vec<(Regex, AppendBits)> {
    let mut out = Vec::new();

        for (r_next, extra) in pderiv_bc(r, x) {
            out.push((r_next, bits.append(&extra)));
        }
    }
    nub2(out)
}
\end{verbatim}
\caption{\texttt{step\_frontier} (bit-coded): counterpart of
Figure~\ref{fig:step-frontier-rust}, \texttt{nub2} for \texttt{nub\_tree}.}

\end{figure}

Selection returns the first accepting pair's bits, extended with
$\mathit{mkEpsBC}$ of its residual:
\begin{figure}[H]
\small
\begin{verbatim}

    -> Option<Vec<bool>> {
    for (r, bits) in frontier {
        if nullable(r) {
            return Some(bits.append(&mk_eps_bits(r)).to_vec());
        }
    }
    None
}
\end{verbatim}

\label{fig:select-bits-rust}
\end{figure}

Like \texttt{select}, \texttt{select\_bits} walks the state set 
in generation order and returns the first accepting pair, 
so the same non-POSIX bias applies.
Whichever branch committed earliest wins, with
no preference for the pair whose underlying tree would be longest.
The two selections differ only in what they hand back.
\texttt{select} applies one injection to build a tree directly.
\texttt{select\_bits} appends \texttt{mk\_eps\_bits} 
of the accepting residual and returns a flat bit vector, 
leaving tree construction to \texttt{decode} 
(Section~\ref{sec:pderiv-bc-parser}) rather than doing it here.

\subsection{Parser}
\label{sec:pderiv-bc-parser}

The parser runs the same single pass 
as the standard partial-derivative parser 
(Equation~\eqref{eq:pderiv-std-driver}), 
advancing the whole state set at once 
and handing the final state set directly to $\mathit{select}_b$, 
with bit-sequences in place of injections:
\begin{equation}\label{eq:pderiv-bc-driver}
\begin{aligned}
T_0 &= \{(r, [\,])\}, \\
T_i &= \mathit{step}_b(T_{i-1}, x_i) \quad (1 \leq i \leq n), \\
\mathit{result} &= \mathit{decode}_r(\mathit{select}_b(T_n)),
\end{aligned}
\end{equation}
where $\mathit{step}_b$ applies \texttt{pderiv\_bc} to each pair 
and $\mathit{select}_b$ returns $bs \mathbin{+\!\!+} \mathit{mkEpsBC}(r')$
for the first pair $(r', bs)$ in $T_n$ whose residual is nullable.

%

As with the standard driver, no backward pass over the input is needed,
but the two parsers differ in what their one remaining reconstruction
step costs.
\texttt{select}'s $\mathit{inj}$ applies a chain of closures built up
one per character consumed, so its cost tracks how many derivative
steps produced it.
\texttt{decode} instead walks $r_0$'s own structure once, consuming
bits only at the choice points (\texttt{Alt} and \texttt{Star}) that
produced them, so its cost tracks the size of the resulting parse tree
rather than the length of the derivation that built the bits.

\paragraph{In Rust.}
Figure~\ref{fig:pderiv-bc-parser-rust} implements~\eqref{eq:pderiv-bc-driver}.
The loop is identical to the standard variant,
replacing \texttt{Inj} with \texttt{AppendBits}.
As in \texttt{parse\_pderiv\_std} (Figure~\ref{fig:pderiv-std-parser-rust}),
it overwrites \texttt{frontier} in place each iteration, so no earlier
state set survives once the next one exists, and an empty state set
early-returns \texttt{None} for the same reason: no pair can consume
the next character, so the whole input is rejected.
Once the loop finishes, \texttt{select\_bits} returns the final bits by
appending \texttt{mk\_eps\_bits} to the first accepting pair's bits, an
\texttt{Option<Vec<bool>{}>} mirroring \texttt{select}'s own
\texttt{Option<ParseTree>}, and \texttt{decode} reads those bits
against $r$.
The parser therefore pays for state set maintenance exactly once per
character and for reconstruction exactly once at the end, the same
shape as the standard partial-derivative parser, just with a smaller
and more uniform payload travelling through the loop.

\begin{figure}[H]
\small
\begin{verbatim}
pub fn parse_pderiv_bc(input: &str, r: &Regex) -> Option<ParseTree> {
    let mut frontier = vec![(r.clone(), AppendBits::empty())];
    for c in input.chars() {
        frontier = step_frontier(&frontier, c);
        if frontier.is_empty() {
            return None;
        }
    }
    let bits = select_bits(&frontier)?;
    Some(decode(r, &bits))
}

\subsection{Worked Example: Bit-Coded Partial-Derivative Parser}
\label{sec:pderiv-bc-worked}

Consider again the ambiguous example $r_0 = (a + ab)(b + \varepsilon)$ on
input $\mathtt{ab}$.

%

\paragraph{Forward pass.}
The initial state set holds a single pair with empty bits:
\[
S_0 = \bigl[(r_0,\ [\,])\bigr].
\]

Transitioning by $\mathtt{a}$, the first factor is not nullable, so
$\mathit{pderivBC}$ recurses into it:
\[
\begin{aligned}
\mathit{pderivBC}(a + ab, \mathtt{a})
  &= \mathit{pderivBC}(a, \mathtt{a}).\mathit{map}(+[0])
     \cup \mathit{pderivBC}(ab, \mathtt{a}).\mathit{map}(+[1]) \\
  &= \bigl[(\varepsilon,\ [0]),\;
            (b,\ [1])\bigr].
\end{aligned}
\]
The sequence rule then places the second factor after each derivative:
\[
S_1 = \bigl[
  (b + \varepsilon,\ [0]),\;
  (b\,(b + \varepsilon),\ [1])\bigr].
\]

Transitioning by $\mathtt{b}$, both pairs are stepped. 
The first pair reaches the second factor directly:
\[
\mathit{pderivBC}(b + \varepsilon, \mathtt{b})
  = \bigl[(\varepsilon,\ [0])\bigr],
\]
giving bits $[0, 0]$. The second pair's
derivative comes from $b$ inside the leading sequence:
\[
\mathit{pderivBC}(b, \mathtt{b}) = \bigl[(\varepsilon,\ [\,])\bigr],
\]
and the outer sequence rule reconstructs the residual $b + \varepsilon$ with
the bits unchanged:
\[
S_2 = \bigl[
  (\varepsilon,\ [0, 0]),\;
  (b + \varepsilon,\ [1])\bigr].
\]

%

\paragraph{Selection and decoding.}
The first pair is accepting, so $\mathit{selectBits}$ returns its
bits extended with $\mathit{mkEpsBC}_\varepsilon = [\,]$:
\[
\mathit{selectBits}(S_2) = [0, 0].
\]
Decoding these bits against $r_0$:
\[
\mathit{decode}_{r_0}\bigl([0, 0]\bigr)
  = \bigl(\mathit{Left}(a), \mathit{Left}(b)\bigr).
\]
The first $0$ selects the left branch of the first factor's
alternation, committing to the shorter alternative $a$. The second
$0$ selects the left branch of the second factor's alternation,
committing to the shorter alternative $b$. The resulting tree is the non-POSIX
parse tree, identical to the one produced by the standard partial-derivative
parser.

Flattening confirms that $\mathtt{ab} \in L(r_0)$:
\[
\begin{aligned}
|v_0|
  &= |(\mathit{Left}(a), \mathit{Left}(b))| \\
  &= |\mathit{Left}(a)|\,|\mathit{Left}(b)| \\
  &= |a|\,|b| \\
  &= \mathtt{ab}.
\end{aligned}
\]

Both partial-derivative parsers produce this same tree.
Unlike the derivative-based parsers of
Chapter~\ref{sec:derivative-parser}, 
they select the shorter first alternative, 
returning $(\mathit{Left}(a), \mathit{Left}(b))$ 
rather than the parse tree $(\mathit{Right}(a,b), \mathit{Right}())$.
