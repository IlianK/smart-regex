\chapter{Derivatives and Partial Derivatives}
\label{sec:derivatives}

This chapter introduces three algorithms for deciding \(w \in L(r)\),
starting with a naive recursive matcher as a simple starting point,
before introducing the two transformation-based approaches.
Brzozowski derivatives transform the expression 
into a single residual as input is consumed, 
while Antimirov's partial derivatives represent a set of residuals.

%
%
%

\section{Naive Matching}
\label{sec:naive-matching}

The direct way to decide whether $w \in L(r)$ 
is to interpret the semantic rules of Equation~\eqref{eq:semantics} 
as recursive matching rules.
Let $w[i:j]$ denote the substring of $w$ from position $i$ to $j$.
A procedure $\operatorname{match}(w,i,j,r)$ determines whether $w[i:j] \in L(r)$:
\begin{equation}
\begin{aligned}
\operatorname{match}(w,i,j,\varepsilon)
  &\iff i = j, \\[2pt]
\operatorname{match}(w,i,j,x)
  &\iff j = i+1 \land w[i] = x, \\[2pt]
\operatorname{match}(w,i,j,r+s)
  &\iff \operatorname{match}(w,i,j,r)
      \lor \operatorname{match}(w,i,j,s), \\[2pt]
\operatorname{match}(w,i,j,r\cdot s)
  &\iff \exists k \in [i,j].\,
      \operatorname{match}(w,i,k,r)
      \land
      \operatorname{match}(w,k,j,s), \\[2pt]
\operatorname{match}(w,i,j,r^{*})
  &\iff i=j
      \lor
      \exists k \in (i,j].\,
      \operatorname{match}(w,i,k,r)
      \land
      \operatorname{match}(w,k,j,r^{*}).
\end{aligned}
\label{eq:naive-matcher}
\end{equation}

Each rule mirrors one case of the semantics.
Concatenation does not specify where the prefix ends and the suffix begins, 
so the matcher tries every split point $k$.
For $(a\cdot a)\cdot a$ against $\mathtt{aaa}$, 
the outer concatenation considers each $k\in\{0,1,2,3\}$ in turn. 
The split $k=2$ succeeds,
placing $a\cdot a$ against $\mathtt{aa}$ and $a$ against $\mathtt{a}$.
The recursive call on $a\cdot a$ against $\mathtt{aa}$
in turn succeeds at its own split $k=1$, completing the match
(Figure~\ref{fig:naive-splits}).

\paragraph{In Rust.}
The rules of Equation~\ref{eq:naive-matcher} 
translate directly into the match arms of Figure~\ref{fig:match-naive-rust}. 
Alternation tries both branches on the same input, 
and concatenation and star search the split points with \texttt{.any}, 
short-circuiting at the first success. 
The star arm clones its body, 
because the recursive call must own the newly built \texttt{Star} expression.

\begin{figure}[H]
\small
\begin{verbatim}
Regex::Alt(r, s) => {
    match_naive_range(word, i, j, r)
        || match_naive_range(word, i, j, s)
}
Regex::Seq(r, s) => {
    (i..=j).any(|k| {
        match_naive_range(word, i, k, r)
            && match_naive_range(word, k, j, s)
    })
}
Regex::Star(r) => {
    i == j || (i + 1..=j).any(|k| {
        match_naive_range(word, i, k, r)
            && match_naive_range(word, k, j,
                &Regex::star(*r.clone()))
    })
}
\end{verbatim}
\caption{Alternation, concatenation, and star arms of the naive matcher.}
\label{fig:match-naive-rust}
\end{figure}

Although inefficient, the matcher serves as a reference implementation
that follows the semantics directly, without intermediate transformations.
Nested concatenations can cause exponential backtracking 
as the matcher repeatedly explores smaller substrings and alternative paths. 
By contrast, the derivative approach transforms \(r\) 
as each character of \(w\) is consumed, 
producing an expression that describes the language of the remaining suffix.

\section{Brzozowski Derivatives}
\label{sec:brzozowski-derivatives}

Brzozowski's derivative of $r$ with respect to a symbol $x$, 
written $r \backslash x$, describes what remains of $r$'s language 
after the leading symbol $x$ is consumed~\citep{brzozowski1964}. 
For a word $w = x_1x_2\cdots x_n$, one derivative is taken per symbol:
\begin{equation}\label{eq:der-23}
\begin{gathered}
L(r \backslash x) \;=\; \{\, w \mid xw \in L(r) \,\}, \\[6pt]
r \;\xrightarrow{\;x_1\;}\; r\backslash x_1
  \;\xrightarrow{\;x_2\;}\; (r\backslash x_1)\backslash x_2
  \;\xrightarrow{\;x_3\;}\; \cdots
\end{gathered}
\end{equation}

%

\paragraph{Nullability.}
\label{par:nullability}
After all symbols have been consumed, the remaining input is $\varepsilon$. 
Thus, the resulting expression must accept $\varepsilon$ 
for the original word to belong to $L(r)$. 
This is the question of whether the expression is \emph{nullable}.
Let $n(r)$ be true exactly when $\varepsilon \in L(r)$:
\begin{equation}\label{eq:nullability}
\begin{aligned}
n(\emptyset) &= \mathrm{false} &&(\mathsf{N}_{\emptyset}) &
n(r + s) &= n(r) \lor n(s) &&(\mathsf{N}_{+}) \\
n(\varepsilon) &= \mathrm{true} &&(\mathsf{N}_{\varepsilon}) &
n(r \cdot s) &= n(r) \land n(s) &&(\mathsf{N}_{\mathrm{seq}}) \\
n(x) &= \mathrm{false} &&(\mathsf{N}_{\mathrm{lit}}) &
n(r^{*}) &= \mathrm{true} &&(\mathsf{N}_{*})
\end{aligned}
\end{equation}

The empty language $\emptyset$ is not nullable 
because it contains no words, 
including $\varepsilon$, while a literal cannot match the empty word. 
$\varepsilon$ and $r^{*}$ always match $\varepsilon$.
An alternation is nullable when either branch is nullable, 
and a concatenation only when both components are.

%

\paragraph{In Rust.}
\label{par:nullability-rust}
The definition is transcribed one \texttt{Regex} variant at a time,
using the enum of Figure~\ref{fig:regex-enum}. 
The case split shown in Equation~\eqref{eq:nullability} 
are the \texttt{match} arms of Figure~\ref{fig:nullable-rust}.

\begin{figure}[H]
\small
\begin{verbatim}
pub fn nullable(r: &Regex) -> bool {
    match r {
        Regex::Phi => false,
        Regex::Eps => true,
        Regex::Lit(_) => false,
        Regex::Alt(r, s) => nullable(r) || nullable(s),
        Regex::Seq(r, s) => nullable(r) && nullable(s),
        Regex::Star(_) => true,
    }
}
\end{verbatim}
\caption{\texttt{nullable} implementation and its six cases:
$\mathsf{N}_{\emptyset}$, $\mathsf{N}_{\varepsilon}$,
$\mathsf{N}_{\mathrm{lit}}$, $\mathsf{N}_{+}$,
$\mathsf{N}_{\mathrm{seq}}$ and $\mathsf{N}_{*}$.}
\label{fig:nullable-rust}
\end{figure}

The expression is passed by reference because \texttt{nullable} only
inspects $r$ and does not modify or consume it. 
The underscores in $\mathsf{N}_{\mathrm{lit}}$ and $\mathsf{N}_{*}$ indicate 
that the corresponding operands are irrelevant. 
A literal is never nullable, regardless of its symbol, 
and a Kleene-star expression is always nullable, regardless of its body. 
The short-circuiting operators \texttt{||} and \texttt{\&\&} 
avoid evaluating the second operand when the result is already determined.

%

\paragraph{Derivative Rules.}
\label{par:derivative-rules}

Equation~\ref{eq:derivative} specifies the expression remaining after consuming $x$:
\begin{equation}\label{eq:derivative}
\begin{aligned}
\emptyset \backslash x &= \emptyset &&(\mathsf{D}_{\emptyset}) 
\quad &
(r + s) \backslash x &= (r \backslash x) + (s \backslash x) &&\hspace{0.4em}(\mathsf{D}_{+}) \\
\varepsilon \backslash x &= \emptyset &&(\mathsf{D}_{\varepsilon})
\quad &
r^{*} \backslash x &= (r \backslash x) \cdot r^{*} &&\hspace{0.4em}(\mathsf{D}_{*}) \\
y \backslash x &= \begin{cases}
  \varepsilon & x = y \\
  \emptyset & x \neq y
\end{cases}
&&(\mathsf{D}_{\mathrm{lit}})
\quad &
(r \cdot s) \backslash x &= \begin{cases}
  (r \backslash x) \cdot s + s \backslash x & n(r) = \mathrm{true} \\
  (r \backslash x) \cdot s & n(r) = \mathrm{false}
\end{cases}
&&\begin{array}{l}
(\mathsf{D}_{\mathrm{seq}}^{\,n}) \\
(\mathsf{D}_{\mathrm{seq}})
\end{array}
\end{aligned}
\end{equation}

The empty language and \(\varepsilon\) cannot consume \(x\). 
A literal \(y\) succeeds only if \(x=y\), leaving \(\varepsilon\). 
Alternation retains both derivatives, while for \(r^{*}\), 
one occurrence of \(r\) consumes \(x\) and further occurrences remain available.
Concatenation is the only rule that depends on nullability. 
If \(r\) is not nullable, it must consume the leading \(x\), 
leaving \((r\backslash x)\cdot s\). 
If \(r\) is nullable, either \(r\) consumes \(x\), 
leaving \((r\backslash x)\cdot s\), 
or \(r\) matches \(\varepsilon\) and \(s\) consumes \(x\), 
leaving \(s\backslash x\). 
The resulting derivative is therefore \((r\backslash x)\cdot s + s\backslash x\).

%

\paragraph{In Rust.}
Figure~\ref{fig:deriv-rust} implements Equation~\eqref{eq:derivative} 
one variant per arm,  with \texttt{Seq} branching on \texttt{nullable(r1)} 
to select $\mathsf{D}_{\mathrm{seq}}^{\,n}$ or $\mathsf{D}_{\mathrm{seq}}$. 
Unlike \texttt{nullable}, \texttt{deriv} borrows its input 
but returns an owned expression. 
The clones in the \texttt{Seq} and \texttt{Star} arms are needed for $s$ 
to appear untouched in both branches 
and also for $r^{*}$ to be preserved both derived and underived. 
This copying mechanism drives expression growth,
which is why simplification follows every derivative step.

\begin{figure}[H]
\small
\begin{verbatim}
pub fn deriv(r: &Regex, x: char) -> Regex {
    match r {
        Regex::Phi => Regex::Phi,
        Regex::Eps => Regex::Phi,
        Regex::Lit(c) => if *c == x { Regex::Eps } else { Regex::Phi },
        Regex::Alt(r1, r2) => 
            Regex::alt(deriv(r1, x), deriv(r2, x)),
        Regex::Seq(r1, r2) => {
            let dr1 = Regex::seq(deriv(r1, x), *r2.clone());
            if nullable(r1) {
                Regex::alt(dr1, deriv(r2, x))
            } else { dr1 }
        }
        Regex::Star(r1) => 
            Regex::seq(deriv(r1, x), Regex::star(*r1.clone())),
    }
}
\end{verbatim}
\caption{\texttt{deriv}: Implementing the derivative algorithm with six cases, 
one per rule of Equation~\eqref{eq:derivative}.
The \texttt{Seq} arm branches on \texttt{nullable} 
to choose between the two concatenation rules, 
and the clones preserve the untouched operands.}
\label{fig:deriv-rust}
\end{figure}

\paragraph{Example: Growth without simplification.}
Consider $(x+y)^{*}$ against the word $\mathtt{xx}$:
The expression is a star, so $\mathsf{D}_{*}$ applies with
body $r = x+y$:
\begin{equation}\label{eq:der-3}
\begin{aligned}
(x+y)^{*} \backslash \mathtt{x}
  &= ((x+y) \backslash \mathtt{x}) \cdot (x+y)^{*}
  &&\mathsf{D}_{*},\ r = x+y \\
  &= (\varepsilon + \emptyset) \cdot (x+y)^{*}
  &&\mathsf{D}_{+},\ \mathsf{D}_{\mathrm{lit}}
\end{aligned}
\end{equation}

The expression is now the concatenation
$(\varepsilon + \emptyset) \cdot (x+y)^{*}$, and deriving it consumes the second
$\mathtt{x}$. The result is an alternation because
$\mathsf{D}_{\mathrm{seq}}^{\,n}$ applies with $r = \varepsilon + \emptyset$ and
$s = (x+y)^{*}$, its nullable case being selected since
$n(r) = n(\varepsilon + \emptyset) = \mathrm{true}$ by $\mathsf{N}_{+}$ and $\mathsf{N}_{\varepsilon}$:
\begin{equation}\label{eq:der-4}
\begin{aligned}
&((\varepsilon + \emptyset) \cdot (x+y)^{*}) \backslash \mathtt{x} \\
  &= ((\varepsilon + \emptyset) \backslash \mathtt{x}) \cdot (x+y)^{*}
     + (x+y)^{*} \backslash \mathtt{x}
  &&\mathsf{D}_{\mathrm{seq}}^{\,n} \\
  &= (\emptyset + \emptyset) \cdot (x+y)^{*}
     + (x+y)^{*} \backslash \mathtt{x}
  &&\mathsf{D}_{\varepsilon} \\
  &= (\emptyset + \emptyset) \cdot (x+y)^{*}
     + (\varepsilon + \emptyset) \cdot (x+y)^{*}
  &&\mathsf{D}_{*},\ \mathsf{D}_{+},\ \mathsf{D}_{\mathrm{lit}}
\end{aligned}
\end{equation}

After both symbols are consumed, the result is checked for nullability:
\begin{equation}\label{eq:der-5}
\begin{aligned}
&n((\emptyset + \emptyset) \cdot (x+y)^{*} + (\varepsilon + \emptyset) \cdot (x+y)^{*}) \\
&= n((\emptyset + \emptyset) \cdot (x+y)^{*}) \lor n((\varepsilon + \emptyset) \cdot (x+y)^{*})
   &&\mathsf{N}_{+} \\
&= (n(\emptyset + \emptyset) \land n((x+y)^{*})) \lor
   (n(\varepsilon + \emptyset) \land n((x+y)^{*}))
   &&\mathsf{N}_{\mathrm{seq}} \\
&= (\mathrm{false} \land \mathrm{true}) \lor
   (\mathrm{true} \land \mathrm{true})
   &&\mathsf{N}_{+},\ \mathsf{N}_{\emptyset},\ \mathsf{N}_{\varepsilon},\ \mathsf{N}_{*} \\
&= \mathrm{true}.
\end{aligned}
\end{equation}

Thus $(x+y)^{*}$ matches $\mathtt{xx}$.

%

\paragraph{Simplification.}
As shown in Equation~\ref{eq:der-growth}, repeatedly deriving
$(x+y)^{*}$ by the same symbol causes unbounded growth as the nullable
branch of $\mathsf{D}_{\mathrm{seq}}^{\,n}$ introduces redundant
alternations that accumulate $\varepsilon$ and $\emptyset$ in
subsequent derivatives:
\begin{equation}\label{eq:der-growth}
\begin{aligned}
& (x+y)^{*} && 4 \\
\xrightarrow{\;\mathtt{x}\;}\quad
& (\varepsilon+\emptyset)\cdot(x+y)^{*} && 8 \\
\xrightarrow{\;\mathtt{x}\;}\quad
& (\emptyset+\emptyset)\cdot(x+y)^{*}
  \;+\; (\varepsilon+\emptyset)\cdot(x+y)^{*} && 17 \\
\xrightarrow{\;\mathtt{x}\;}\quad
& (\emptyset+\emptyset)\cdot(x+y)^{*}
  \;+\; \bigl( (\emptyset+\emptyset)\cdot(x+y)^{*}
  \;+\; (\varepsilon+\emptyset)\cdot(x+y)^{*} \bigr) && 26
\end{aligned}
\end{equation}

To limit expression growth, 
each derivation step is followed by simplification 
using identify functions that preserve the original language and eliminate:
dead concatenations $\emptyset$ ($\mathsf{S}_{1}$), 
identity concatenations ($\mathsf{S}_{2}$),
redundant alternatives ($\mathsf{S}_{3}$),
and hold symmetrically.
\begin{equation}\label{eq:simp-identities}
\emptyset \cdot r = \emptyset \;(\mathsf{S}_{1})
\qquad
\varepsilon \cdot r = r \;(\mathsf{S}_{2})
\qquad
\emptyset + r = r \;(\mathsf{S}_{3})
\end{equation}

Applying these identities to Equation~\eqref{eq:der-4} after each step, 
returns the expression back to $(x+y)^{*}$,
keeping the size bounded regardless of input length:
\begin{equation}\label{eq:der-6}
\begin{aligned}
(\emptyset + \emptyset) \cdot (x+y)^{*} + (\varepsilon + \emptyset) \cdot (x+y)^{*}
  &= \emptyset \cdot (x+y)^{*} + \varepsilon \cdot (x+y)^{*}
  &&\mathsf{S}_{3},\ \text{twice} \\
  &= \emptyset + (x+y)^{*}
  &&\mathsf{S}_{1},\ \mathsf{S}_{2} \\
  &= (x+y)^{*}
  &&\mathsf{S}_{3}
\end{aligned}
\end{equation}

%

\paragraph{In Rust.}
The identities are implemented in \ref{fig:simplify-rust} recursively:

\begin{figure}[ht]
\small
\begin{verbatim}
pub fn simplify(r: Regex) -> Regex {
    match r {
        Regex::Seq(r, s) => match (simplify(*r), simplify(*s)) {
            (Regex::Phi, _) | (_, Regex::Phi) => Regex::Phi,
            (Regex::Eps, s) => s,
            (r, Regex::Eps) => r,
            (r, s) => Regex::seq(r, s),
        },
        Regex::Alt(r, s) => match (simplify(*r), simplify(*s)) {
            (Regex::Phi, s) => s,
            (r, Regex::Phi) => r,
            (r, s) if r == s => r,
            (r, s) => Regex::alt(r, s),
        },
        Regex::Star(r) => match simplify(*r) {
            Regex::Eps | Regex::Phi => Regex::Eps,
            r => Regex::star(r),
        },
        other => other,
    }
}
\end{verbatim}
\caption{Simplification rules: \texttt{Seq} implements
$\mathsf{S}_{1}$ and $\mathsf{S}_{2}$, 
while \texttt{Alt} implements $\mathsf{S}_{3}$ and removes duplicates. 
\texttt{Star} additionally also reduces $\varepsilon^{*}$ and $\emptyset^{*}$ 
to $\varepsilon$, since both denote $\{\varepsilon\}$.}
\label{fig:simplify-rust}
\end{figure}

The identities are implemented bottom-up, 
so every dead subexpression is removed before an expression is returned.
\texttt{simplify} takes ownership of its input, 
unlike \texttt{deriv}, which borrows and constructs. 
The two compose directly,
Together, they form the matcher's core loop, deriving and simplifying
the expression at each input symbol.

\paragraph{The matcher.}
\label{sec:derivative-matcher}
The implementation is the sequence of residuals produced 
while consuming the input. 
For $w=x_1x_2\cdots x_n$, the initial residual is $r_0=r$ 
and each subsequent residual is obtained by deriving 
with respect to the next symbol and simplifying the result:
\begin{equation}
r_0=r,
\qquad
r_i=\operatorname{simplify}(r_{i-1}\backslash x_i)
\quad (1\leq i\leq n).
\label{eq:derivative-residuals}
\end{equation}

The residual $r_i$ denotes the set of suffixes 
that complete the consumed prefix $x_1\cdots x_i$ to a word in $L(r)$. 
Since simplification preserves the language, 
each $r_i$ is equivalent to the unsimplified derivative, 
and the matcher accepts exactly when $r_n$ is nullable, so:
\begin{equation}\label{eq:deriv-accept}
w\in L(r)\iff n(r_n).
\end{equation}

Each step depends only on the current residual 
and the next symbol, so the matcher never revisits a prefix.
The cost of one step is the cost of \texttt{deriv} on the current residual, 
which is proportional to its size.
The sequence
$r_0\xrightarrow{x_1}r_1\xrightarrow{x_2}\cdots\xrightarrow{x_n}r_n$ is
thus a path through a lazily constructed DFA, whose states are residuals
and whose accepting states are the nullable ones. Only the states reached
by the input are constructed.

%

\paragraph{In Rust.}
Figure~\ref{fig:match-deriv-rust} shows the matcher built around
\texttt{deriv}, \texttt{simplify}, and \texttt{nullable}. 
It follows the mathematical definition directly, 
transforming the current residual for each input symbol 
and checking nullability once the input is consumed.

\begin{figure}[H]
\small
\begin{verbatim}
pub fn match_deriv(input: &str, r: &Regex) -> bool {
    let mut current = r.clone();
    for c in input.chars() {
        current = simplify(deriv(&current, c));
    }
    nullable(&current)
}
\end{verbatim}
\caption{\texttt{match\_deriv}: Implementing the derivative matcher. 
For each input character, 
derive the current residual and simplify it in place. 
The updated expression becomes the residual for the next iteration. 
After the input is consumed, accept if the final residual is nullable.}
\label{fig:match-deriv-rust}
\end{figure}

Figure~\ref{fig:match-deriv-rust} shows the derivative-based matcher.
Its loop implements the residual sequence 
by repeatedly deriving  and simplifying the current expression 
for each input character. 
The variable \texttt{current} holds only the latest residual, 
replacing the previous one at each iteration. 
Unlike parsing, which may require intermediate results to reconstruct a parse tree, 
Boolean matching needs only the final residual to determine acceptance.

The derivative-based matcher avoids the exponential backtracking 
of naive matching by transforming the expression 
rather than searching for decompositions. 
Simplification keeps the resulting expressions compact,
preventing the growth shown in Equation~\eqref{eq:der-growth}.

\paragraph{Worked Example: Applying the derivative-based matcher}
\label{sec:deriv-worked-example}

Apply \texttt{match\_deriv} to $r_0 = (a + ab)(b + \varepsilon)$ 
and $w = \mathtt{ab}$ with the expression written as:
\[
r_0 = \mathit{Seq}(s,\, t),
\qquad
s = a + ab,
\qquad
t = b + \varepsilon,
\]

\paragraph{Derive by $\mathtt{a}$.}
The first factor $s$ is not nullable, 
so $\mathsf{D}_{\mathrm{seq}}$ applies to the sequence $r_0$:
\[
r_0 \backslash \mathtt{a}
  = (s \backslash \mathtt{a}) \cdot t
  \qquad (\mathsf{D}_{\mathrm{seq}}).
\]
Since $s$ cannot match the empty word, 
the second factor $t$ is not touched by this derivative and appears unchanged. 
To derive $s$, the alternation rule $\mathsf{D}_{+}$ is applied to give:
\[
s \backslash \mathtt{a}
  = (a \backslash \mathtt{a}) + (ab \backslash \mathtt{a})
  \qquad (\mathsf{D}_{+}).
\]
The two summands are derived separately, each by its own rule:
\[
\begin{aligned}
a \backslash \mathtt{a}
  &= \varepsilon
  &&(\mathsf{D}_{\mathrm{lit}}), \\[2pt]
ab \backslash \mathtt{a}
  &= (a \backslash \mathtt{a}) \cdot b
   = \varepsilon \cdot b
  &&(\mathsf{D}_{\mathrm{seq}},\ \mathsf{D}_{\mathrm{lit}}).
\end{aligned}
\]
Substituting both summands into the alternation 
and the result into the outer sequence:
\[
\begin{aligned}
s \backslash \mathtt{a}
  &= \varepsilon + \varepsilon \cdot b
  &&(\mathsf{D}_{+}), \\[4pt]
r_0 \backslash \mathtt{a}
  &= (\varepsilon + \varepsilon \cdot b) \cdot t
  &&(\mathsf{D}_{\mathrm{seq}}).
\end{aligned}
\]
Then, applying the simplification rule $\mathsf{S}_{2}$ 
to the occurrence of $\varepsilon \cdot b$, gives the residual:
\[
r_1 = (\varepsilon + b) \cdot t
  \qquad (\mathsf{S}_{2}).
\]

%

\paragraph{Derive by $\mathtt{b}$.}
The residual $r_1$ is again a sequence,
but now the first factor $\varepsilon + b$ is nullable, 
so the nullable sequence rule $\mathsf{D}_{\mathrm{seq}}^{\,n}$ applies 
when deriving by $b$:
\[
r_2 = r_1 \backslash \mathtt{b}
  = \big((\varepsilon + b) \backslash \mathtt{b}\big) \cdot t
    + (t \backslash \mathtt{b})
  \qquad (\mathsf{D}_{\mathrm{seq}}^{\,n}).
\]
Since the first factor $\varepsilon + b$ is nullable, 
it can either consume the character itself, 
leaving $t$ untouched, or match $\varepsilon$ and let $t$ consume it. 
Both are possible, so $\mathsf{D}_{\mathrm{seq}}^{\,n}$ 
produces one summand for each, 
and $\mathsf{D}_{+}$ derives the first factor 
and $t$ in their respective summands:
\[
\begin{aligned}
(\varepsilon + b) \backslash \mathtt{b}
  &= (\varepsilon \backslash \mathtt{b}) + (b \backslash \mathtt{b})
   = \emptyset + \varepsilon
  &&(\mathsf{D}_{+},\ \mathsf{D}_{\varepsilon},\
           \mathsf{D}_{\mathrm{lit}}), \\[4pt]
t \backslash \mathtt{b} = (b + \varepsilon) \backslash \mathtt{b}
  &= (b \backslash \mathtt{b}) + (\varepsilon \backslash \mathtt{b})
   = \varepsilon + \emptyset
  &&(\mathsf{D}_{+},\ \mathsf{D}_{\mathrm{lit}},\
           \mathsf{D}_{\varepsilon}).
\end{aligned}
\]
Substituting both summands into the two-summand expression:
\[
r_1 \backslash \mathtt{b}
  = (\emptyset + \varepsilon) \cdot t
    + (\varepsilon + \emptyset).
\]
Applying the simplification rules $\mathsf{S}_{3}$ 
and $\mathsf{S}_{2}$ to the first summand and $\mathsf{S}_{3}$ to the second, 
gives the final residual after deriving the second character:
\[
r_2 
  = t + \varepsilon
  \qquad (\mathsf{S}_{3},\ \mathsf{S}_{2},\ \mathsf{S}_{3}).
\]

\paragraph{Acceptance.}
The residual $r_2 = (b + \varepsilon) + \varepsilon$ 
is nullable by $\mathsf{N}_{+}$ and $\mathsf{N}_{\varepsilon}$, 
so $\mathtt{ab} \in L(r_0)$.

\section{Antimirov Partial Derivatives}
\label{sec:antimirov-partial-derivatives}

The derivative of Section~\ref{sec:brzozowski-derivatives} 
combines alternative residuals into a single expression using $+$. 
Antimirov's partial derivatives instead keep them as a set of expressions,
one per strand of nondeterminism, written $pd(r,x)$~\citep{antimirov1996}.
\begin{equation}\label{eq:pd}
\begin{aligned}
pd(\emptyset, x) &= \{\} &&(\mathsf{P}_{\emptyset}) \\
pd(\varepsilon, x) &= \{\} &&(\mathsf{P}_{\varepsilon}) \\
pd(y, x) &=
  \begin{cases} \{\varepsilon\} & x = y \\ \{\} & x \neq y \end{cases}
  &&(\mathsf{P}_{\mathrm{lit}}) \\
pd(r + s, x) &= pd(r,x) \cup pd(s,x) &&(\mathsf{P}_{+}) \\
pd(r^{*}, x) &= \{\, \mathit{smartC}(r', r^{*}) \mid r' \in pd(r,x) \,\}
  &&(\mathsf{P}_{*}) \\
pd(r \cdot s, x) &=
  \begin{cases}
    \{\, \mathit{smartC}(r', s) \mid r' \in pd(r,x) \,\} \cup pd(s,x)
      & n(r) = \mathrm{true} \\
    \{\, \mathit{smartC}(r', s) \mid r' \in pd(r,x) \,\}
      & n(r) = \mathrm{false}
  \end{cases}
  &&\begin{array}{l}
    (\mathsf{P}_{\mathrm{seq}}^{\,n}) \\
    (\mathsf{P}_{\mathrm{seq}})
  \end{array}
\end{aligned}
\end{equation}

Where $\mathsf{D}_{\emptyset}$ and $\mathsf{D}_{\varepsilon}$
return $\emptyset$ as a node, $\mathsf{P}_{\emptyset}$ and
$\mathsf{P}_{\varepsilon}$ return no residual. 
A literal $y$ yields $\{\varepsilon\}$ if $x=y$ and $\{\}$ otherwise. 
Alternation unions the residual sets, 
while for $r^{*}$, each residual of $r$ is concatenated with $r^{*}$ 
to allow further iterations. 
Unlike Brzozowski derivatives, 
these alternatives are not combined with $+$ but remain separate set elements.
Concatenation branches on nullability as in $\mathsf{D}_{\mathrm{seq}}$. 
If $r$ is not nullable, each residual of $r$ is concatenated with $s$. 
If $r$ is nullable, the set also includes $\mathsf{pd}(s,x)$, 
since $r$ may match $\varepsilon$ and allow $s$ to consume $x$.
So $\mathsf{D}_{\mathrm{seq}}^{\,n}$ combines both cases with $+$,
$\mathsf{P}_{\mathrm{seq}}^{\,n}$ keeps them as separate set elements.

%

\paragraph{The smart constructor.}
The concatenation in $\mathsf{P}_{\mathrm{seq}}$ 
uses an auxiliary constructor $\mathit{smartC}$. 
Since each element of $pd(r,x)$ is a separate residual 
rather than a branch of a sum, 
$\mathit{smartC}$ is applied to each independently. 
The constructor avoids building $\varepsilon \cdot s$:
\begin{equation}\label{eq:smartc}
\mathit{smartC}(r', s) =
  \begin{cases}
    s & r' = \varepsilon \\
    r' \cdot s & \text{otherwise.}
  \end{cases}
\end{equation}

%

\paragraph{In Rust.}
Figure~\ref{fig:smart-seq-rust} implements $\mathit{smartC}$ directly, 
one arm per case of Equation~\eqref{eq:smartc}:

pub fn smart_seq(r: Regex, s: &Regex) -> Regex {
    match r {
        Regex::Eps => s.clone(),
        r => Regex::seq(r, s.clone()),
    }
}
\end{verbatim}

Figure~\ref{fig:pderiv-rust} presents the implementation of \eqref{eq:pd}, 
one arm per case.  
The \texttt{Phi}, \texttt{Eps}, and \texttt{Lit} variants implement 
$\mathsf{P}_{\emptyset}$, $\mathsf{P}_{\varepsilon}$, and $\mathsf{P}_{\mathrm{lit}}$ 
directly, returning \texttt{Vec::new()} where the equation gives $\{\}$. 
\texttt{Alt} concatenates the two child vectors, 
implementing the union of $\mathsf{P}_{+}$. 
\texttt{Star} maps \texttt{smart\_seq} over $r$'s residuals,
placing each in front of a fresh \texttt{Regex::star}, 
and the clone in \texttt{Regex::star(*r.clone())} is needed 
because the closure owns its result. 

\texttt{Seq} implements the case split directly.
The \texttt{map} applies \texttt{smart\_seq} to each residual of the left operand,
matching $\mathsf{P}_{\mathrm{seq}}$, 
while the guarded \texttt{out.extend(pderiv(s, x))} adds $pd(s,x)$ 
for $\mathsf{P}_{\mathrm{seq}}^{\,n}$.
Although the mathematical definition uses sets, 
the implementation uses \texttt{Vec<Regex>} 
throughout the recursion and defers deduplication 
to a single \texttt{HashSet} insertion at the top, 
rather than deduplicating at every \texttt{Alt} 
or \texttt{Seq} node on the way down.

Every union in \texttt{pderiv} is therefore a vector \texttt{extend}, 
not a set operation. 
Duplicate residuals reached by different strands are only merged 
once inserted into the \texttt{HashSet} 
used by the matcher below to keep the residual generation separate from deduplication.

\begin{figure}[H]
\small
\begin{verbatim}
fn pderiv(r: &Regex, x: char) -> Vec<Regex> {
    match r {
        Regex::Phi => Vec::new(),
        Regex::Eps => Vec::new(),
        Regex::Lit(c) => {
            if *c == x { vec![Regex::Eps] } else { Vec::new() }
        }
        Regex::Alt(r, s) => {
            let mut out = pderiv(r, x);
            out.extend(pderiv(s, x));
            out
        }
        Regex::Seq(r, s) => {
            let mut out: Vec<Regex> = pderiv(r, x)
                .into_iter()
                .map(|r_prime| smart_seq(r_prime, s))
                .collect();
            if nullable(r) {
                out.extend(pderiv(s, x));
            }
            out
        }
        Regex::Star(r) => {
            pderiv(r, x)
                .into_iter()
                .map(|r_prime| smart_seq(r_prime, &Regex::star(*r.clone())))
                .collect()
        }
    }
}
\end{verbatim}
\caption{\texttt{pderiv}: Implementing Equation~\eqref{eq:pd} 
one arm per case of the equation.}
\label{fig:pderiv-rust}
\end{figure}

\paragraph{Example: No growth under \boldmath$pd$\unboldmath.}
Consider $(x+y)^{*}$ against $\mathtt{xx}$ under $pd$.

$\mathsf{P}_{*}$ applies with star body $r=x+y$:
\begin{equation}\label{eq:der-15}
\begin{aligned}
pd((x+y)^{*},\mathtt{x})
  &= \{\, \mathit{smartC}(r',(x+y)^{*}) \mid r' \in pd(x+y,\mathtt{x}) \,\}
  &&\mathsf{P}_{*} \\
  &= \{\, \mathit{smartC}(r',(x+y)^{*}) \mid r' \in \{\varepsilon\} \,\}
  &&\mathsf{P}_{+},\ \mathsf{P}_{\mathrm{lit}}\ \text{twice} \\
  &= \{(x+y)^{*}\}
  &&\mathsf{SC},\ r' = \varepsilon.
\end{aligned}
\end{equation}
The set is $\{(x+y)^{*}\}$, 
so deriving by the second $\mathtt{x}$ repeats the computation, 
and the final partial derivative accepts $\varepsilon$ 
since $(x+y)^{*}$ is nullable by $\mathsf{N}_{*}$. 
So $\mathtt{xx}\in L((x+y)^{*})$.

Equation~\eqref{eq:growth-comparison} traces the derivative 
and the partial derivative on the same expression:
\begin{equation}\label{eq:growth-comparison}
\begin{aligned}
\text{Derivative (unsimplified):} &\quad
  \underbrace{(x{+}y)^{*}}_{4}
  \xrightarrow{\mathtt{x}}
  \underbrace{(\varepsilon{+}\emptyset)(x{+}y)^{*}}_{8}
  \xrightarrow{\mathtt{x}}
  \underbrace{(\emptyset{+}\emptyset)(x{+}y)^{*}{+}(\varepsilon{+}\emptyset)(x{+}y)^{*}}_{17} \\[6pt]
\text{Partial derivative:} &\quad
  \underbrace{\{(x{+}y)^{*}\}}_{4}
  \xrightarrow{\mathtt{x}}
  \underbrace{\{(x{+}y)^{*}\}}_{4}
  \xrightarrow{\mathtt{x}}
  \underbrace{\{(x{+}y)^{*}\}}_{4}
\end{aligned}
\end{equation}

The unsimplified derivative grows at every step, 
while the partial derivative stays at one element 
because $\mathsf{P}_{\emptyset}$ and $\mathsf{P}_{\varepsilon}$ 
contribute no residual, 
so there is nothing to simplify.

%

\paragraph{Finiteness.}
For a regular expression $r$, 
the number of distinct partial derivatives reachable by any input 
is bounded by $\|r\|+1$ \citep[Theorem~3.4, p.~309]{antimirov1996}. 
This is a ceiling, not a guarantee that all $\|r\|+1$ are reached.
For $(x{+}y)^{*}$, $\|r\| = 2$ the ceiling is $3$, 
yet only $(x{+}y)^{*}$ is reachable, 
since deriving by either $\mathtt{x}$ or $\mathtt{y}$ returns it unchanged.

Ordinary derivatives need equivalence classes to be finite
\citep[Theorem~4.3]{brzozowski1964}, giving $d_R \leq 2^{d_P}-1$.
Simplification removes units and redundant $\emptyset$, 
but not all equivalent forms. 
In contrast the partial-derivative bound is linear without simplification.

%

\paragraph{The matcher.}
The implementation can be summarized by the sequence of state sets
produced while consuming the input. 
For $w=x_1x_2\cdots x_n$, the initial state set is $S_0=\{r\}$, 
and each subsequent set is obtained by taking $pd$ of every residual
in the previous set and unioning the results:
\begin{equation}
S_0=\{r\},
\qquad
S_i=\bigcup_{r'\in S_{i-1}} pd(r',x_i)
\quad (1\leq i\leq n).
\label{eq:pderiv-state-set}
\end{equation}

The state set $S_i$ collects every residual reachable 
after consuming the prefix $x_1\cdots x_i$. 
Unlike the derivative matcher's single residual $r_i$, 
no element of $S_i$ grows with the input. 
The number of elements is bounded by $\|r\|+1$ as shown above. 
After the final symbol has been consumed, 
the matcher accepts when some residual in $S_n$ is nullable:
\[
w\in L(r)
\iff
\exists r_n \in S_n.\ n(r_n)=\mathrm{true}.
\]

$S_0\xrightarrow{x_1}S_1\xrightarrow{x_2}\cdots\xrightarrow{x_n}S_n$
can be viewed as a path through a lazily constructed NFA. 
Each state set represents the set of NFA states reachable 
after reading the corresponding prefix, 
and $\xrightarrow{x}$ denotes the transition obtained by taking $pd$ 
with respect to $x$ and unioning. 
Unlike an explicitly constructed NFA, 
only the states reached by the input are constructed. 
A state set is accepting exactly when it contains at least one nullable residual, 
so acceptance is determined by whether the final state set contains a nullable residual.

%

\paragraph{In Rust.}
Figure~\ref{fig:pderiv-loop-rust} implements Equation~\eqref{eq:pderiv-state-set}
with a \texttt{HashSet<Regex>},
whose \texttt{Hash} and \texttt{Eq} implementations collapse residuals
reached by different paths. 
The early return when the set empties follows from construction.
An empty set has no states to derive. 
The final \texttt{any(nullable)} checks whether some residual is nullable.
Where \texttt{match\_deriv} holds one growing \texttt{Regex}, 
\texttt{match\_pderiv} holds a set of small residuals that never need simplification.

\begin{figure}[ht]
\small
\begin{verbatim}
pub fn match_pderiv(input: &str, r: &Regex) -> bool {
    let mut states: HashSet<Regex> = HashSet::new();
    states.insert(r.clone());
    for c in input.chars() {
        let mut next: HashSet<Regex> = HashSet::new();
        for state in &states {
            next.extend(pderiv(state, c));
        }
        if next.is_empty() { return false; }
        states = next;
    }
    states.iter().any(nullable)
}
\end{verbatim}

\label{fig:pderiv-loop-rust}
\end{figure}

\paragraph{Worked Example: Applying the partial-derivative-based matcher}
\label{sec:pderiv-worked-example}

Applying \texttt{match\_pderiv} to $r_0 = (a + ab)(b + \varepsilon)$ and
$w = \mathtt{ab}$ with the expression written as:
\[
r_0 = \mathit{Seq}(s,\, t),
\qquad
s = a + ab,
\qquad
t = b + \varepsilon.
\]

\paragraph{Derive by $\mathtt{a}$.}
Since $s$ is not nullable, $t$ is untouched and $\mathsf{P}_{\mathrm{seq}}$
applies to $r_0$:
\[
S_1 = \{\, \mathit{smartC}(r',t) \mid r' \in pd(s,\mathtt{a}) \,\}
  \qquad (\mathsf{P}_{\mathrm{seq}}).
\]
The alternation rule gives the two branches of $s$ separately:
\[
\begin{aligned}
pd(a,\mathtt{a}) &= \{\varepsilon\}
  &&(\mathsf{P}_{\mathrm{lit}}), \\[2pt]
pd(ab,\mathtt{a}) &= \{\mathit{smartC}(\varepsilon,b)\} = \{b\}
  &&(\mathsf{P}_{\mathrm{seq}}),
\end{aligned}
\]
So $pd(s,\mathtt{a}) = \{\varepsilon, b\}$. Applying $\mathit{smartC}$
to each element against $t$ prepends that element to $t$, with
$\varepsilon$ absorbed so that $\varepsilon \cdot t$ is never built:
\[
S_1 = \{\, t,\ b\cdot t \,\} = \{\, b+\varepsilon,\ \ b\,(b+\varepsilon) \,\}.
\]

\paragraph{Derive by $\mathtt{b}$.}
Each state in $S_1$ is derived separately and the results unioned. 

For the first state $t = b+\varepsilon$:
\[
pd(b+\varepsilon,\mathtt{b})
  = pd(b,\mathtt{b}) \cup pd(\varepsilon,\mathtt{b})
  = \{\varepsilon\} \cup \{\}
  = \{\varepsilon\}
  \qquad (\mathsf{P}_{+},\ \mathsf{P}_{\mathrm{lit}},\
           \mathsf{P}_{\varepsilon}).
\]

For the second state $b\cdot t = b\,(b+\varepsilon)$:
\[
pd\big(b\,(b+\varepsilon),\mathtt{b}\big)
  = \{\, \mathit{smartC}(\varepsilon,\,b+\varepsilon) \,\}
  = \{b+\varepsilon\}
  \qquad (\mathsf{P}_{\mathrm{seq}}).
\]

Only the left factor $b$ is derived, as it is a non-nullable literal.
The union gives:
\[
S_2 = \{\varepsilon\} \cup \{b+\varepsilon\}
    = \{\, \varepsilon,\ \ b+\varepsilon \,\}.
\]

\paragraph{Acceptance.}
Both states in $S_2$ are nullable, $\varepsilon$ by
$\mathsf{N}_{\varepsilon}$ and $b+\varepsilon$ by $\mathsf{N}_{+}$ and
$\mathsf{N}_{\varepsilon}$, so \texttt{match\_pderiv("ab", $r_0$)}
returns \texttt{true} and $\mathtt{ab} \in L(r_0)$, agreeing with
Section~\ref{sec:deriv-worked-example}.
