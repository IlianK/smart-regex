\chapter{Derivatives and Partial Derivatives}
\label{sec:derivatives}

Chapter~\ref{sec:regular-expressions} introduced the syntax and semantics
of regular expressions. This chapter introduces three algorithms for
deciding whether $w \in L(r)$.

The first is a naive recursive matcher that follows the structure of the
regular-expression semantics. The second uses Brzozowski derivatives to
transform a regular expression as input symbols are consumed. The third
uses Antimirov's partial derivatives, representing the possible residual
expressions as a set rather than combining them into a single expression.
All three approaches are implemented in Rust. 

All three matchers \texttt{match\_naive}, \texttt{match\_deriv}, and
\texttt{match\_pderiv} share the signature
\texttt{fn(\&str, \&Regex) -> bool}, so the same expression and input can
be processed by any of them.

%

\section{Naive Matching}
\label{sec:naive-matching}

A direct way to decide whether $w \in L(r)$ is to interpret the
regular-expression semantics as recursive matching rules. The resulting
naive matcher follows the structure of the expression and searches for
possible decompositions of the input.

Let $w$ be given as an indexable sequence of characters, and let
$w[i:j]$ denote the substring beginning at position $i$ and ending
immediately before position $j$. A recursive procedure
$\operatorname{match}(w,i,j,r)$ determines whether
$w[i:j] \in L(r)$ by following the structure of $r$:

\begin{equation}
\begin{aligned}
\operatorname{match}(w,i,j,\varepsilon)
  &\iff i = j, \\[2pt]
\operatorname{match}(w,i,j,x)
  &\iff j = i+1 \land w[i] = x, \\[2pt]
\operatorname{match}(w,i,j,r+s)
  &\iff \operatorname{match}(w,i,j,r)
      \lor \operatorname{match}(w,i,j,s), \\[2pt]
\operatorname{match}(w,i,j,r\cdot s)
  &\iff \exists k \in [i,j].\,
      \operatorname{match}(w,i,k,r)
      \land
      \operatorname{match}(w,k,j,s), \\[2pt]
\operatorname{match}(w,i,j,r^{*})
  &\iff i=j
      \lor
      \exists k \in (i,j].\,
      \operatorname{match}(w,i,k,r)
      \land
      \operatorname{match}(w,k,j,r^{*}).
\end{aligned}
\label{eq:naive-matcher}
\end{equation}

Membership of the complete word $w$ is then given by
$\operatorname{match}(w,0,|w|,r)$. Each rule directly corresponds to the
semantics of the respective regular-expression construct.

The direct correspondence with the semantics comes at a cost. In
particular, the concatenation rule does not prescribe where the input
should be split. It asks whether \emph{some} split point $k$ exists such
that $r$ matches $w[i:k]$ and $s$ matches $w[k:j]$. The naive matcher
therefore searches the possible values of $k$.

%

For example, consider matching
$r\cdot s = (a\cdot a)\cdot a$ against $w[0:3]$, where
$w=\mathtt{aaa}$. Here, $r=a\cdot a$ and $s=a$, so the recursive rule
requires the matcher to consider the possible split points
$k\in\{0,1,2,3\}$:

\[
\begin{aligned}
&\underbrace{\operatorname{match}(w,0,0,a\cdot a)}_
  {\text{$a\cdot a$ against }w[0:0]=\mathtt{\epsilon}}
  \land
  \underbrace{\operatorname{match}(w,0,3,a)}_
  {\text{$a$ against }w[0:3]=\mathtt{aaa}}
\\[4pt]
{}\lor\;&
\underbrace{\operatorname{match}(w,0,1,a\cdot a)}_
  {\text{$a\cdot a$ against }w[0:1]=\mathtt{a}}
  \land
  \underbrace{\operatorname{match}(w,1,3,a)}_
  {\text{$a$ against }w[1:3]=\mathtt{aa}}
\\[4pt]
{}\lor\;&
\underbrace{\operatorname{match}(w,0,2,a\cdot a)}_
  {\text{$a\cdot a$ against }w[0:2]=\mathtt{aa}}
  \land
  \underbrace{\operatorname{match}(w,2,3,a)}_
  {\text{$a$ against }w[2:3]=\mathtt{a}}
\\[4pt]
{}\lor\;&
\underbrace{\operatorname{match}(w,0,3,a\cdot a)}_
  {\text{$a\cdot a$ against }w[0:3]=\mathtt{aaa}}
  \land
  \underbrace{\operatorname{match}(w,3,3,a)}_
  {\text{$a$ against }w[3:3]=\mathtt{\epsilon}}.
\end{aligned}
\]

The first alternative fails because $a\cdot a$ cannot match the empty
substring $w[0:0]$. The matcher therefore proceeds to $k=1$, where
$a\cdot a$ would have to match the one-character substring
$w[0:1]=\mathtt{a}$; this also fails. At $k=2$, however, the first
component receives $w[0:2]=\mathtt{aa}$ and the second receives
$w[2:3]=\mathtt{a}$, so both recursive calls succeed. The final split
$k=3$ is therefore never reached. The successful match is obtained only
after the preceding split points have been tried.

The successful alternative produces two recursive calls:

\[
\begin{aligned}
&\underbrace{\operatorname{match}(w,0,2,a\cdot a)}_
  {\text{$a\cdot a$ against }w[0:2]=\mathtt{aa}}
  \qquad\text{and}\qquad
  \underbrace{\operatorname{match}(w,2,3,a)}_
  {\text{$a$ against }w[2:3]=\mathtt{a}}.
\end{aligned}
\]

The second call succeeds immediately because the substring contains
exactly one character. The first call is itself a concatenation match,
so the same rule is applied again. This time the possible split points
are $k\in\{0,1,2\}$:

\[
\begin{aligned}
&\underbrace{\operatorname{match}(w,0,0,a)}_
  {\text{$a$ against }w[0:0]=\mathtt{\epsilon}}
  \land
  \underbrace{\operatorname{match}(w,0,2,a)}_
  {\text{$a$ against }w[0:2]=\mathtt{aa}}
\\[4pt]
{}\lor\;&
\underbrace{\operatorname{match}(w,0,1,a)}_
  {\text{$a$ against }w[0:1]=\mathtt{a}}
  \land
  \underbrace{\operatorname{match}(w,1,2,a)}_
  {\text{$a$ against }w[1:2]=\mathtt{a}}
\\[4pt]
{}\lor\;&
\underbrace{\operatorname{match}(w,0,2,a)}_
  {\text{$a$ against }w[0:2]=\mathtt{aa}}
  \land
  \underbrace{\operatorname{match}(w,2,2,a)}_
  {\text{$a$ against }w[2:2]=\mathtt{\epsilon}}.
\end{aligned}
\]

Here, $k=0$ fails because the first $a$ cannot match the empty
substring. The split $k=1$ succeeds because the two $a$ expressions
match $w[0:1]=\mathtt{a}$ and $w[1:2]=\mathtt{a}$, respectively. The
split $k=2$ is therefore not reached. The original match consequently
succeeds through the nested sequence of split points $k=2$ and $k=1$.

This shows that concatenation can cause the matcher to explore
several split points recursively before finding a successful
decomposition. Each recursive call repeats the same search on a
smaller substring.

%

\paragraph{In Rust.}
The specification's $\operatorname{match}(w,i,j,r)$ becomes a recursive
helper over an indexable word,

\begin{verbatim}
fn match_naive_range(word: &[char], i: usize, j: usize,
                     r: &Regex) -> bool
\end{verbatim}

with the public entry point collecting the input once and calling it
over the whole word:

\begin{verbatim}
pub fn match_naive(input: &str, r: &Regex) -> bool {
    let chars: Vec<char> = input.chars().collect();
    let len = chars.len();
    match_naive_range(&chars, 0, len, r)
}
\end{verbatim}

The two rules that require a search become the two arms shown in
Figure~\ref{fig:match-naive-rust}.

\begin{figure}[ht]
\begin{verbatim}
Regex::Seq(r, s) => {
    (i..=j).any(|k| {
        match_naive_range(word, i, k, r)
            && match_naive_range(word, k, j, s)
    })
}
Regex::Star(r) => {
    i == j
    || (i + 1..=j).any(|k| {
        match_naive_range(word, i, k, r)
            && match_naive_range(word, k, j, &Regex::star(*r.clone()))
    })
}
\end{verbatim}
\caption{The searching arms of the naive matcher. The $\exists k$ of
Equation~\eqref{eq:naive-matcher} becomes a range and
\texttt{any}, which stops at the first $k$ that succeeds.}
\label{fig:match-naive-rust}
\end{figure}

The existential quantifier of Equation~\eqref{eq:naive-matcher} becomes a
range and \texttt{any}, which short-circuits at the first successful
$k$. Thus, the worked example above stops once $k=2$ is found. The
interval bounds correspond directly to the specification: concatenation
searches \texttt{(i..=j)}, matching $\exists k \in [i,j]$, while star
searches \texttt{(i + 1..=j)}, matching $\exists k \in (i,j]$. Excluding
$k=i$ prevents the recursive call from considering the same interval
again when $r$ matches the empty substring.

The matcher indexes
\texttt{\&[char]} rather than \texttt{\&str}, because Rust strings are
UTF-8 and cannot be indexed directly by character position. The input is
therefore collected into a \texttt{Vec<char>} once at the entry point
above, and addressed by position from then on.
The star arm also reconstructs the expression with
\texttt{Regex::star(*r.clone())} on each recursive call, since the
recursive call requires an owned \texttt{Regex}. Each recursive
iteration therefore clones the star body.

Although inefficient, this matcher is useful as a reference
implementation because it follows the regular-expression semantics
without any intermediate transformation.

%

The derivative approach takes a different approach.
Rather than searching for a decomposition of $w$ while keeping $r$ fixed,
it transforms $r$ as each character of $w$ is consumed. The resulting
expression describes the language that can still match the remaining
suffix.

%

\section{Brzozowski Derivatives}
\label{sec:brzozowski-derivatives}

Brzozowski's derivative of $r$ with respect to a symbol $x$, written
$r \backslash x$, is the expression describing exactly what remains of
$r$'s language after consuming the leading symbol $x$ of a word
$w \in L(r)$ \citep{brzozowski1964}:

\begin{equation}\label{eq:der-23}
L(r \backslash x) \;=\; \{\, w \mid xw \in L(r) \,\}.
\end{equation}

For $w = x_1x_2\cdots x_n$, consume one symbol at a time
by repeatedly taking derivatives:


\[
r,\quad
r\backslash x_1,\quad
(r\backslash x_1)\backslash x_2,\quad \ldots
\]

After all symbols have been consumed, the remaining input is
$\varepsilon$. Thus, the resulting expression must accept $\varepsilon$
for the original word to belong to $L(r)$. This is the
question of whether the expression is \emph{nullable}.
Let $n(r)$ be true exactly when $\varepsilon \in L(r)$:

\begin{equation}\label{eq:nullability}
\begin{aligned}
n(\emptyset) &= \mathrm{false} &&(\mathsf{N}_{\emptyset}) &
n(r + s) &= n(r) \lor n(s) &&(\mathsf{N}_{+}) \\
n(\varepsilon) &= \mathrm{true} &&(\mathsf{N}_{\varepsilon}) &
n(r \cdot s) &= n(r) \land n(s) &&(\mathsf{N}_{\mathrm{seq}}) \\
n(x) &= \mathrm{false} &&(\mathsf{N}_{\mathrm{lit}}) &
n(r^{*}) &= \mathrm{true} &&(\mathsf{N}_{*})
\end{aligned}
\end{equation}

The empty language $\emptyset$ is not nullable because it contains no
words, including $\varepsilon$, while a literal cannot match the empty
word. $\varepsilon$ and $r^{*}$ always match $\varepsilon$.
An alternation is nullable when either branch is nullable, and a
concatenation when both components are.

%

The derivative rules specify the expression that remains after consuming $x$:

\begin{equation}\label{eq:derivative}
\begin{aligned}
\emptyset \backslash x &= \emptyset &&(\mathsf{D}_{\emptyset}) \\
\varepsilon \backslash x &= \emptyset &&(\mathsf{D}_{\varepsilon}) \\
y \backslash x &=
  \begin{cases}
    \varepsilon & x = y \\
    \emptyset & x \neq y
  \end{cases}
  &&(\mathsf{D}_{\mathrm{lit}}) \\
(r + s) \backslash x
  &= (r \backslash x) + (s \backslash x)
  &&(\mathsf{D}_{+}) \\
r^{*} \backslash x
  &= (r \backslash x) \cdot r^{*}
  &&(\mathsf{D}_{*}) \\
(r \cdot s) \backslash x
  &=
  \begin{cases}
    (r \backslash x) \cdot s + s \backslash x
      & n(r) = \mathrm{true} \\
    (r \backslash x) \cdot s
      & n(r) = \mathrm{false}
  \end{cases}
  &&\begin{array}{l}
    (\mathsf{D}_{\mathrm{seq}}^{\,n}) \\
    (\mathsf{D}_{\mathrm{seq}})
  \end{array}
\end{aligned}
\end{equation}

The empty language contains no words, so it cannot match a word beginning
with $x$ and $\emptyset \backslash x = \emptyset$. Likewise,
$\varepsilon$ contains no symbol to consume, so
$\varepsilon \backslash x = \emptyset$. For a literal $y$, consuming
$x$ leaves $\varepsilon$ when $x=y$ and no possible match otherwise.
For $r+s$, the symbol may come from either alternative, so both
derivatives are preserved. For $r^{*}$, the symbol is consumed
by one occurrence of $r$, after which $r^{*}$ may still match the remainder.

Concatenation is the only derivative rule that depends on nullability. 
If $r$ is not nullable, $r$ must consume the leading $x$, leaving
$r\backslash x$ as the remainder of $r$ while $s$ remains untouched.
If $r$ is nullable, it may either consume $x$, as in the non-nullable case, 
giving $(r\backslash x)\cdot s$, 
or $r$ matches $\varepsilon$ and is finished, so $s$ consumes $x$ and leaves $s\backslash x$.
Hence the nullable case produces the alternation $(r\backslash x)\cdot s + s\backslash x$.

%

\paragraph{Why the case split.}
Brzozowski's original definition wrote the concatenation case as

\begin{equation}\label{eq:brzozowski-seq}
x^{-1}(r \cdot t) = (x^{-1}r) \cdot t + o(r) \cdot x^{-1}t,
\end{equation}

in the notation Antimirov uses, where $x^{-1}r$ is the derivative
of $r$ by $x$ and $o(r)$ is the constant part of $r$, equal to
$\varepsilon$ when $r$ is nullable and $\emptyset$ otherwise.
Antimirov observed that deriving $(x+y)^{*}$ by $x$, then $xx$,
then $xxx$, and so on under this rule gives ``an infinite sequence of
regular terms non-equivalent modulo $\mathcal{E}(ACI)$''
\citep[Remark~1.3, p.~298]{antimirov1996}, and to restore finiteness,
replaces it with his following \citep[Definition~1.1, Eq.~(21), p.~297]{antimirov1996}:

\begin{equation}\label{eq:antimirov-seq}
x^{-1}(r \cdot t) =
  \textbf{if}\ \, o(r) = 0\ \, \textbf{then}\ \, (x^{-1}r) \cdot t
  \ \, \textbf{else}\ \, (x^{-1}r) \cdot t + x^{-1}t\ \, \textbf{fi}
\end{equation}

This is the same rule as ~\eqref{eq:derivative}: $x^{-1}r$ is written $r\backslash x$
there and $t$ is written $s$, while $o(r)=0$ is the non-nullable case
$n(r)=\mathrm{false}$. Its two branches are therefore
$\mathsf{D}_{\mathrm{seq}}$ and $\mathsf{D}_{\mathrm{seq}}^{\,n}$.

%

\paragraph{Worked example: single-symbol matching.}
Consider $x^{*}$ against the word $\mathtt{xx}$. Writing
$r \xrightarrow{x} r \backslash x$ for one derivative step,

\emph{Step 1.} The expression is a star, so $\mathsf{D}_{*}$ applies with
body $r = x$:

\begin{equation}\label{eq:der-3}
\begin{aligned}
x^{*} \backslash \mathtt{x}
  &= (x \backslash \mathtt{x}) \cdot x^{*}
  &&\mathsf{D}_{*},\ r = x \\
  &= \varepsilon \cdot x^{*}
  &&\mathsf{D}_{\mathrm{lit}},\ \text{since } \mathtt{x} = x
\end{aligned}
\end{equation}

\emph{Step 2.} The expression is now the concatenation
$\varepsilon \cdot x^{*}$, and deriving it consumes the second
$\mathtt{x}$. The result is an alternation because
$\mathsf{D}_{\mathrm{seq}}^{\,n}$ applies with $r = \varepsilon$ and
$s = x^{*}$, its nullable case being selected since
$n(r) = n(\varepsilon) = \mathrm{true}$ by $\mathsf{N}_{\varepsilon}$:

\begin{equation}\label{eq:der-4}
\begin{aligned}
(\varepsilon \cdot x^{*}) \backslash \mathtt{x}
  &= (\varepsilon \backslash \mathtt{x}) \cdot x^{*}
     + x^{*} \backslash \mathtt{x}
  &&\mathsf{D}_{\mathrm{seq}}^{\,n},\ r = \varepsilon,\ s = x^{*} \\
  &= \emptyset \cdot x^{*}
     + x^{*} \backslash \mathtt{x}
  &&\mathsf{D}_{\varepsilon} \\
  &= \emptyset \cdot x^{*}
     + (x \backslash \mathtt{x}) \cdot x^{*}
  &&\mathsf{D}_{*},\ r = x \\
  &= \emptyset \cdot x^{*}
     + \varepsilon \cdot x^{*}
  &&\mathsf{D}_{\mathrm{lit}}
\end{aligned}
\end{equation}

After both symbols are consumed, we check whether the result is nullable:

\begin{equation}\label{eq:der-5}
\begin{aligned}
n(\emptyset \cdot x^{*} + \varepsilon \cdot x^{*})
&= n(\emptyset \cdot x^{*}) \lor n(\varepsilon \cdot x^{*})
   &&\mathsf{N}_{+},\ r = \emptyset \cdot x^{*},\ s = \varepsilon \cdot x^{*} \\
&= (n(\emptyset) \land n(x^{*})) \lor
   (n(\varepsilon) \land n(x^{*}))
   &&\mathsf{N}_{\mathrm{seq}},\ \text{twice} \\
&= (\mathrm{false} \land \mathrm{true}) \lor
   (\mathrm{true} \land \mathrm{true})
   &&\mathsf{N}_{\emptyset},\ \mathsf{N}_{*},\ \mathsf{N}_{\varepsilon} \\
&= \mathrm{true}.
\end{aligned}
\end{equation}

Thus $x^{*}$ matches $\mathtt{xx}$.

%

\paragraph{Simplification.}
Every nullable concatenation makes
$\mathsf{D}_{\mathrm{seq}}^{\,n}$ introduce an alternation, and each
alternation carries a copy of a subexpression that the next
derivative step will carry further. Nothing in
Equation~\eqref{eq:derivative} bounds this, so expressions are simplified
after each derivative step, using identities that preserve the denoted
language:

\begin{equation}\label{eq:simp-identities}
\begin{aligned}
\emptyset \cdot r &= \emptyset &&(\mathsf{S}_{1}) \\
\varepsilon \cdot r &= r       &&(\mathsf{S}_{2}) \\
\emptyset + r &= r             &&(\mathsf{S}_{3}) \\
r + r &= r                     &&(\mathsf{S}_{4})
\end{aligned}
\end{equation}

$\mathsf{S}_{1}$ to $\mathsf{S}_{3}$ remove units $\emptyset$ and
$\varepsilon$ wherever a derivative step has left one behind, and each
holds equally with the unit on the right.
$\mathsf{S}_{4}$ collapses two
syntactically identical summands into one, which is what keeps repeated
alternations from doubling. The implementation applies all four
recursively over the expression tree, matching on both sides, and
additionally reduces $\varepsilon^{*}$ and $\emptyset^{*}$ to
$\varepsilon$; Figure~\ref{fig:simplify-rust} below gives it in full. 
Applying them to Equation~\eqref{eq:der-4}:

\begin{equation}\label{eq:der-6}
\begin{aligned}
\emptyset \cdot x^{*} + \varepsilon \cdot x^{*}
  &= \emptyset + \varepsilon \cdot x^{*}
  &&\mathsf{S}_{1},\ \emptyset \cdot x^{*} = \emptyset \\
  &= \varepsilon \cdot x^{*}
  &&\mathsf{S}_{3},\ \emptyset + \varepsilon \cdot x^{*}
     = \varepsilon \cdot x^{*} \\
  &= x^{*}
  &&\mathsf{S}_{2},\ \varepsilon \cdot x^{*} = x^{*}
\end{aligned}
\end{equation}

The case split of Equation~\eqref{eq:antimirov-seq} repaired the
finiteness result that Equation~\eqref{eq:brzozowski-seq} had broken, but
only up to the ACI-equivalence named in the quotation above, which
\citet[Section~1.1, p.~293]{antimirov1996} defines. It does not prevent
expressions from growing syntactically. This can be seen by repeatedly
deriving Antimirov's example $(x+y)^{*}$ by the same symbol
$\mathtt{x}$, without simplifying between steps:

\begin{equation}\label{eq:der-growth}
\begin{aligned}
& (x+y)^{*} && 4 \\
\xrightarrow{\;\mathtt{x}\;}\quad
& (\varepsilon+\emptyset)\cdot(x+y)^{*} && 8 \\
\xrightarrow{\;\mathtt{x}\;}\quad
& (\emptyset+\emptyset)\cdot(x+y)^{*}
  \;+\; (\varepsilon+\emptyset)\cdot(x+y)^{*} && 17 \\
\xrightarrow{\;\mathtt{x}\;}\quad
& (\emptyset+\emptyset)\cdot(x+y)^{*}
  \;+\; \bigl( (\emptyset+\emptyset)\cdot(x+y)^{*}
  \;+\; (\varepsilon+\emptyset)\cdot(x+y)^{*} \bigr) && 26
\end{aligned}
\end{equation}

The starting expression has four nodes: a star, an alternation and two
literals. The first derivative places it behind a concatenation with
$(\varepsilon+\emptyset)$, adding a concatenation, an alternation and two
units, so $4 + 4 = 8$. The second is an alternation of two eight-node
expressions of that shape, so $1 + 8 + 8 = 17$, and the third has the
entire second as its right operand, so $1 + 8 + 17 = 26$. Each step from
the second onwards adds exactly nine nodes, one alternation and one
eight-node summand.

Those nine nodes are dead every time.
$\mathsf{D}_{\mathrm{seq}}^{\,n}$ fires at each step because the left
factor is nullable, and the summand it adds,
$(\emptyset+\emptyset)\cdot(x+y)^{*}$, can consume nothing, since
$\emptyset$ matches no symbol. It derives to itself from then on while a
fresh one joins at every step, so only the rightmost summand is ever
live.

The identities remove exactly this. $\mathsf{S}_{3}$ reduces
$\varepsilon+\emptyset$ to $\varepsilon$ and $\mathsf{S}_{2}$ reduces
$\varepsilon\cdot(x+y)^{*}$ to $(x+y)^{*}$, so the first derivative
collapses back to the expression it started from. Under ``derive by
$\mathtt{x}$, then simplify'', $(x+y)^{*}$ is a fixed point and the size
stays at four at every step.

%

\paragraph{Worked example: \boldmath$r_{01} = (0+1)^{*} \cdot 0 \cdot 1$\unboldmath.}
Recall $r_{01}$ from Section~\ref{sec:regex-syntax}. It is left-associated
as $\big((0+1)^{*}\cdot0\big)\cdot1$, so the outer operands are
$r=(0+1)^{*}\cdot0$ and $s=1$. We derive against
$w=\mathtt{101}$ one symbol at a time.

\begin{enumerate}
  \item \textbf{Derive by $\mathtt{1}$.}
  At the outer node, $r = (0+1)^{*} \cdot 0$ and $s = 1$. This $r$ is
  not nullable:
  \[
  n\big((0+1)^{*} \cdot 0\big)
  = \mathrm{true} \land \mathrm{false}
  = \mathrm{false},
  \]
  by $\mathsf{N}_{\mathrm{seq}}$, $\mathsf{N}_{*}$ and
  $\mathsf{N}_{\mathrm{lit}}$. Thus $\mathsf{D}_{\mathrm{seq}}$ applies
  without a second summand:
  \[
  r_{01} \backslash \mathtt{1}
  = \big(((0+1)^{*} \cdot 0) \backslash \mathtt{1}\big) \cdot 1.
  \]
  At the middle node, the left operand $(0+1)^{*}$ is nullable, so
  $\mathsf{D}_{\mathrm{seq}}^{\,n}$ applies. First,
  \begin{equation}\label{eq:der-9}
  \begin{aligned}
  (0+1)^{*} \backslash \mathtt{1}
    &= \big((0+1)\backslash\mathtt{1}\big)\cdot(0+1)^{*}
    &&\mathsf{D}_{*} \\
    &= \big((0\backslash\mathtt{1})+(1\backslash\mathtt{1})\big)
       \cdot(0+1)^{*}
    &&\mathsf{D}_{+} \\
    &= (\emptyset+\varepsilon)\cdot(0+1)^{*}
    &&\mathsf{D}_{\mathrm{lit}} \\
    &= (0+1)^{*}
    &&\mathsf{S}_{3},\ \mathsf{S}_{2}.
  \end{aligned}
  \end{equation}
  Hence
  \begin{equation}\label{eq:der-10}
  \begin{aligned}
  ((0+1)^{*}\cdot0)\backslash\mathtt{1}
    &= (0+1)^{*}\cdot0 + (0\backslash\mathtt{1})
    &&\mathsf{D}_{\mathrm{seq}}^{\,n} \\
    &= (0+1)^{*}\cdot0+\emptyset
    &&\mathsf{D}_{\mathrm{lit}} \\
    &= (0+1)^{*}\cdot0
    &&\mathsf{S}_{3}.
  \end{aligned}
  \end{equation}
  Substituting back into the outer node gives
  \begin{equation}\label{eq:der-24}
  r_{01}\backslash\mathtt{1}
  = \big((0+1)^{*}\cdot0\big)\cdot1
  = r_{01}.
  \end{equation}
  Thus a $\mathtt{1}$ not yet part of the final $\mathtt{01}$ is absorbed
  by the leading star.

  \item \textbf{Derive by $\mathtt{0}$.}
  The expression is unchanged. Again,
  $(0+1)^{*}\backslash\mathtt{0}$ simplifies to $(0+1)^{*}$, but now
  the second summand at the middle node survives:
  \begin{equation}\label{eq:der-11}
  \begin{aligned}
  ((0+1)^{*}\cdot0)\backslash\mathtt{0}
    &= (0+1)^{*}\cdot0 + (0\backslash\mathtt{0})
    &&\mathsf{D}_{\mathrm{seq}}^{\,n} \\
    &= (0+1)^{*}\cdot0+\varepsilon
    &&\mathsf{D}_{\mathrm{lit}}.
  \end{aligned}
  \end{equation}
  No simplification applies. The outer node is still non-nullable, so
  \begin{equation}\label{eq:der-25}
  r_{01}\backslash\mathtt{1}\backslash\mathtt{0}
  = \big((0+1)^{*}\cdot0+\varepsilon\big)\cdot1.
  \end{equation}
  After $\mathtt{10}$, either the trailing $\mathtt{01}$ is still owed
  in full, represented by $(0+1)^{*}\cdot0$, or the consumed
  $\mathtt{0}$ was already its first symbol, represented by $\varepsilon$.

  \item \textbf{Derive by $\mathtt{1}$.}
  The outer binding has now changed. The left operand is
  $(0+1)^{*}\cdot0+\varepsilon$, which is nullable by
  $\mathsf{N}_{+}$ and $\mathsf{N}_{\varepsilon}$. So
  $\mathsf{D}_{\mathrm{seq}}^{\,n}$ applies and contributes the second
  summand $1\backslash\mathtt{1}=\varepsilon$. For the first summand,
  $\mathsf{D}_{+}$ applies, reusing the result from step~1:
  \begin{equation}\label{eq:der-13}
  \begin{aligned}
  ((0+1)^{*}\cdot0+\varepsilon)\backslash\mathtt{1}
    &= ((0+1)^{*}\cdot0)\backslash\mathtt{1}
       +(\varepsilon\backslash\mathtt{1})
    &&\mathsf{D}_{+} \\
    &= (0+1)^{*}\cdot0+\emptyset
    &&\text{step~1; }\mathsf{D}_{\varepsilon} \\
    &= (0+1)^{*}\cdot0
    &&\mathsf{S}_{3}.
  \end{aligned}
  \end{equation}
  Therefore
  \begin{equation}\label{eq:der-26}
  r_{01}\backslash\mathtt{1}\backslash\mathtt{0}\backslash\mathtt{1}
  = \big((0+1)^{*}\cdot0\big)\cdot1+\varepsilon
  = r_{01}+\varepsilon.
  \end{equation}
\end{enumerate}

The final expression is nullable by $\mathsf{N}_{+}$ and
$\mathsf{N}_{\varepsilon}$, so $\mathtt{101}\in L(r_{01})$. The
$\varepsilon$ summand witnesses that the match is complete.

For comparison, $w=\mathtt{10}$ leaves
$\big((0+1)^{*}\cdot0+\varepsilon\big)\cdot1$. Neither branch is
nullable: $(0+1)^{*}\cdot0$ still requires a $0$, while
$\varepsilon\cdot1$ still requires a $1$. Hence
$\mathtt{10}\notin L(r_{01})$.

\paragraph{In Rust.}
The nullability and derivative rules are transcribed one
\texttt{Regex} variant at a time. The \texttt{nullable} function
implements Equation~\eqref{eq:nullability}, while
Figure~\ref{fig:deriv-rust} shows the concatenation case of the
derivative, where nullability determines whether the second term is
included, together with the matcher that applies the derivatives.

\begin{figure}[ht]
\begin{verbatim}
pub fn deriv(r: &Regex, x: char) -> Regex {
    match r {
        // ...
        Regex::Seq(r1, r2) => {
            if nullable(r1) {
                let dr1 = Regex::seq(deriv(r1, x), *r2.clone());
                Regex::alt(dr1, deriv(r2, x))
            } else {
                Regex::seq(deriv(r1, x), *r2.clone())
            }
        }
        // ...
    }
}

pub fn match_deriv(input: &str, r: &Regex) -> bool {
    let mut current = r.clone();
    for c in input.chars() {
        current = simplify(deriv(&current, c));
    }
    nullable(&current)
}
\end{verbatim}

repeatedly derives and simplifies the current residual.}
\label{fig:deriv-rust}
\end{figure}

The \texttt{if nullable(r1)} implements the case split of
Equation~\eqref{eq:derivative}, with branches
$\mathsf{D}_{\mathrm{seq}}^{\,n}$ and $\mathsf{D}_{\mathrm{seq}}$.
The expression \texttt{*r2.clone()} copies the right operand, which
appears unchanged in both branches; the nullable branch additionally
derives it for the second term. Repeated derivative construction
therefore reproduces these subexpressions, producing the growth
described by Equation~\eqref{eq:der-growth}.

The simplification identities are implemented recursively in the same
structural manner. Figure~\ref{fig:simplify-rust} shows the complete
simplifier.

\begin{figure}[ht]
\begin{verbatim}
pub fn simplify(r: Regex) -> Regex {
    match r {
        Regex::Seq(r, s) => {
            let r = simplify(*r);
            let s = simplify(*s);
            match (&r, &s) {
                (Regex::Phi, _) | (_, Regex::Phi) => Regex::Phi,
                (Regex::Eps, _) => s,
                (_, Regex::Eps) => r,
                _ => Regex::seq(r, s),
            }
        }
        Regex::Alt(r, s) => {
            let r = simplify(*r);
            let s = simplify(*s);
            match (&r, &s) {
                (Regex::Phi, _) => s,
                (_, Regex::Phi) => r,
                _ if r == s => r,
                _ => Regex::alt(r, s),
            }
        }
        Regex::Star(r) => match simplify(*r) {
            Regex::Eps | Regex::Phi => Regex::Eps,
            r => Regex::star(r),
        },
        other => other,
    }
}
\end{verbatim}
\caption{Implementation of the simplification rules in
Equation~\eqref{eq:simp-identities}.}
\label{fig:simplify-rust}
\end{figure}

Each inner arm implements an identity from
Equation~\eqref{eq:simp-identities}; the guard \texttt{\_ if r == s}
implements $\mathsf{S}_{4}$ by structural equality via
\texttt{PartialEq} (Section~\ref{sec:regex-rust-implementation}).
Thus only syntactically identical summands are collapsed, while the
recursive calls apply the identities bottom-up.

%

The ownership distinction between the two functions is visible in
their composition:
\begin{verbatim}
current = simplify(deriv(&current, c));
\end{verbatim}
The function \texttt{deriv} borrows its input and constructs a new
expression, whereas \texttt{simplify} takes ownership of that result.
It can therefore return simplified subexpressions directly, as in
\texttt{(Regex::Eps, \_) => s}, without copying them. The matcher
maintains one current residual, replacing it after each input symbol
and simplifying it before the next derivative.

The implementation can be summarized by the sequence of residual
expressions produced while consuming the input. For
$w=x_1x_2\cdots x_n$, the initial residual is $r_0=r$, and each
subsequent residual is obtained by deriving with respect to the next
symbol and simplifying the result:
\begin{equation}
r_0=r,
\qquad
r_i=\operatorname{simplify}(r_{i-1}\backslash x_i)
\quad (1\leq i\leq n).
\label{eq:derivative-residuals}
\end{equation}
After the final symbol has been consumed, the matcher accepts exactly
when the remaining residual is nullable:
\[
w\in L(r)
\iff
n(r_n)=\mathrm{true}.
\]

Thus
$r_0\xrightarrow{x_1}r_1\xrightarrow{x_2}\cdots\xrightarrow{x_n}r_n$
can be viewed as a path through a lazily constructed DFA: each residual
expression represents a state, and
$\xrightarrow{x}$ denotes the transition obtained by taking the
derivative with respect to $x$. Acceptance is determined by whether the
final residual is nullable.

\section{Antimirov Partial Derivatives}
\label{sec:antimirov-partial-derivatives}

The derivative of Section~\ref{sec:brzozowski-derivatives} combines
alternative residuals into a single expression using $+$. Antimirov's
partial derivatives instead keep them as a \emph{set} of expressions,
one per strand of nondeterminism \citep{antimirov1996}. Writing
$pd(r,x)$ for this set,

\begin{equation}\label{eq:pd}
\begin{aligned}
pd(\emptyset, x) &= \{\} &&(\mathsf{P}_{\emptyset}) \\
pd(\varepsilon, x) &= \{\} &&(\mathsf{P}_{\varepsilon}) \\
pd(y, x) &=
  \begin{cases} \{\varepsilon\} & x = y \\ \{\} & x \neq y \end{cases}
  &&(\mathsf{P}_{\mathrm{lit}}) \\
pd(r + s, x) &= pd(r,x) \cup pd(s,x) &&(\mathsf{P}_{+}) \\
pd(r^{*}, x) &= \{\, \mathit{smartC}(r', r^{*}) \mid r' \in pd(r,x) \,\}
  &&(\mathsf{P}_{*}) \\
pd(r \cdot s, x) &=
  \begin{cases}
    \{\, \mathit{smartC}(r', s) \mid r' \in pd(r,x) \,\} \cup pd(s,x)
      & n(r) = \mathrm{true} \\
    \{\, \mathit{smartC}(r', s) \mid r' \in pd(r,x) \,\}
      & n(r) = \mathrm{false}
  \end{cases}
  &&\begin{array}{l}
    (\mathsf{P}_{\mathrm{seq}}^{\,n}) \\
    (\mathsf{P}_{\mathrm{seq}})
  \end{array}
\end{aligned}
\end{equation}

Neither $\emptyset$ nor $\varepsilon$ has a symbol to consume, so both
give the empty set. This is already a difference worth noting:
$\mathsf{D}_{\emptyset}$ and $\mathsf{D}_{\varepsilon}$ returned the
expression $\emptyset$, which denotes the empty language but is still a
node in the result, while $\mathsf{P}_{\emptyset}$ and
$\mathsf{P}_{\varepsilon}$ return no residual at all. For a literal $y$,
consuming $x$ leaves $\{\varepsilon\}$ when $x = y$ and nothing
otherwise. For $r+s$ the symbol may come from either alternative, so the
two sets are unioned. For $r^{*}$ the symbol is consumed by one iteration
of $r$, and each residual of that iteration is placed in front of $r^{*}$
so that the star may continue.

Concatenation depends on nullability for exactly the reason
$\mathsf{D}_{\mathrm{seq}}$ did. If $r$ is not nullable it must consume
the $x$, and each of its residuals is placed in front of an untouched
$s$. If $r$ is nullable it may instead contribute nothing, in which case
$s$ consumes the $x$ and $pd(s,x)$ joins the set. The difference from
Section~\ref{sec:brzozowski-derivatives} is that
$\mathsf{D}_{\mathrm{seq}}^{\,n}$ joined them with $+$ inside
one expression, while $\mathsf{P}_{\mathrm{seq}}^{\,n}$ keeps them as two
elements of one set.

%

\paragraph{The smart constructor.}
The concatenation in the $\mathsf{P}_{\mathrm{seq}}$ rules is handled by
the constructor $\mathit{smartC}$, written as $\mathsf{SC}$

\begin{equation}\label{eq:smartc}
\mathit{smartC}(r', s) =
  \begin{cases}
    s & r' = \varepsilon \\
    r' \cdot s & \text{otherwise}
  \end{cases}
\end{equation}

The constructor accounts for the case where the consumed symbol
completes the left-hand expression. If $r' = \varepsilon$, there is
nothing left to concatenate with $s$, so the residual is simply $s$.
Otherwise, the residual $r'$ remains in front of $s$. Thus
$\mathit{smartC}$ expresses the concatenation rule without introducing
the redundant expression $\varepsilon \cdot s$.

A set element represents one possible residual
rather than one branch of an explicit sum. When several alternatives
can consume the same symbol, the alternatives therefore remain as
separate elements of the set. Concatenation is then applied to each
surviving residual independently. If one of those residuals is
$\varepsilon$, that particular strand has finished the left operand and
continues directly with $s$, while the other strands may still retain a
non-empty residual in front of $s$.


%

\paragraph{Worked example: single-symbol matching.}
Consider $x^{*}$ against $\mathtt{xx}$ again, this time under $pd$.
The partial derivative of the literal $x$ with respect to
$\mathtt{x}$ is $\{\varepsilon\}$, which the star rule then places in
front of $x^{*}$ using $\mathit{smartC}$:

\begin{equation}\label{eq:der-15}
\begin{aligned}
pd(x^{*},\mathtt{x})
  &= \{\, \mathit{smartC}(r',x^{*}) \mid r' \in pd(x,\mathtt{x}) \,\}
  &&\mathsf{P}_{*},\ \text{star body } r = x \\
  &= \{\, \mathit{smartC}(r',x^{*}) \mid r' \in \{\varepsilon\} \,\}
  &&\mathsf{P}_{\mathrm{lit}},\ \text{since } \mathtt{x} = x \\
  &= \{\mathit{smartC}(\varepsilon,x^{*})\} \\
  &= \{x^{*}\}
  &&\mathsf{SC},\ r' = \varepsilon,\ s = x^{*}.
\end{aligned}
\end{equation}

The result is again $\{x^{*}\}$, so deriving by the second
$\mathtt{x}$ produces the same set:
\[
pd(x^{*},\mathtt{x},\mathtt{x}) = \{x^{*}\}.
\]
The remaining residual $x^{*}$ is nullable, and therefore
$\mathtt{xx} \in L(x^{*})$. Thus the partial-derivative computation
reaches the same result as the Brzozowski derivative computation, while
keeping the residual as a set throughout.

\paragraph{Why no simplification is needed.}
The partial-derivative rules avoid the redundant expressions that
required simplification in the Brzozowski computation. In particular,
$\mathsf{P}_{\emptyset}$ and $\mathsf{P}_{\varepsilon}$ produce no
residual at all, while $\mathit{smartC}$ returns $s$ directly when the
left residual is $\varepsilon$. Thus the computation never constructs
$\emptyset \cdot x^{*}$ or $\varepsilon \cdot x^{*}$ in the first
place, so the simplification identities of
Section~\ref{sec:brzozowski-derivatives} are not needed after a $pd$
step. The partial-derivative representation therefore removes these
redundant cases at the point where residuals are constructed, rather
than constructing them first and simplifying them afterwards.

This also illustrates the different roles of simplification in the two
constructions. A Brzozowski derivative produces one regular expression
that may contain syntactically redundant structure, whereas a partial
derivative produces a set whose elements are already the individual
residual alternatives. The set itself supplies the separation that an
explicit $+$ supplied in the ordinary derivative. The next example
shows this distinction in a case where more than one residual survives.

%

\paragraph{Worked example: \boldmath$r_{01} = (0+1)^{*} \cdot 0 \cdot 1$\unboldmath.}
Derive $r_{01}$ against $w = \mathtt{101}$, tracking the residual set.
The concatenations bind as in Section~\ref{sec:brzozowski-derivatives},
with $(r,s)=((0+1)^{*}\cdot0,1)$ at the outer node and
$(r,s)=((0+1)^{*},0)$ at the inner node; the star body is $0+1$.
The derivation proceeds from the inside outward.

\begin{enumerate}
  \item \textbf{Derive by $\mathtt{1}$.}
  At the star body, $\mathsf{P}_{+}$ distributes the derivative over
  two alternatives:
  \begin{equation}\label{eq:der-16}
  \begin{aligned}
  pd(0{+}1,\ \mathtt{1})
    &= pd(0,\mathtt{1}) \cup pd(1,\mathtt{1})
    &&\mathsf{P}_{+},\ r = 0,\ s = 1 \\
    &= \{\} \cup \{\varepsilon\}
    &&\mathsf{P}_{\mathrm{lit}},\ \text{both branches} \\
    &= \{\varepsilon\}.
  \end{aligned}
  \end{equation}

  The star rule then applies $\mathit{smartC}$ to the resulting
  residual:
  \begin{equation}\label{eq:der-17}
  \begin{aligned}
  pd\big((0+1)^{*},\ \mathtt{1}\big)
    &= \{\,\mathit{smartC}(r',(0+1)^{*})
        \mid r' \in \{\varepsilon\}\,\}
    &&\mathsf{P}_{*},\ r = 0+1 \\
    &= \{(0+1)^{*}\}
    &&\mathsf{SC},\ r' = \varepsilon.
  \end{aligned}
  \end{equation}

  At the middle concatenation, the left operand is nullable by
  $\mathsf{N}_{*}$, so the nullable case contributes both the
  derivatives through the left and right operand:
  \begin{equation}\label{eq:der-18}
  \begin{aligned}
  pd\big((0+1)^{*}\cdot0,\ \mathtt{1}\big)
    &= \{\,\mathit{smartC}(r',0)
        \mid r' \in pd\big((0+1)^{*},\mathtt{1}\big)\,\}
       \cup pd(0,\mathtt{1})
    &&\mathsf{P}_{\mathrm{seq}}^{\,n} \\
    &= \{\mathit{smartC}((0+1)^{*},0)\} \cup \{\}
    &&\text{above; }\mathsf{P}_{\mathrm{lit}} \\
    &= \{(0+1)^{*}\cdot0\}
    &&\mathsf{SC},\ r' \neq \varepsilon.
  \end{aligned}
  \end{equation}

  At the outer node, the left operand is not nullable, so only one branch contributes:

  \begin{equation}\label{eq:der-19}
  \begin{aligned}
  pd(r_{01},\ \mathtt{1})
    &= \{\,\mathit{smartC}(r',1)
        \mid r' \in \{(0+1)^{*}\cdot0\}\,\}
    &&\mathsf{P}_{\mathrm{seq}},\
      r = (0+1)^{*}\cdot0,\ s = 1 \\
    &= \{(0+1)^{*}\cdot0\cdot1\}
     = \{r_{01}\}
    &&\mathsf{SC}.
  \end{aligned}
  \end{equation}

  Thus the first symbol leaves a single residual, the $r_{01}$
  itself. The computation has returned to the same residual from which
  it started, representing the possibility that the consumed
  $\mathtt{1}$ belonged to the leading star.

  \item \textbf{Derive by $\mathtt{0}$.}
  The current set is still $\{r_{01}\}$. As before,
  \[
  pd\big((0+1)^{*},\mathtt{0}\big) = \{(0+1)^{*}\}.
  \]
  At the middle concatenation, however, the right operand is now the
  matching literal $0$, so $\mathsf{P}_{\mathrm{lit}}$ contributes
  $\{\varepsilon\}$:
  \begin{equation}\label{eq:der-20}
  \begin{aligned}
  pd\big((0+1)^{*}\cdot0,\ \mathtt{0}\big)
    &= \{\mathit{smartC}((0+1)^{*},0)\}
       \cup pd(0,\mathtt{0})
    &&\mathsf{P}_{\mathrm{seq}}^{\,n},\
      r = (0+1)^{*},\ s = 0 \\
    &= \{(0+1)^{*}\cdot0\} \cup \{\varepsilon\}
    &&\mathsf{P}_{\mathrm{lit}},\ \text{since } \mathtt{0} = 0 \\
    &= \{(0+1)^{*}\cdot0,\ \varepsilon\}.
  \end{aligned}
  \end{equation}

  The outer concatenation applies $\mathit{smartC}$ separately to both
  residuals:
  \begin{equation}\label{eq:der-21}
  \begin{aligned}
  pd(r_{01},\mathtt{1},\mathtt{0})
    &= \{\,\mathit{smartC}(r',1)
        \mid r' \in \{(0+1)^{*}\cdot0,\varepsilon\}\,\}
    &&\mathsf{P}_{\mathrm{seq}},\ s = 1 \\
    &= \{(0+1)^{*}\cdot0\cdot1,\ 1\}
    &&\mathsf{SC} \\
    &= \{r_{01},\ 1\}.
  \end{aligned}
  \end{equation}

  The two residuals represent the possible strands after $\mathtt{10}$:
  $r_{01}$ keeps both symbols in the leading star, while $1$ means the
  $\mathtt{0}$ began the final $\mathtt{01}$. Since
  $\mathit{smartC}(\varepsilon,1)=1$, the latter is represented directly
  as $1$.

  \item \textbf{Derive by $\mathtt{1}$.}
  The two residuals are derived independently and their results are
  unioned:
  \begin{equation}\label{eq:der-22}
  \begin{aligned}
  pd(r_{01},\mathtt{1},\mathtt{0},\mathtt{1})
    &= pd(r_{01},\mathtt{1}) \cup pd(1,\mathtt{1})
    &&\text{union over the set} \\
    &= \{r_{01}\} \cup \{\varepsilon\}
    &&\text{step~1; }\mathsf{P}_{\mathrm{lit}} \\
    &= \{r_{01},\ \varepsilon\}.
  \end{aligned}
  \end{equation}
\end{enumerate}

The final set contains $\varepsilon$, so one surviving residual is
nullable and therefore
$\mathtt{101} \in L(r_{01})$. The conclusion matches
Equation~\eqref{eq:der-26}.

For $w=\mathtt{10}$, the first two steps are the same, leaving
$\{r_{01},1\}$. Neither residual is nullable:
$n(r_{01})=\mathrm{false}$, while the literal $1$ becomes nullable only
after a further derivative. Hence $\mathtt{10}\notin L(r_{01})$.

Step~2 directly relates the two constructions. The set
$\{r_{01},1\}$ represents the same alternatives as
$\big((0+1)^{*}\cdot0+\varepsilon\big)\cdot1$ in
Equation~\eqref{eq:der-25}: either the trailing $\mathtt{01}$ remains
to be matched, or the consumed $\mathtt{0}$ was its first symbol. The
Brzozowski derivative combines these alternatives using $+$, whereas
$pd$ retains them as separate residuals.

%

\paragraph{Finiteness.}

The set of partial derivatives reachable from a fixed $r$ is finite,
bounded by $\|r\|+1$, where $\|r\|$ counts literal occurrences
\citep[Theorem~3.4, p.~309]{antimirov1996}. For $r_{01}$,
$\|r_{01}\|=4$, so at most five residuals can occur; the example reaches
only $\{r_{01}\}$, $\{r_{01},1\}$, and $\{r_{01},\varepsilon\}$.

Ordinary derivatives are finite only after equivalent expressions have
been identified \citep[Theorem~4.3]{brzozowski1964}; the resulting bound
is exponential, $d_R\leq2^{d_P}-1$. The simplifications of
Equation~\eqref{eq:simp-identities} approximate this identification by
removing units and collapsing identical summands, but do not identify
all equivalent expressions. Antimirov's bound is linear and applies
directly to the partial-derivative set.

%

\paragraph{In Rust.}
Figure~\ref{fig:pderiv-rust} shows the partial-derivative function
together with the smart constructor, and
Figure~\ref{fig:pderiv-loop-rust} the frontier loop that drives them.

\begin{figure}[ht]
\begin{verbatim}
fn pderiv(r: &Regex, x: char) -> Vec<Regex> {
    match r {
        // ...
        Regex::Seq(r, s) => {
            let mut out: Vec<Regex> = pderiv(r, x)
                .into_iter()
                .map(|r_prime| smart_seq(r_prime, s))
                .collect();
            if nullable(r) {
                out.extend(pderiv(s, x));
            }
            out
        }
        // ...
    }
}

pub fn smart_seq(r: Regex, s: &Regex) -> Regex {
    match r {
        Regex::Eps => s.clone(),
        r => Regex::seq(r, s.clone()),
    }
}
\end{verbatim}
\caption{The concatenation case of $pd(r,x)$ and the smart constructor
$\mathit{smartC}$, corresponding to
Equations~\eqref{eq:pd} and~\eqref{eq:smartc}.}
\label{fig:pderiv-rust}
\end{figure}

The \texttt{map} implements the set comprehension of
$\mathsf{P}_{\mathrm{seq}}$, applying $\mathit{smartC}$ to each residual
of the left operand, and the guarded \texttt{out.extend(pderiv(s, x))}
implements the additional $\cup\ pd(s,x)$ of
$\mathsf{P}_{\mathrm{seq}}^{\,n}$. The union of the two rules is
therefore an \texttt{extend} on a vector rather than a set operation.

\begin{figure}[ht]
\begin{verbatim}
pub fn match_pderiv(input: &str, r: &Regex) -> bool {
    let mut states: HashSet<Regex> = HashSet::new();
    states.insert(r.clone());

    for c in input.chars() {
        let mut next: HashSet<Regex> =
            HashSet::with_capacity(states.len());
        for state in &states {
            next.extend(pderiv(state, c));
        }
        if next.is_empty() {
            return false;
        }
        states = next;
    }
    states.iter().any(nullable)
}
\end{verbatim}
\caption{The partial-derivative matcher. The set of residuals is a
\texttt{HashSet<Regex>}, one entry per surviving strand.}
\label{fig:pderiv-loop-rust}
\end{figure}

The residual set is a \texttt{HashSet<Regex>}
\citep{rust-hashset,rust-hash}. Here, \texttt{Regex}'s derived
\texttt{Hash} and \texttt{Eq} (Section~\ref{sec:regex-rust-implementation})
allow residuals reached by different routes to be represented by a
single set element. The contrast with \texttt{match\_deriv} is visible
in the declarations: the Brzozowski matcher maintains one
\texttt{Regex}, while the partial-derivative matcher maintains a set of
them.

\texttt{pderiv} itself returns a \texttt{Vec<Regex>} rather than a set,
so the union across strands is formed only where the results are
inserted into \texttt{next}. The empty-set cases
$\mathsf{P}_{\emptyset}$ and $\mathsf{P}_{\varepsilon}$ return
\texttt{Vec::new()} and therefore contribute no residual.

The early \texttt{return false} follows from the construction: once the
frontier is empty, no later derivative can produce a residual from it.
The remaining input therefore cannot change the result. The final
\texttt{states.iter().any(nullable)} is the acceptance condition:
\emph{some} surviving residual must be nullable, whereas
\texttt{match\_deriv} checks nullability of its single residual.

\texttt{smart\_seq} takes \texttt{r} by value and \texttt{s} by
reference, reflecting the construction in Equation~\eqref{eq:smartc}.
The residual $r'$ comes from the recursive derivative and is consumed,
while the right operand $s$ must be retained in the resulting
expression. The $r'=\varepsilon$ branch clones only \texttt{s} and
omits the $\varepsilon$, avoiding the construction of
$\varepsilon\cdot s$ altogether.

Thus, while the Brzozowski matcher follows one residual expression at a
time, the partial-derivative matcher maintains all surviving residuals
explicitly. The transition
$\{r_{01}\}\to\{r_{01},1\}\to\{r_{01},\varepsilon\}$ illustrates this
difference. Each residual can be viewed as a possible NFA state, and
the set records all states that can be active after reading the input.
