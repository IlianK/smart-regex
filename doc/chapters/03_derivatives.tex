\chapter{Derivatives and Partial Derivatives}
\label{sec:derivatives}

Chapter~\ref{sec:regular-expressions} introduced the syntax and semantics
of regular expressions, and defined the \emph{membership problem}: Decide
whether a word $w$ belongs to $L(r)$. This chapter introduces three algorithms
for solving it, each returning a Boolean answer: match or no match.

The first is a naive recursive matcher that follows the structure of the
regular-expression semantics. The other two transform the regular expression
as input symbols are consumed. Brzozowski derivatives transform it into a
single residual expression, while Antimirov's partial derivatives represent
the possible residual expressions as a set.


%
%
%

\section{Naive Matching}
\label{sec:naive-matching}

A direct way to decide whether $w \in L(r)$ is to interpret the
regular-expression semantics as recursive matching rules, by 
following the structure of the expression and searching for
possible decompositions of the input. Let $w[i:j]$
denote the substring from position $i$ to $j$. A recursive procedure
$\operatorname{match}(w,i,j,r)$ determines whether $w[i:j] \in L(r)$:
\begin{equation}
\begin{aligned}
\operatorname{match}(w,i,j,\varepsilon)
  &\iff i = j, \\[2pt]
\operatorname{match}(w,i,j,x)
  &\iff j = i+1 \land w[i] = x, \\[2pt]
\operatorname{match}(w,i,j,r+s)
  &\iff \operatorname{match}(w,i,j,r)
      \lor \operatorname{match}(w,i,j,s), \\[2pt]
\operatorname{match}(w,i,j,r\cdot s)
  &\iff \exists k \in [i,j].\,
      \operatorname{match}(w,i,k,r)
      \land
      \operatorname{match}(w,k,j,s), \\[2pt]
\operatorname{match}(w,i,j,r^{*})
  &\iff i=j
      \lor
      \exists k \in (i,j].\,
      \operatorname{match}(w,i,k,r)
      \land
      \operatorname{match}(w,k,j,r^{*}).
\end{aligned}
\label{eq:naive-matcher}
\end{equation}

Each rule corresponds directly to the semantics. Concatenation does not
specify where to split, so the matcher must consider all possible split
points $k$.

For matching $(a\cdot a)\cdot a$ against $\mathtt{aaa}$, the
split points $k\in\{0,1,2,3\}$ are:
\begin{equation}
\begin{aligned}
&\underbrace{\operatorname{match}(w,0,0,a\cdot a)}_
  {\text{$a\cdot a$ against }w[0:0]=\mathtt{\epsilon}}
  \land
  \underbrace{\operatorname{match}(w,0,3,a)}_
  {\text{$a$ against }w[0:3]=\mathtt{aaa}}
\\[4pt]
{}\lor\;&
\underbrace{\operatorname{match}(w,0,1,a\cdot a)}_
  {\text{$a\cdot a$ against }w[0:1]=\mathtt{a}}
  \land
  \underbrace{\operatorname{match}(w,1,3,a)}_
  {\text{$a$ against }w[1:3]=\mathtt{aa}}
\\[4pt]
{}\lor\;&
\underbrace{\operatorname{match}(w,0,2,a\cdot a)}_
  {\text{$a\cdot a$ against }w[0:2]=\mathtt{aa}}
  \land
  \underbrace{\operatorname{match}(w,2,3,a)}_
  {\text{$a$ against }w[2:3]=\mathtt{a}}
\\[4pt]
{}\lor\;&
\underbrace{\operatorname{match}(w,0,3,a\cdot a)}_
  {\text{$a\cdot a$ against }w[0:3]=\mathtt{aaa}}
  \land
  \underbrace{\operatorname{match}(w,3,3,a)}_
  {\text{$a$ against }w[3:3]=\mathtt{\epsilon}}.
\end{aligned}
\label{eq:naive-splits-1}
\end{equation}

At $k=2$, both operands match, triggering a recursive search on $(a\cdot a)$
against $\mathtt{aa}$ with split points $k\in\{0,1,2\}$, where $k=1$ succeeds:
\begin{equation}
\begin{aligned}
&\underbrace{\operatorname{match}(w,0,0,a)}_
  {\text{$a$ against }w[0:0]=\mathtt{\epsilon}}
  \land
  \underbrace{\operatorname{match}(w,0,2,a)}_
  {\text{$a$ against }w[0:2]=\mathtt{aa}}
\\[4pt]
{}\lor\;&
\underbrace{\operatorname{match}(w,0,1,a)}_
  {\text{$a$ against }w[0:1]=\mathtt{a}}
  \land
  \underbrace{\operatorname{match}(w,1,2,a)}_
  {\text{$a$ against }w[1:2]=\mathtt{a}}
\\[4pt]
{}\lor\;&
\underbrace{\operatorname{match}(w,0,2,a)}_
  {\text{$a$ against }w[0:2]=\mathtt{aa}}
  \land
  \underbrace{\operatorname{match}(w,2,2,a)}_
  {\text{$a$ against }w[2:2]=\mathtt{\epsilon}}.
\end{aligned}
\label{eq:naive-splits-2}
\end{equation}

This completes the original match through the nested split points $k=2$ and
$k=1$.

%

\paragraph{In Rust.}
The recursive rules translate directly into the corresponding Rust match arms,
shown in Figure~\ref{fig:match-naive-rust}.
Alternation tries both branches on the same input, while concatenation and star
search possible split points.
The star arm clones the body to construct the recursive \texttt{Star} expression.
This is necessary because the recursive call needs to own the newly constructed
expression. The range-based search short-circuits at the first successful split.
Nested concatenations repeatedly search smaller substrings, exploring multiple
paths before succeeding. This leads to exponential backtracking in the worst
case.

\begin{figure}[H]
\small
\begin{verbatim}
Regex::Alt(r, s) => {
    match_naive_range(word, i, j, r) 
        || match_naive_range(word, i, j, s)
}
Regex::Seq(r, s) => {
    (i..=j).any(|k| {
        match_naive_range(word, i, k, r) 
            && match_naive_range(word, k, j, s)
    })
}
Regex::Star(r) => {
    i == j || (i + 1..=j).any(|k| {
        match_naive_range(word, i, k, r)
            && match_naive_range(word, k, j, 
                &Regex::star(*r.clone()))
    })
}
\end{verbatim}
\caption{Alternation, concatenation, and star arms of the naive matcher.}
\label{fig:match-naive-rust}
\end{figure}

Although inefficient, this matcher is useful as a reference implementation
because it follows the regular-expression semantics directly without any
intermediate transformation. The cost is visible in the worked examples: nested
concatenations repeatedly search smaller substrings, each exploring all possible
split points before finding a match.

%

The derivative approach takes a different approach.
Rather than searching for a decomposition of $w$ while keeping $r$ fixed,
it transforms $r$ as each character of $w$ is consumed. The resulting
expression describes the language that can still match the remaining
suffix.

\section{Brzozowski Derivatives}
\label{sec:brzozowski-derivatives}

Brzozowski's derivative of $r$ with respect to a symbol $x$, written
$r \backslash x$, is the expression describing exactly what remains of
$r$'s language after consuming the leading symbol $x$ of a word
$w \in L(r)$ \citep{brzozowski1964}:

\begin{equation}\label{eq:der-23}
L(r \backslash x) \;=\; \{\, w \mid xw \in L(r) \,\}.
\end{equation}

For $w = x_1x_2\cdots x_n$, consume one symbol at a time
by repeatedly taking derivatives:


\[
r,\quad
r\backslash x_1,\quad
(r\backslash x_1)\backslash x_2,\quad \ldots
\]

\paragraph{Nullability.}
\label{par:nullability}
After all symbols have been consumed, the remaining input is
$\varepsilon$. Thus, the resulting expression must accept $\varepsilon$
for the original word to belong to $L(r)$. This is the
question of whether the expression is \emph{nullable}.
Let $n(r)$ be true exactly when $\varepsilon \in L(r)$:

\begin{equation}\label{eq:nullability}
\begin{aligned}
n(\emptyset) &= \mathrm{false} &&(\mathsf{N}_{\emptyset}) &
n(r + s) &= n(r) \lor n(s) &&(\mathsf{N}_{+}) \\
n(\varepsilon) &= \mathrm{true} &&(\mathsf{N}_{\varepsilon}) &
n(r \cdot s) &= n(r) \land n(s) &&(\mathsf{N}_{\mathrm{seq}}) \\
n(x) &= \mathrm{false} &&(\mathsf{N}_{\mathrm{lit}}) &
n(r^{*}) &= \mathrm{true} &&(\mathsf{N}_{*})
\end{aligned}
\end{equation}

The empty language $\emptyset$ is not nullable because it contains no
words, including $\varepsilon$, while a literal cannot match the empty
word. $\varepsilon$ and $r^{*}$ always match $\varepsilon$.
An alternation is nullable when either branch is nullable, and a
concatenation only when both components are.

%

\paragraph{In Rust.}
\label{par:nullability-rust}
The definition is transcribed one \texttt{Regex} variant at a time,
using the enum of Figure~\ref{fig:regex-enum}. The case split of
~\eqref{eq:nullability} becomes the arms of a \texttt{match},
shown in Figure~\ref{fig:nullable-rust}.

\begin{figure}[H]
\begin{verbatim}
pub fn nullable(r: &Regex) -> bool {
    match r {
        Regex::Phi => false,
        Regex::Eps => true,
        Regex::Lit(_) => false,
        Regex::Alt(r, s) => nullable(r) || nullable(s),
        Regex::Seq(r, s) => nullable(r) && nullable(s),
        Regex::Star(_) => true,
    }
}
\end{verbatim}
\caption{\texttt{nullable} implementation and its six cases:
$\mathsf{N}_{\emptyset}$, $\mathsf{N}_{\varepsilon}$,
$\mathsf{N}_{\mathrm{lit}}$, $\mathsf{N}_{+}$,
$\mathsf{N}_{\mathrm{seq}}$ and $\mathsf{N}_{*}$.}
\label{fig:nullable-rust}
\end{figure}

The expression is passed by reference because \texttt{nullable} only
inspects $r$ and does not modify or consume it. The underscores in
$\mathsf{N}_{\mathrm{lit}}$ and $\mathsf{N}_{*}$ indicate that the
corresponding operands are irrelevant. A literal is never nullable,
regardless of its symbol, while a Kleene-star expression is always
nullable, regardless of its body. The short-circuiting operators
\texttt{||} and \texttt{\&\&} avoid evaluating the second operand when
the result is already determined, while preserving the corresponding
logical semantics.

%

\paragraph{Derivative Rules.}
\label{par:derivative-rules}
The rules specify the expression that remains after consuming $x$:

\begin{equation}\label{eq:derivative}
\begin{aligned}
\emptyset \backslash x &= \emptyset &&(\mathsf{D}_{\emptyset}) 
\quad &
(r + s) \backslash x &= (r \backslash x) + (s \backslash x) &&\hspace{0.4em}(\mathsf{D}_{+}) \\
\varepsilon \backslash x &= \emptyset &&(\mathsf{D}_{\varepsilon})
\quad &
r^{*} \backslash x &= (r \backslash x) \cdot r^{*} &&\hspace{0.4em}(\mathsf{D}_{*}) \\
y \backslash x &= \begin{cases}
  \varepsilon & x = y \\
  \emptyset & x \neq y
\end{cases}
&&(\mathsf{D}_{\mathrm{lit}})
\quad &
(r \cdot s) \backslash x &= \begin{cases}
  (r \backslash x) \cdot s + s \backslash x & n(r) = \mathrm{true} \\
  (r \backslash x) \cdot s & n(r) = \mathrm{false}
\end{cases}
&&\begin{array}{l}
(\mathsf{D}_{\mathrm{seq}}^{\,n}) \\
(\mathsf{D}_{\mathrm{seq}})
\end{array}
\end{aligned}
\end{equation}
The empty language and $\varepsilon$ cannot consume $x$. 
A literal $y$ succeeds exactly when $x=y$, leaving $\varepsilon$. 
Alternation retains both derivatives and for $r^{*}$, 
one occurrence of $r$ consumes $x$ while further occurrences remain available. 

Concatenation is the only rule that depends on nullability.
If $r$ is not nullable, $r$ must consume the leading $x$, leaving
$r\backslash x$ as the remainder of $r$ while $s$ remains untouched.
If $r$ is nullable, it may either consume $x$ giving $(r\backslash x)\cdot s$,
or $r$ matches $\varepsilon$ and $s$ consumes $x$ leaving $s\backslash x$.
Hence the nullable case produces the alternation $(r\backslash x)\cdot s + s\backslash x$.

%

\paragraph{In Rust.}
Figure~\ref{fig:deriv-rust} implements~\eqref{eq:derivative} similarly, one variant at a time.

\begin{figure}[H]
\begin{verbatim}
pub fn deriv(r: &Regex, x: char) -> Regex {
    match r {
        Regex::Phi => Regex::Phi,
        Regex::Eps => Regex::Phi,
        Regex::Lit(c) => if *c == x { Regex::Eps } else { Regex::Phi },
        Regex::Alt(r1, r2) => 
            Regex::alt(deriv(r1, x), deriv(r2, x)),
        Regex::Seq(r1, r2) => {
            let dr1 = Regex::seq(deriv(r1, x), *r2.clone());
            if nullable(r1) {
                Regex::alt(dr1, deriv(r2, x))
            } else { dr1 }
        }
        Regex::Star(r1) => 
            Regex::seq(deriv(r1, x), Regex::star(*r1.clone())),
    }
}
\end{verbatim}
\caption{\texttt{deriv} implementation with six cases.}
\label{fig:deriv-rust}
\end{figure}

\texttt{deriv} differs from \texttt{nullable} in that it borrows its input
but returns an owned \texttt{Regex}, since a derivative is a new expression.
The \texttt{if nullable(r1)} implements the case split of~\eqref{eq:derivative},
with branches in order $\mathsf{D}_{\mathrm{seq}}^{\,n}$ then $\mathsf{D}_{\mathrm{seq}}$.
This is the only place where a derivative rule consults nullability and where
the output can be larger than the input, since the nullable branch produces
an alternation while the other produces a concatenation.

The cloning in \texttt{*r2.clone()} is necessary because $s$ appears untouched
in both branches of the concatenation case, and the star arm must preserve $r^{*}$'s
body both derived and underived. This copying mechanism drives expression growth,
which justifies simplification after every derivative step.

%

\paragraph{Example: Growth without simplification.}
Consider $(x+y)^{*}$ against the word $\mathtt{xx}$:
The expression is a star, so $\mathsf{D}_{*}$ applies with
body $r = x+y$:
\begin{equation}\label{eq:der-3}
\begin{aligned}
(x+y)^{*} \backslash \mathtt{x}
  &= ((x+y) \backslash \mathtt{x}) \cdot (x+y)^{*}
  &&\mathsf{D}_{*},\ r = x+y \\
  &= (\varepsilon + \emptyset) \cdot (x+y)^{*}
  &&\mathsf{D}_{+},\ \mathsf{D}_{\mathrm{lit}}
\end{aligned}
\end{equation}

The expression is now the concatenation
$(\varepsilon + \emptyset) \cdot (x+y)^{*}$, and deriving it consumes the second
$\mathtt{x}$. The result is an alternation because
$\mathsf{D}_{\mathrm{seq}}^{\,n}$ applies with $r = \varepsilon + \emptyset$ and
$s = (x+y)^{*}$, its nullable case being selected since
$n(r) = n(\varepsilon + \emptyset) = \mathrm{true}$ by $\mathsf{N}_{+}$ and $\mathsf{N}_{\varepsilon}$:
\begin{equation}\label{eq:der-4}
\begin{aligned}
&((\varepsilon + \emptyset) \cdot (x+y)^{*}) \backslash \mathtt{x} \\
  &= ((\varepsilon + \emptyset) \backslash \mathtt{x}) \cdot (x+y)^{*}
     + (x+y)^{*} \backslash \mathtt{x}
  &&\mathsf{D}_{\mathrm{seq}}^{\,n} \\
  &= (\emptyset + \emptyset) \cdot (x+y)^{*}
     + (x+y)^{*} \backslash \mathtt{x}
  &&\mathsf{D}_{\varepsilon} \\
  &= (\emptyset + \emptyset) \cdot (x+y)^{*}
     + (\varepsilon + \emptyset) \cdot (x+y)^{*}
  &&\mathsf{D}_{*},\ \mathsf{D}_{+},\ \mathsf{D}_{\mathrm{lit}}
\end{aligned}
\end{equation}

After both symbols are consumed, the result is checked for nullability:
\begin{equation}\label{eq:der-5}
\begin{aligned}
&n((\emptyset + \emptyset) \cdot (x+y)^{*} + (\varepsilon + \emptyset) \cdot (x+y)^{*}) \\
&= n((\emptyset + \emptyset) \cdot (x+y)^{*}) \lor n((\varepsilon + \emptyset) \cdot (x+y)^{*})
   &&\mathsf{N}_{+} \\
&= (n(\emptyset + \emptyset) \land n((x+y)^{*})) \lor
   (n(\varepsilon + \emptyset) \land n((x+y)^{*}))
   &&\mathsf{N}_{\mathrm{seq}} \\
&= (\mathrm{false} \land \mathrm{true}) \lor
   (\mathrm{true} \land \mathrm{true})
   &&\mathsf{N}_{+},\ \mathsf{N}_{\emptyset},\ \mathsf{N}_{\varepsilon},\ \mathsf{N}_{*} \\
&= \mathrm{true}.
\end{aligned}
\end{equation}

Thus $(x+y)^{*}$ matches $\mathtt{xx}$.

%

\paragraph{Simplification.}
Derivatives can grow unboundedly. Repeatedly
deriving $(x+y)^{*}$ by the same symbol produces expressions of increasing
size. This growth results from the nullable branch of
$\mathsf{D}_{\mathrm{seq}}^{\,n}$, which introduces an alternation as a redundant structure
that is carried into subsequent derivatives. $\varepsilon$ and
$\emptyset$ accumulate without bound:

\begin{equation}\label{eq:der-growth}
\begin{aligned}
& (x+y)^{*} && 4 \\
\xrightarrow{\;\mathtt{x}\;}\quad
& (\varepsilon+\emptyset)\cdot(x+y)^{*} && 8 \\
\xrightarrow{\;\mathtt{x}\;}\quad
& (\emptyset+\emptyset)\cdot(x+y)^{*}
  \;+\; (\varepsilon+\emptyset)\cdot(x+y)^{*} && 17 \\
\xrightarrow{\;\mathtt{x}\;}\quad
& (\emptyset+\emptyset)\cdot(x+y)^{*}
  \;+\; \bigl( (\emptyset+\emptyset)\cdot(x+y)^{*}
  \;+\; (\varepsilon+\emptyset)\cdot(x+y)^{*} \bigr) && 26
\end{aligned}
\end{equation}

To counter the growth, expressions are simplified
after each derivative step, using identities that preserve the denoted
language:

\begin{equation}\label{eq:simp-identities}
\begin{aligned}
\emptyset \cdot r &= \emptyset &&(\mathsf{S}_{1}) \\
\varepsilon \cdot r &= r       &&(\mathsf{S}_{2}) \\
\emptyset + r &= r             &&(\mathsf{S}_{3})
\end{aligned}
\end{equation}

$\mathsf{S}_{1}$ eliminates dead concatenations with $\emptyset$,
$\mathsf{S}_{2}$ eliminates identity concatenations with $\varepsilon$,
and $\mathsf{S}_{3}$ eliminates $\emptyset$ from alternations. Each
holds equally with the unit on the right. 

Applying them to ~\eqref{eq:der-4}, 
after each step, returns the expression back to $(x+y)^{*}$,
keeping the size bounded regardless of input length:
\begin{equation}\label{eq:der-6}
\begin{aligned}
&(\emptyset + \emptyset) \cdot (x+y)^{*} + (\varepsilon + \emptyset) \cdot (x+y)^{*} \\
  &= \emptyset \cdot (x+y)^{*} + \varepsilon \cdot (x+y)^{*}
  &&\mathsf{S}_{3},\ \text{twice} \\
  &= \emptyset + (x+y)^{*}
  &&\mathsf{S}_{1},\ \mathsf{S}_{2} \\
  &= (x+y)^{*}
  &&\mathsf{S}_{3}
\end{aligned}
\end{equation}

%

\paragraph{In Rust.}
The identities are implemented recursively, applying the rules
bottom-up over the expression tree. Each arm of the inner match implements
an identity from ~\eqref{eq:simp-identities}.

\texttt{simplify} takes ownership of its input and returns simplified subexpressions
directly, unlike \texttt{deriv}, which borrows and constructs. This model is visible
where the two compose:

\begin{verbatim}
current = simplify(deriv(&current, c));
\end{verbatim}

\texttt{deriv} borrows \texttt{current}, constructs a new expression, and \texttt{simplify}
takes ownership of that result to return it without additional copying. The recursive
calls ensure that all dead code is eliminated before an expression is returned, keeping
size bounded at each step. Together, derive-then-simplify forms the core loop of the
matcher, transforming and cleaning the expression at every input symbol.

\begin{figure}[H]
\small
\begin{verbatim}
pub fn simplify(r: Regex) -> Regex {
    match r {
        Regex::Seq(r, s) => {
            let r = simplify(*r);
            let s = simplify(*s);
            match (&r, &s) {
                (Regex::Phi, _) | (_, Regex::Phi) => Regex::Phi,
                (Regex::Eps, _) => s,
                (_, Regex::Eps) => r,
                _ => Regex::seq(r, s),
            }
        }
        Regex::Alt(r, s) => {
            let r = simplify(*r);
            let s = simplify(*s);
            match (&r, &s) {
                (Regex::Phi, _) => s,
                (_, Regex::Phi) => r,
                _ if r == s => r,
                _ => Regex::alt(r, s),
            }
        }
        Regex::Star(r) => match simplify(*r) {
            Regex::Eps | Regex::Phi => Regex::Eps,
            r => Regex::star(r),
        },
        other => other,
    }
}
\end{verbatim}
\caption{Simplification rules: $\mathsf{S}_{1}$ and $\mathsf{S}_{2}$ in concatenation,
$\mathsf{S}_{3}$ in both branches.}
\label{fig:simplify-rust}
\end{figure}

\paragraph{The matcher.}
\label{sec:derivative-matcher}
The implementation can be summarized by the sequence of residual
expressions produced while consuming the input. For
$w=x_1x_2\cdots x_n$, the initial residual is $r_0=r$, and each
subsequent residual is obtained by deriving with respect to the next
symbol and simplifying the result:
\begin{equation}
r_0=r,
\qquad
r_i=\operatorname{simplify}(r_{i-1}\backslash x_i)
\quad (1\leq i\leq n).
\label{eq:derivative-residuals}
\end{equation}

The residual $r_i$ denotes exactly the set of suffixes that complete the
consumed prefix $x_1\cdots x_i$ to a word in $L(r)$. Since simplification
preserves the represented language, each $r_i$ is equivalent to the
unsimplified derivative after consuming that prefix. After the final
symbol has been consumed, the matcher accepts when the remaining
residual is nullable:

\[
w\in L(r)
\iff
n(r_n)=\mathrm{true}.
\]

Each step depends only on the current residual and the next symbol, so
the matcher never revisits a prefix and never backtracks into an earlier
residual. The cost of one step is the cost of \texttt{deriv} on the
current residual, which is proportional to its size.

So $r_0\xrightarrow{x_1}r_1\xrightarrow{x_2}\cdots\xrightarrow{x_n}r_n$
can be viewed as a path through a lazily constructed DFA. Each residual
expression represents a state, and
$\xrightarrow{x}$ denotes the transition obtained by taking the derivative
with respect to $x$. Unlike an explicitly constructed DFA, only the states
reached by the input are constructed. A residual is an accepting state
exactly when it is nullable, so acceptance is determined by whether the
final residual is nullable.

%

\paragraph{In Rust.}
Figure~\ref{fig:match-deriv-rust} implements ~\eqref{eq:derivative-residuals}
by composing \texttt{deriv}, \texttt{simplify}, and \texttt{nullable}.
The implementation follows the mathematical definition directly. The current
residual is transformed at each step, and acceptance is determined after the
complete input has been consumed.

\begin{figure}[H]
\begin{verbatim}
pub fn match_deriv(input: &str, r: &Regex) -> bool {
    let mut current = r.clone();
    for c in input.chars() {
        current = simplify(deriv(&current, c));
    }
    nullable(&current)
}
\end{verbatim}
\caption{\texttt{match\_deriv}: the core matcher loop. For each input character,
derive the current residual expression and simplify it in place. 
Accept if the final residual is nullable.}
\label{fig:match-deriv-rust}
\end{figure}

The loop implements the residual sequence. At each iteration,
\texttt{current} contains the current residual, which is then derived and
simplified before processing the next input symbol. Only the current
residual is retained, since the previous residual is dropped when
\texttt{current} is reassigned. In contrast to parsing, where intermediate
results may be required to reconstruct a parse tree, Boolean matching
requires only the final residual.

The derivative-based matcher avoids the exponential backtracking of naive
matching by transforming the expression rather than searching for
decompositions. Simplification keeps the resulting expressions compact,
preventing the growth shown in ~\eqref{eq:der-growth}.

\paragraph{Worked Example: Applying the derivative-based matcher}
\label{sec:deriv-worked-example}

Apply \texttt{match\_deriv} to $r_0 = (a + ab)(b + \varepsilon)$ and
$w = \mathtt{ab}$ with the expression written as:
\[
r_0 = \mathit{Seq}(s,\, t),
\qquad
s = a + ab,
\qquad
t = b + \varepsilon,
\]

\paragraph{Derive by $\mathtt{a}$.}
The first factor $s$ is not nullable, so $\mathsf{D}_{\mathrm{seq}}$
applies to the sequence $r_0$:
\[
r_1 = r_0 \backslash \mathtt{a}
  = (s \backslash \mathtt{a}) \cdot t
  \qquad (\mathsf{D}_{\mathrm{seq}}).
\]
Since $s$ cannot match the empty word, the second factor $t$ is not
touched by this derivative and appears unchanged. To derive $s$,
the alternation rule $\mathsf{D}_{+}$ is applied to give:
\[
s \backslash \mathtt{a}
  = (a \backslash \mathtt{a}) + (ab \backslash \mathtt{a})
  \qquad (\mathsf{D}_{+}).
\]
The two summands are derived separately, each by its own rule:
\[
\begin{aligned}
a \backslash \mathtt{a}
  &= \varepsilon
  &&(\mathsf{D}_{\mathrm{lit}}), \\[2pt]
ab \backslash \mathtt{a}
  &= (a \backslash \mathtt{a}) \cdot b
   = \varepsilon \cdot b
  &&(\mathsf{D}_{\mathrm{seq}},\ \mathsf{D}_{\mathrm{lit}}).
\end{aligned}
\]
Substituting both summands into the alternation and the result into the
outer sequence:
\[
\begin{aligned}
s \backslash \mathtt{a}
  &= \varepsilon + \varepsilon \cdot b
  &&(\mathsf{D}_{+}), \\[4pt]
r_0 \backslash \mathtt{a}
  &= (\varepsilon + \varepsilon \cdot b) \cdot t
  &&(\mathsf{D}_{\mathrm{seq}}).
\end{aligned}
\]
Then, applying the simplification rule $\mathsf{S}_{2}$ to the occurrences
of $\varepsilon \cdot b$, gives the residual:
\[
r_1 = (\varepsilon + b) \cdot t
  \qquad (\mathsf{S}_{2}).
\]

%

\paragraph{Derive by $\mathtt{b}$.}
The residual $r_1$ is again a sequence,
but now the first factor $\varepsilon + b$ is nullable, so the nullable
sequence rule $\mathsf{D}_{\mathrm{seq}}^{\,n}$ applies when deriving by $b$:
\[
r_2 = r_1 \backslash \mathtt{b}
  = \big((\varepsilon + b) \backslash \mathtt{b}\big) \cdot t
    + (t \backslash \mathtt{b})
  \qquad (\mathsf{D}_{\mathrm{seq}}^{\,n}).
\]
Since the first factor $\varepsilon + b$ is nullable, it can either
consume the character itself, leaving $t$ untouched, or match
$\varepsilon$ and let $t$ consume it. Both are possible, so
$\mathsf{D}_{\mathrm{seq}}^{\,n}$ produces one summand for each, and
$\mathsf{D}_{+}$ derives the first factor and $t$ in their respective
summands:
\[
\begin{aligned}
(\varepsilon + b) \backslash \mathtt{b}
  &= (\varepsilon \backslash \mathtt{b}) + (b \backslash \mathtt{b})
   = \emptyset + \varepsilon
  &&(\mathsf{D}_{+},\ \mathsf{D}_{\varepsilon},\
           \mathsf{D}_{\mathrm{lit}}), \\[4pt]
t \backslash \mathtt{b} = (b + \varepsilon) \backslash \mathtt{b}
  &= (b \backslash \mathtt{b}) + (\varepsilon \backslash \mathtt{b})
   = \varepsilon + \emptyset
  &&(\mathsf{D}_{+},\ \mathsf{D}_{\mathrm{lit}},\
           \mathsf{D}_{\varepsilon}).
\end{aligned}
\]
Substituting both summands into the two-summand expression:
\[
r_1 \backslash \mathtt{b}
  = (\emptyset + \varepsilon) \cdot t
    + (\varepsilon + \emptyset).
\]
Applying the simplification rules $\mathsf{S}_{3}$ and
$\mathsf{S}_{2}$ to the first summand and $\mathsf{S}_{3}$ to the
second, gives the final residual after deriving the second character:
\[
r_2 
  = t + \varepsilon
  \qquad (\mathsf{S}_{3},\ \mathsf{S}_{2},\ \mathsf{S}_{3}).
\]

\paragraph{Acceptance.}
The residual $r_2 = (b + \varepsilon) + \varepsilon$ is nullable by
$\mathsf{N}_{+}$ and $\mathsf{N}_{\varepsilon}$, so
$\mathtt{ab} \in L(r_0)$.

\section{Antimirov Partial Derivatives}
\label{sec:antimirov-partial-derivatives}

The derivative of Section~\ref{sec:brzozowski-derivatives} combines
alternative residuals into a single expression using $+$. Antimirov's
partial derivatives instead keep them as a \emph{set} of expressions,
one per strand of nondeterminism \citep{antimirov1996}. Writing
$pd(r,x)$ for this set:
\begin{equation}\label{eq:pd}
\begin{aligned}
pd(\emptyset, x) &= \{\} &&(\mathsf{P}_{\emptyset}) \\
pd(\varepsilon, x) &= \{\} &&(\mathsf{P}_{\varepsilon}) \\
pd(y, x) &=
  \begin{cases} \{\varepsilon\} & x = y \\ \{\} & x \neq y \end{cases}
  &&(\mathsf{P}_{\mathrm{lit}}) \\
pd(r + s, x) &= pd(r,x) \cup pd(s,x) &&(\mathsf{P}_{+}) \\
pd(r^{*}, x) &= \{\, \mathit{smartC}(r', r^{*}) \mid r' \in pd(r,x) \,\}
  &&(\mathsf{P}_{*}) \\
pd(r \cdot s, x) &=
  \begin{cases}
    \{\, \mathit{smartC}(r', s) \mid r' \in pd(r,x) \,\} \cup pd(s,x)
      & n(r) = \mathrm{true} \\
    \{\, \mathit{smartC}(r', s) \mid r' \in pd(r,x) \,\}
      & n(r) = \mathrm{false}
  \end{cases}
  &&\begin{array}{l}
    (\mathsf{P}_{\mathrm{seq}}^{\,n}) \\
    (\mathsf{P}_{\mathrm{seq}})
  \end{array}
\end{aligned}
\end{equation}

The empty language and $\varepsilon$ produce the empty set, since
neither has a residual with respect to $x$: where
$\mathsf{D}_{\emptyset}$ and $\mathsf{D}_{\varepsilon}$ returned
$\emptyset$ as a node in the result, $\mathsf{P}_{\emptyset}$ and
$\mathsf{P}_{\varepsilon}$ return no residual at all. A literal $y$
gives $\{\varepsilon\}$ when $x=y$ and $\{\}$ otherwise. Alternation
unions the two residual sets, and for $r^{*}$ one iteration of $r$
consumes $x$, with each resulting residual placed in front of $r^{*}$
so the star may continue. None of these alternatives are combined with
$+$; each stays a separate element of the set.

Concatenation depends on nullability for the same reason as
$\mathsf{D}_{\mathrm{seq}}$. If $r$ is not nullable it must consume
$x$, and each of its residuals is concatenated with the untouched $s$.
If $r$ is nullable, $r$ may instead match $\varepsilon$ and let $s$
consume $x$, in which case $pd(s,x)$ joins the set. Where
$\mathsf{D}_{\mathrm{seq}}^{\,n}$ combined the two cases with $+$
inside one expression, $\mathsf{P}_{\mathrm{seq}}^{\,n}$ keeps them as
two elements of one set.

%


\paragraph{The smart constructor.}
The concatenation in $\mathsf{P}_{\mathrm{seq}}$ uses an auxiliary
constructor $\mathit{smartC}$. Since each element of $pd(r,x)$ is a
separate residual rather than a branch of a sum, $\mathit{smartC}$ is
applied to each independently. The constructor avoids building
$\varepsilon \cdot s$:
\begin{equation}\label{eq:smartc}
\mathit{smartC}(r', s) =
  \begin{cases}
    s & r' = \varepsilon \\
    r' \cdot s & \text{otherwise.}
  \end{cases}
\end{equation}

\paragraph{In Rust.}
Figure~\ref{fig:smart-seq-rust} implements $\mathit{smartC}$ directly as
\texttt{smart\_seq}. Matching on \texttt{r} implements the case split of
\eqref{eq:smartc}: the \texttt{Eps} arm returns a clone of \texttt{s}
and never builds $\varepsilon \cdot s$, while the second arm wraps
\texttt{r} in front of a cloned \texttt{s}

\begin{figure}[H]
\begin{verbatim}
pub fn smart_seq(r: Regex, s: &Regex) -> Regex {
    match r {
        Regex::Eps => s.clone(),
        r => Regex::seq(r, s.clone()),
    }
}
\end{verbatim}
\caption{\texttt{smart\_seq}, the smart constructor $\mathit{smartC}$}
\label{fig:smart-seq-rust}
\end{figure}

%

Figure~\ref{fig:pderiv-rust} presents the implementation of
\eqref{eq:pd}, with each \texttt{match} arm corresponding to one case. 
The \texttt{Phi}, \texttt{Eps}, and \texttt{Lit} variants implement
$\mathsf{P}_{\emptyset}$, $\mathsf{P}_{\varepsilon}$, and
$\mathsf{P}_{\mathrm{lit}}$ directly, returning \texttt{Vec::new()}
where the equation gives $\{\}$. \texttt{Alt} concatenates the two
child vectors, implementing the union of $\mathsf{P}_{+}$. 

\texttt{Star} maps \texttt{smart\_seq} over $r$'s own residuals,
matching $\mathsf{P}_{*}$. The star's body is derived, and each
resulting residual is placed in front of a fresh $\texttt{Regex::star}$
so the star may continue. \texttt{Regex::star(*r.clone())} clones
because \texttt{Regex::star} needs an owned \texttt{Regex} and
\texttt{r} is only borrowed, once per residual since the closure runs
once for each.

\texttt{Seq} implements the case split directly. The \texttt{map}
applies \texttt{smart\_seq} to each residual of the left operand,
matching $\mathsf{P}_{\mathrm{seq}}$, and the guarded
\texttt{out.extend(pderiv(s, x))} adds $pd(s,x)$ for
$\mathsf{P}_{\mathrm{seq}}^{\,n}$. Although the mathematical definition
uses sets, the implementation uses \texttt{Vec<Regex>} throughout the
recursion and defers deduplication to a single \texttt{HashSet}
insertion at the top, rather than deduplicating at every \texttt{Alt}
or \texttt{Seq} node on the way down.

Every union in \texttt{pderiv} is therefore a vector
\texttt{extend}, not a set operation. Duplicate residuals reached by
different strands are only merged once inserted into the
\texttt{HashSet} used by the matcher below to keep the residual
generation separate from deduplication

\begin{figure}[H]
\small
\begin{verbatim}
fn pderiv(r: &Regex, x: char) -> Vec<Regex> {
    match r {
        Regex::Phi => Vec::new(),
        Regex::Eps => Vec::new(),
        Regex::Lit(c) => {
            if *c == x { vec![Regex::Eps] } else { Vec::new() }
        }
        Regex::Alt(r, s) => {
            let mut out = pderiv(r, x);
            out.extend(pderiv(s, x));
            out
        }
        Regex::Seq(r, s) => {
            let mut out: Vec<Regex> = pderiv(r, x)
                .into_iter()
                .map(|r_prime| smart_seq(r_prime, s))
                .collect();
            if nullable(r) {
                out.extend(pderiv(s, x));
            }
            out
        }
        Regex::Star(r) => {
            pderiv(r, x)
                .into_iter()
                .map(|r_prime| smart_seq(r_prime, &Regex::star(*r.clone())))
                .collect()
        }
    }
}
\end{verbatim}
\caption{\texttt{pderiv}, implementing~\eqref{eq:pd} one arm per case
of the equation.}
\label{fig:pderiv-rust}
\end{figure}

\paragraph{Example: No growth under \boldmath$pd$\unboldmath.}
Consider $(x+y)^{*}$ against $\mathtt{xx}$ under $pd$.

$\mathsf{P}_{*}$ applies with star body $r=x+y$:
\begin{equation}\label{eq:der-15}
\begin{aligned}
pd((x+y)^{*},\mathtt{x})
  &= \{\, \mathit{smartC}(r',(x+y)^{*}) \mid r' \in pd(x+y,\mathtt{x}) \,\}
  &&\mathsf{P}_{*} \\
  &= \{\, \mathit{smartC}(r',(x+y)^{*}) \mid r' \in \{\varepsilon\} \,\}
  &&\mathsf{P}_{+},\ \mathsf{P}_{\mathrm{lit}}\ \text{twice} \\
  &= \{(x+y)^{*}\}
  &&\mathsf{SC},\ r' = \varepsilon.
\end{aligned}
\end{equation}
The set is $\{(x+y)^{*}\}$, so deriving by the second $\mathtt{x}$
repeats the computation, and the final partial derivative accepts
$\varepsilon$ since $(x+y)^{*}$ is nullable by $\mathsf{N}_{*}$. So
$\mathtt{xx}\in L((x+y)^{*})$.

Equation~\eqref{eq:growth-comparison} traces the derivative and the
partial derivative on the same expression:
\begin{equation}\label{eq:growth-comparison}
\begin{aligned}
\text{Derivative (unsimplified):} &\quad
  \underbrace{(x{+}y)^{*}}_{4}
  \xrightarrow{\mathtt{x}}
  \underbrace{(\varepsilon{+}\emptyset)(x{+}y)^{*}}_{8}
  \xrightarrow{\mathtt{x}}
  \underbrace{(\emptyset{+}\emptyset)(x{+}y)^{*}{+}(\varepsilon{+}\emptyset)(x{+}y)^{*}}_{17} \\[6pt]
\text{Partial derivative:} &\quad
  \underbrace{\{(x{+}y)^{*}\}}_{4}
  \xrightarrow{\mathtt{x}}
  \underbrace{\{(x{+}y)^{*}\}}_{4}
  \xrightarrow{\mathtt{x}}
  \underbrace{\{(x{+}y)^{*}\}}_{4}
\end{aligned}
\end{equation}

The unsimplified derivative grows at every step, while the partial derivative
stays at one element because $\mathsf{P}_{\emptyset}$ and
$\mathsf{P}_{\varepsilon}$ contribute no residual, so there is nothing
to simplify.

%

\paragraph{Finiteness.}
For a regular expression $r$, the number of distinct partial derivatives
reachable by any input is bounded by $\|r\|+1$
\citep[Theorem~3.4, p.~309]{antimirov1996}. This is a ceiling, not a
guarantee that all $\|r\|+1$ are reached. For $(x{+}y)^{*}$, $\|r\| = 2$
the ceiling is $3$, yet only $(x{+}y)^{*}$ is reachable, since
deriving by either $\mathtt{x}$ or $\mathtt{y}$ returns it unchanged.

Ordinary derivatives need equivalence classes to be finite
\citep[Theorem~4.3]{brzozowski1964}, giving $d_R \leq 2^{d_P}-1$.
Simplification removes units and redundant $\emptyset$, but not all
equivalent forms. 
In contrast the partial-derivative bound is linear without simplification.

%

\paragraph{The matcher.}
The implementation can be summarized by the sequence of state sets
produced while consuming the input. For $w=x_1x_2\cdots x_n$, the
initial state set is $S_0=\{r\}$, and each subsequent set is obtained by
taking $pd$ of every residual in the previous set and unioning the
results:
\begin{equation}
S_0=\{r\},
\qquad
S_i=\bigcup_{r'\in S_{i-1}} pd(r',x_i)
\quad (1\leq i\leq n).
\label{eq:pderiv-state-set}
\end{equation}

The state set $S_i$ collects every residual reachable after consuming
the prefix $x_1\cdots x_i$. Unlike the derivative matcher's single
residual $r_i$, no element of $S_i$ grows with the input. The number of
elements is bounded by $\|r\|+1$ as shown above. After the final symbol
has been consumed, the matcher accepts when some residual in $S_n$ is
nullable:

\[
w\in L(r)
\iff
\exists r_n \in S_n.\ n(r_n)=\mathrm{true}.
\]

So $S_0\xrightarrow{x_1}S_1\xrightarrow{x_2}\cdots\xrightarrow{x_n}S_n$
can be viewed as a path through a lazily constructed NFA. Each state set
represents the set of NFA states reachable after reading the corresponding
prefix, and $\xrightarrow{x}$ denotes the transition obtained by taking
$pd$ with respect to $x$ and unioning. Unlike an explicitly constructed
NFA, only the states reached by the input are constructed. A state set is
accepting exactly when it contains at least one nullable residual, so
acceptance is determined by whether the final state set contains a
nullable residual.

%

\paragraph{In Rust.}
Figure~\ref{fig:pderiv-loop-rust}
implements~\eqref{eq:pderiv-state-set} with a \texttt{HashSet<Regex>},
whose \texttt{Hash} and \texttt{Eq} implementations collapse residuals
reached by different paths. The early return when the set empties
follows from construction: an empty set has no states to derive. The
final \texttt{any(nullable)} checks whether some residual is nullable.
Where the derivative matcher holds one growing \texttt{Regex}, this holds
a set of small residuals that never need simplification.

\begin{figure}[ht]
\small
\begin{verbatim}
pub fn match_pderiv(input: &str, r: &Regex) -> bool {
    let mut states: HashSet<Regex> = HashSet::new();
    states.insert(r.clone());
    for c in input.chars() {
        let mut next: HashSet<Regex> = HashSet::new();
        for state in &states {
            next.extend(pderiv(state, c));
        }
        if next.is_empty() { return false; }
        states = next;
    }
    states.iter().any(nullable)
}
\end{verbatim}
\caption{The partial-derivative matcher.}
\label{fig:pderiv-loop-rust}
\end{figure}

\paragraph{Worked Example: Applying the partial-derivative-based matcher}
\label{sec:pderiv-worked-example}

Applying \texttt{match\_pderiv} to $r_0 = (a + ab)(b + \varepsilon)$ and
$w = \mathtt{ab}$ with the expression written as:
\[
r_0 = \mathit{Seq}(s,\, t),
\qquad
s = a + ab,
\qquad
t = b + \varepsilon.
\]

\paragraph{Derive by $\mathtt{a}$.}
Since $s$ is not nullable, $t$ is untouched and $\mathsf{P}_{\mathrm{seq}}$
applies to $r_0$:
\[
S_1 = \{\, \mathit{smartC}(r',t) \mid r' \in pd(s,\mathtt{a}) \,\}
  \qquad (\mathsf{P}_{\mathrm{seq}}).
\]
The alternation rule gives the two branches of $s$ separately:
\[
\begin{aligned}
pd(a,\mathtt{a}) &= \{\varepsilon\}
  &&(\mathsf{P}_{\mathrm{lit}}), \\[2pt]
pd(ab,\mathtt{a}) &= \{\mathit{smartC}(\varepsilon,b)\} = \{b\}
  &&(\mathsf{P}_{\mathrm{seq}}),
\end{aligned}
\]
So $pd(s,\mathtt{a}) = \{\varepsilon, b\}$. Applying $\mathit{smartC}$
to each element against $t$ prepends that element to $t$, with
$\varepsilon$ absorbed so that $\varepsilon \cdot t$ is never built:
\[
S_1 = \{\, t,\ b\cdot t \,\} = \{\, b+\varepsilon,\ \ b\,(b+\varepsilon) \,\}.
\]

\paragraph{Derive by $\mathtt{b}$.}
Each state in $S_1$ is derived separately and the results unioned. 

For the first state $t = b+\varepsilon$:
\[
pd(b+\varepsilon,\mathtt{b})
  = pd(b,\mathtt{b}) \cup pd(\varepsilon,\mathtt{b})
  = \{\varepsilon\} \cup \{\}
  = \{\varepsilon\}
  \qquad (\mathsf{P}_{+},\ \mathsf{P}_{\mathrm{lit}},\
           \mathsf{P}_{\varepsilon}).
\]

For the second state $b\cdot t = b\,(b+\varepsilon)$:
\[
pd\big(b\,(b+\varepsilon),\mathtt{b}\big)
  = \{\, \mathit{smartC}(\varepsilon,\,b+\varepsilon) \,\}
  = \{b+\varepsilon\}
  \qquad (\mathsf{P}_{\mathrm{seq}}).
\]

Only the left factor $b$ is derived, as it is a non-nullable literal.
The union gives:
\[
S_2 = \{\varepsilon\} \cup \{b+\varepsilon\}
    = \{\, \varepsilon,\ \ b+\varepsilon \,\}.
\]

\paragraph{Acceptance.}
Both states in $S_2$ are nullable, $\varepsilon$ by
$\mathsf{N}_{\varepsilon}$ and $b+\varepsilon$ by $\mathsf{N}_{+}$ and
$\mathsf{N}_{\varepsilon}$, so \texttt{match\_pderiv("ab", $r_0$)}
returns \texttt{true} and $\mathtt{ab} \in L(r_0)$, agreeing with
Section~\ref{sec:deriv-worked-example}.
