\chapter{Matching and Parsing}
\label{sec:matching-vs-parsing}

Chapter~\ref{sec:derivatives} established matching with a Boolean
answer: $w \in L(r)$. A matcher only answers whether
the input is accepted by the regular expression. 
Parsing identifies the evidence for the match and
\emph{parse trees} act as their structured witnesses.

%

\section{Matching: A Boolean Answer}
\label{sec:matching-problem}

Consider $r = (a+ab)(b+\varepsilon)$ and $w = \mathtt{ab}$. 
The matcher can determine $w \in L(r)$ using the algorithms of Chapter~\ref{sec:derivatives}. 
There are, however, two ways in which $r$ can match $w$:
\begin{equation}
\begin{aligned}
\underbrace{a}_{a+ab}\; \underbrace{b}_{b+\varepsilon}
\quad&\text{and}\quad
\underbrace{\mathtt{ab}}_{a+ab}\; \underbrace{\varepsilon}_{b+\varepsilon}
\end{aligned}
\label{eq:match-decompositions}
\end{equation}

Both choices establish the same membership result,
but assign the input differently to the subexpressions of $r$.
The Boolean result alone cannot distinguish these cases,
so the matcher cannot reveal which decomposition was chosen.

Parsing makes this additional structure explicit, by showing
which alternatives were chosen and which parts of the input were
consumed by the corresponding subexpressions.

%

\section{Parsing: Parse Trees as Matching Evidence}
\label{sec:parse-trees-as-evidence}
\paragraph{Parse Tree.} A \emph{parse tree} provides a structured witness for such a derivation.
Sulzmann and Lu view regular expressions as types and \emph{parse trees} as their
values \citep{sulzmannlu2014}. The judgment $\vdash v : r$ states that $v$ is a
valid parse tree for $r$, recording which alternatives were chosen and how each
part of the input was consumed during matching:

\begin{equation}
\label{eq:typing-rules}
\begin{aligned}
\begin{aligned}
\vdash () : \varepsilon
&
\quad(\mathsf{T}_{\varepsilon})
\\[1.0em]
\dfrac{l \in \Sigma}{\vdash l : l}
&
\quad(\mathsf{T}_{\mathrm{lit}})
\\[1.4em]
\dfrac{\vdash v_1 : r_1 \qquad \vdash v_2 : r_2}
      {\vdash (v_1,v_2) : r_1 r_2}
&
\quad(\mathsf{T}_{\mathrm{seq}})
\end{aligned}
\qquad\qquad
\begin{aligned}
\dfrac{\vdash v_1 : r_1}
      {\vdash \mathit{Left}\ v_1 : r_1 + r_2}
&
\quad(\mathsf{T}_{+}^{L})
\\[1.4em]
\dfrac{\vdash v_2 : r_2}
      {\vdash \mathit{Right}\ v_2 : r_1 + r_2}
&
\quad(\mathsf{T}_{+}^{R})
\\[1.4em]
\dfrac{}{\vdash [\,] : r^{*}}
&
\quad(\mathsf{T}_{*}^{0})
\\[1.4em]
\dfrac{\vdash v : r \qquad \vdash vs : r^{*}}
      {\vdash (v:vs) : r^{*}}
&
\quad(\mathsf{T}_{*})
\end{aligned}
\end{aligned}
\end{equation}



%

\paragraph{In Rust.}
Figure~\ref{fig:parsetree-enum}
shows the parse-tree type, with one variant for each constructor.
\begin{figure}[H]
\small
\begin{verbatim}
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum ParseTree {
    Empty,                                 // ()
    Char(char),                            // l
    Pair(Box<ParseTree>, Box<ParseTree>),  // (v1, v2)
    Left(Box<ParseTree>),                  // Left v
    Right(Box<ParseTree>),                 // Right v
    Star(Vec<ParseTree>),                  // [v1, ..., vn]
}
\end{verbatim}
\caption{The parse tree type, representing the structure of a parse.}
\label{fig:parsetree-enum}
\end{figure}

The definitions above translate directly to Rust, except for the star case:
$\mathsf{T}{\varepsilon}$ corresponds to \texttt{Empty} for the empty
parse, $\mathsf{T}_{\mathrm{lit}}$ to \texttt{Char} for a literal,
$\mathsf{T}_{\mathrm{seq}}$ to \texttt{Pair} for a concatenation of
parse trees, and $\mathsf{T}_{+}^{L}$ and $\mathsf{T}_{+}^{R}$ to
\texttt{Left} and \texttt{Right}, recording the chosen branch of an
alternation. Both star rules are represented
by \texttt{Star(vec![])}.

%

\paragraph{Flattening.}
The typing judgment describes the structure of a match, but a parse tree
must also be related to the word that it matches. For this purpose, they
define a \emph{flattening} function $\lvert v\rvert$ that maps a parse
tree to the word represented by its structure:

\begin{equation}
\label{eq:flatten}
\begin{aligned}
\begin{aligned}
\lvert ()\rvert
  &= \varepsilon,
\\
\lvert l\rvert
  &= l,
\\
\lvert [\,]\rvert
  &= \varepsilon
\end{aligned}
\qquad\qquad
\begin{aligned}
\lvert (v_1,v_2)\rvert
  &= \lvert v_1\rvert\lvert v_2\rvert,
\\
\lvert \mathit{Left}\ v\rvert
  &= \lvert v\rvert,
\\
\lvert \mathit{Right}\ v\rvert
  &= \lvert v\rvert,
\\
\lvert v:vs\rvert
  &= \lvert v\rvert\lvert vs\rvert.
\end{aligned}
\end{aligned}
\end{equation}

The flattening function directly connects parse trees to $L(r)$,
and thus validates that a parse tree witnesses membership in $L(r)$,
serving as an correctness check:

\begin{equation}\label{eq:mvp-5}
L(r)
=
\{\,\lvert v\rvert \mid \vdash v : r\,\}.
\end{equation}

%

\paragraph{In Rust.}
Figure~\ref{fig:flatten-rust} shows that the function takes \texttt{\&ParseTree}
rather than consuming the tree, so it can be inspected, printed, and compared after flattening. 
The star case similarly borrows its elements through \texttt{vs.iter()}.
\begin{figure}[H]
\small
\begin{verbatim}
pub fn flatten(v: &ParseTree) -> String {
    match v {
        ParseTree::Empty       => String::new(),
        ParseTree::Char(c)     => c.to_string(),
        ParseTree::Pair(v1, v2) =>
            format!("{}{}", flatten(v1), flatten(v2)),
        ParseTree::Left(v)     => flatten(v),
        ParseTree::Right(v)    => flatten(v),
        ParseTree::Star(vs)    => vs.iter().map(flatten).collect(),
    }
}
\end{verbatim}
\caption{The \texttt{flatten} function extracts the matched word from a parse tree.}
\label{fig:flatten-rust}
\end{figure}

\paragraph{Unambiguous example.}
\label{par:unambigious-example}
Consider $r = ab$ and $w = \mathtt{ab}$. 
Since each subexpression is a literal, the rule $\mathsf{T}_{\mathrm{lit}}$ 
gives each literal a unique witness.
Then $\mathsf{T}_{\mathrm{seq}}$ requires 
the parse tree for $a$ to be followed by the parse tree for $b$,
combining them into a parse tree for $ab$:
\begin{equation}\label{eq:mvp-6}
\dfrac{a \in \Sigma}{\vdash a : a}\;(\mathsf{T}_{\mathrm{lit}})
\qquad\qquad
\dfrac{b \in \Sigma}{\vdash b : b}\;(\mathsf{T}_{\mathrm{lit}})
\qquad\qquad
\dfrac{
  \vdash a : a \qquad \vdash b : b
}{
  \vdash (a,b) : ab
}\;(\mathsf{T}_{\mathrm{seq}})
\end{equation}

The parse tree $v=(a,b)$ flattens to $\lvert (a,b)\rvert = \mathtt{ab}$.

%
\paragraph{Ambiguous Example.}
\label{par:ambigious-example}
Recall $r = (a+ab)(b+\varepsilon)$ and $w = \mathtt{ab}$ from the example in
Section~\ref{sec:matching-problem}, the two decompositions
in~\eqref{eq:match-decompositions} correspond to two distinct parse
trees.

The first decomposition uses the right alternatives of both subexpressiosn $a+ab$ and $b+\varepsilon$. 
First deriving the parse tree for $a+ab$, gives:
\begin{equation}\label{eq:mvp-7a}
\begin{gathered}
\dfrac{a \in \Sigma}{\vdash a : a}\;(\mathsf{T}_{\mathrm{lit}})
\qquad\qquad
\dfrac{b \in \Sigma}{\vdash b : b}\;(\mathsf{T}_{\mathrm{lit}})
\\[1.6em]
\dfrac{\vdash a : a \quad \vdash b : b}{\vdash (a,b) : ab}\;(\mathsf{T}_{\mathrm{seq}})
\qquad\qquad
\dfrac{\vdash (a,b) : ab}{\vdash \mathit{Right}(a,b) : a+ab}\;(\mathsf{T}_{+}^{R})
\end{gathered}
\end{equation}

Then the parse tree for $b+\varepsilon$:
\begin{equation}\label{eq:mvp-7b}
\dfrac{b \in \Sigma}{\vdash b : b}\;(\mathsf{T}_{\mathrm{lit}})
\qquad\qquad
\vdash () : \varepsilon\;(\mathsf{T}_{\varepsilon})
\qquad\qquad
\dfrac{\vdash () : \varepsilon}{\vdash \mathit{Right}() : b+\varepsilon}\;(\mathsf{T}_{+}^{R})
\end{equation}


By $\mathsf{T}_{\mathrm{seq}}$, the parse trees for $a+ab$ and $b+\varepsilon$ combine into one derivation for $r$:
\begin{equation}
\label{eq:mvp-7}
\dfrac{
  \dfrac{\vdash a : a \quad \vdash b : b}
        {\vdash (a,b) : ab}
}{
  \vdash \mathit{Right}(a,b) : a + ab
}
\quad
\dfrac{
  \vdash () : \varepsilon
}{
  \vdash \mathit{Right}() : b + \varepsilon
}
\quad\Rightarrow\quad
v_1 =
\bigl(
  \mathit{Right}(a,b),
  \mathit{Right}()
\bigr),
\quad
\lvert v_1\rvert = \mathtt{ab}.
\end{equation}

The second decomposition matches $\mathtt{a}$ and $\mathtt{b}$ using
the first alternatives of $a+ab$ and $b+\varepsilon$:
\begin{equation}\label{eq:mvp-9a}
\dfrac{a \in \Sigma}{\vdash a : a}\;(\mathsf{T}_{\mathrm{lit}})
\qquad\qquad
\dfrac{\vdash a : a}{\vdash \mathit{Left}\ a : a+ab}\;(\mathsf{T}_{+}^{L})
\end{equation}

Then the parse tree for $b+\varepsilon$:
\begin{equation}\label{eq:mvp-9b}
\dfrac{b \in \Sigma}{\vdash b : b}\;(\mathsf{T}_{\mathrm{lit}})
\qquad\qquad
\dfrac{\vdash b : b}{\vdash \mathit{Left}\ b : b+\varepsilon}\;(\mathsf{T}_{+}^{L})
\end{equation}

By $\mathsf{T}_{\mathrm{seq}}$, the parse trees for $a+ab$ and $b+\varepsilon$ 
combine into one derivation for $r$:
\begin{equation}
\label{eq:mvp-9}
\dfrac{\vdash a : a}
      {\vdash \mathit{Left}\ a : a + ab}
\quad
\dfrac{\vdash b : b}
      {\vdash \mathit{Left}\ b : b + \varepsilon}
\quad\Rightarrow\quad
v_2 =
\bigl(
  \mathit{Left}\ a,
  \mathit{Left}\ b
\bigr),
\quad
\lvert v_2\rvert = \mathtt{ab}.
\end{equation}


Both trees are valid parse trees for the same expression and word, yet
they differ in their structure. The typing judgment alone does not
determine which should be selected. A \emph{disambiguation policy}
specifies this choice.
